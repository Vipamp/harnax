## 正文

### 一、先说清楚:这些题不是评论区来的

第一季还没更完,评论区还没有问题可以收集。所以本篇的题目是**我们自己出的**。从第 5 期起,每一篇我们都给读者留了一段边界——第 5 期专门写"挡不住什么",第 8 期把"我们没做的"单列一档,第 10、11 期各有一节讲没交付的那一半。把这些段落反过来问,就是读者最可能问的东西。

配套一条规矩:**回答只用我们已经对源码核对过的口径**。答不了的就写"没做",不为了凑一个漂亮答案去猜。十三道里,六道的答案是同一句:**没做,这一件得你来**。

### 二、第一组:数据到底在哪儿

**1. 对话真的一个字节都不出你的内网吗?**
不能这么说。运行期必须出网的有三类:模型服务、外部 MCP 系统、IM 平台。前两类的地址都可以填内网——`ollama` 是三个受支持的 provider 类型之一,默认就指向 `localhost:11434`,那条分支根本不读 apiKey;OpenAI 兼容协议的 baseUrl 接受 `http://`、纯 IP 加端口、带路径,校验只查格式。第三类不启用渠道就没有流量,而源码里硬编码的公网域名只有飞书、钉钉、企业微信那三个。
另一件是真的:**运行期零上报**——没有 Sentry / OTLP / 日志回传,也没有版本检查、心跳回连、许可证校验;指标只有一个被动等着被抓取的端点,我们不主动外呼。

**2. 那对话是明文存的?**
分两层。密钥类字段是 AES-256-GCM 加密入库的;对话正文不是,它得参与读取与渲染。模型 key、渠道配置、手机号这些也都是明文列——这是"能查、能改、能渲染"换来的代价,我们不把它说成加密存储。检索这一路连 embedding 模型都不需要,是关键词实现,所以不必为它再接一个向量库。

**3. 传输加密呢?**
这里要精确。**HTTPS 在仓库里是配好的**:nginx 有 443 的 ssl server、TLS 1.2 到 1.3,80 那个入口除了健康检查全部 301 到 https,compose 也发布了 443 并挂 `./ssl` 只读。但**证书不进仓库**——`ssl/` 目录被 gitignore,仓里也没有自签脚本。所以不放证书的表现是**前端容器起不来**,不是"退化成 HTTP"。另外安全头只有三个,没有 HSTS、没有 CSP。

**4. 这算开源吗?**
不算,也不说。仓库目前没有 LICENSE 文件。准确说法是**可完全私有部署 / 自托管**。这两件事不一样,我们不混着讲。

### 三、第二组:它会不会算钱,会不会看路

**5. 用超了会自动拦吗?**
不会。用量表里那个 `fee` 列每次写的都是零,列类型是 `decimal(10,0)`——零位小数,连"分"都存不下;前端"总费用"那张卡渲染成 `¥0.00`,把维度从 token 切到费用,三个饼图和四条折线全部归零。全仓没有单价表、没有计费规则、没有预算,也没有配额、阈值、告警。库里确实有个限流器,但它按 API Key 限的是**每分钟请求数**(默认 60),跟 token 没关系。看板是纯展示。

**6. 它每次调工具,页面上能看到吗?**
五张表都在写,能读回来的只有两处:管理台的用量看板(7 张数字卡 + 3 饼 + 4 线),和网关镜像另外自带的一张控制页。工具调用日志的 mapper 里**只有一条 insert,连 select 都没有**;令牌授权表同样;过程日志表有 select 但生产代码没有调用方。我们自己的文档写着"需要直连数据库查"。所以准确说法是:**写了,要看就得自己连库**。

**7. 定时任务失败了,谁会告诉我?**
没有人。不重试、不补发、没有告警出口——失败的痕迹只在三个地方:账本上一行红色状态、进程日志、以及可以被抓取的指标。想把"没人告诉你"变成"有人告诉你",得自己接 Prometheus 抓 Actuator,而 admin 和执行服务连 `management:` 这个配置段都没有,采集范围要你自己补。

**8. 副本调到三台,同一件事会不会做三遍?**
"到点只有一台敲"这件事有两层锁保证:调度框架的数据库行锁管谁拿到触发器,我们往一张专门放触发锁的表撞唯一键管这一发归谁。**但"只做一遍"要的是幂等,这一件系统给不了你**——锁不续租、也不校验持有者,重复下发的可能性在。幂等得做在你自己的业务里:发出去的邮件、写进去的订单,系统不会替你判重。

### 四、第三组:上线那天你会撞上什么

**9. 一条命令就能部署吗?**
不能说"一条命令"。compose 里只声明镜像名,镜像得先用构建脚本产出,而那台机器上要有 mvn、node、docker。准确说法是**一个脚本**。

**10. 能上 Kubernetes 吗?**
不能。只有 Docker Compose,单机可运维,没有 Helm chart、没有 manifest。我们不说"支持 K8s 编排"。

**11. 备份和日志清理有吗?**
都没有。没有备份脚本、没有恢复工具、没有导出通道,运维文档里只有一句"生产执行迁移前必须备份"。清理这一头:全系统只有调度域两张表有保留期(执行日志 90 天、触发锁 7 天),而且这两个数字是代码里的裸常量、改不了;观测域那四张表没有任何清理任务,会一直长。留痕那一列还是 `text` 类型——**64KB 是硬顶,而写入端没有截断保护**,超长的一行会被数据库拒绝、被 catch 吞掉,丢得不报错。容器日志交给 Docker 默认驱动,compose 里没有一行 `logging:` 配置;挂在 `/app/logs` 上那几个卷是堆转储目录,不是日志。这三件是你的 `mysqldump` 和 cron 的事。

### 五、第四组:安全与判断

**12. 它会不会被一句话骗去删库?**
我们用的是机制描述,不用"绝对安全""百分百拦截"这种话。三道锁:工具跑在一个一次性的隔离容器里,弄脏了就扔;危险动作停下来等一次人工确认;技能包先扫描后上岗,九条规则命中就"入库即停用"。旁边还有两个开关是往回收的:stdio 类型的 MCP 默认关(两个服务各一道,得同时打开才会跑),沙箱网络可以设成 `none`。

但第 5 期写过的那段"挡不住什么",在这儿重说一遍:挡不住你给它绑了不该绑的工具——它有多大权限是你在配置页上定的;挡不住模型想歪但参数看起来无害的活——扫描是模式匹配,不是意图理解;也挡不住你把一个被停用的技能人工复审后重新启用,那是我们故意留的口子。

**13. 登录这一头呢?**
这是最该在上线前补的一块。**没有失败锁定、没有退避**;而且除了管理台的网页登录,移动端与 CLI 的登录连验证码都没有。出厂默认口令是一串公开的字符串(而且会打进启动日志),Redis 的端口默认发布到宿主机、带着出厂默认口令,全仓只有一处配置检查会真的拒绝启动,而它只在鉴权开启且用 Redis 模式时生效。公网暴露之前,限流和失败计数请在入口层自己做。
