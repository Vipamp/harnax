## 摘要

一句话:把 AI 收进内网,真正的门槛不是"数据放在谁家",而是这台机器上从此多了九个服务、一份备份计划和一条出站规则。这一篇先讲两件我们确认过的事——运行期没有任何上报路径、模型可以完全不出门;再把剩下七件事逐条列给你:哪些默认值必须改、哪些组件必须自己加、哪些我们没做、哪些是我们明确决定不做的。

## 正文

### 一、这一篇不讲什么

先把开头那个测试做一遍。打开你正在用的那个 AI 助手,把下面这段换成你们公司真实的代码、真实的客户名单、真实的季度数据,然后发出去:

> 帮我看看这段逻辑有没有问题。

发完之后,有三个问题大概答不上来:这段话现在存在谁的磁盘上;它会不会出现在某个人的后台日志里;它会不会进某个训练管道,变成明年那个模型的一部分。

**但这一篇不讲另一家的后台做得怎样。** 我们没有依据去讲,讲了就是靠比较抬高自己,这种话在我们这里不写。这一篇只讲一件事:换到你自己的机器上之后,你要面对什么。

而这条路上真正的门槛,不是"选一家更可信的服务商",是很朴素的一句话:**这套东西本来就得有人当操作系统。** 磁盘在哪、进程谁拉起、时钟准不准、权限归谁管、备份什么时候跑——这五样没有一样会因为系统装在你的机器上就自动出现。它们原本由云厂商替你做掉,现在回到你手上。

所以这一篇的顺序是:先给你一张地形图,再讲两个我们敢写死的结论,最后把运维账单摊开。

### 二、先看清这套东西长什么样

这一节没有卖点,只是一张地形图。但后面每一件事都指回这张图。

| 这个容器是干什么的 | 里面装的东西 |
|---|---|
| 数据库 | MySQL,一台实例分五个库,不同服务各用各的 |
| 缓存与协调 | Redis,只在多实例集群形态下承担共享状态 |
| 对象存储 | 存沙箱工作区的快照、AI 产出的文件、团队之间传递的产物 |
| 管理台后端 | 配置模型、技能、工具、渠道,看用量 |
| 会话网关 | 决定每个会话归哪台实例、把请求转过去 |
| 调度服务 | 定时触发,可以多副本组集群 |
| 执行服务 | 真正跑 AI 的那一个,沙箱容器由它创建 |
| 渠道服务 | 接飞书、钉钉、企业微信 |
| 前端 | 一个 nginx,把网页和几组 API 路径代理到对应服务 |

`docker-compose` 起上面这九个服务,这里**没有第十方**——没有任何一个组件是"我们的云端",你和管理台之间隔着的,只有你自己的网络。

补一句免得你起容器时纳闷:compose 里还有第十个块,是一个自带的天气示例 MCP 服务(0.5 核 / 256M),用来说明 MCP 这条链路怎么接。它不属于系统本体,也不在 `build.sh` 构建的六个镜像清单里——要它,得让 compose 现场把那个 Python 小服务构建出来。

这台机器要多大,我们不猜数字。compose 里给每个服务都写死了资源上限:数据库 1 核 1G、执行服务 2 核 2G、管理台和网关各 2 核 1G,这九个加总是 **11.5 核 / 8 GiB 的天花板**;把那个自带的示例服务也算进去是 12 核 / 8.25 GiB。保底(reservations)只有六个服务写了,加起来 2.6 GiB。真正的变量是沙箱:每个会话会在你机器上另起一个临时容器,它们不在这张表里,也不受这些 limits 约束。所以我们不写"最低配置 4 核 8G"这种句子——仓库里没有这个数,我们也不在这儿编一个。

安装是一个脚本:先构建再启动,会编译后端、构建前端、打出镜像、把容器拉起来。前提是你那台机器上已经有 JDK/Maven、Node、Docker——它不替你装环境,但它把后面每一步都做完了。

### 三、我们搜遍了自己的代码,找不出这三样东西

这是第一件我们敢写死的事。写之前我去代码里确认了一遍,不是凭印象。

**第一样:上报。** Sentry、Bugsnag、OpenTelemetry/OTLP、Zipkin、Jaeger、Loki/Filebeat 那类日志采集器、任何 analytics 埋点——全仓后端源码里,零命中。连 logback/log4j 的配置文件都没有,更不存在会把日志往外发的网络 appender。

**第二样:回连。** 版本检查、升级探针、启动时"ping 一下厂商"、许可证校验、试用期到期判断——零命中。代码里确实有叫 heartbeat 的东西,但那些全是内部机制:网关心跳写自己的 Redis,调度集群心跳写自己的 MySQL。

**第三样:主动推送指标。** 系统有指标,但形态是被动的——服务开了一个端点等人来抓。没有 PushGateway,没有把任何数据推到外部。想看你的调用量,得是你自己搭 Prometheus 来拉。

一个自托管产品最容易漏的从来不是主流程,而是那些"顺手回连一下"的边角:一个检查更新的请求、一条崩溃上报、一段匿名统计。我们的部署里之所以没有这些,不是因为比谁更谨慎,而是因为**这套系统里没有任何一条路通到我们那儿——我们不维护任何接收端**。

少说一句:管理台桌面版有三张装饰背景图来自支付宝的 CDN,网关自带的监控页引了 Google 的字体。都是浏览器侧请求,只为好看,断网不影响功能。纯内网部署时你会在控制台看到几条失败请求,这两处我们记在待办里。

### 四、连模型都可以不出门

这是第二件我们敢写死的事,也是往里一层:如果你连"请求发到模型厂商"这一步都不接受呢?

Harnax 支持三类模型协议:通义(DashScope)、OpenAI 兼容协议、Ollama。后两个是这件事的关键:

- **Ollama 是一等公民。** 管理台里有"Ollama(本地)"这个服务商类型,选中就能用,地址默认 `http://localhost:11434`,**这条路径根本不读 API Key**——本地推理不需要凭据这回事,这是代码里的分支,不是一句口号。
- **OpenAI 兼容协议接受任意地址。** 校验只查格式,不强制 HTTPS、没有域名白名单,纯 IP + 端口 + 路径都合法(有单元测试覆盖这三种写法)。你们内网那套 vLLM、OneAPI、LiteLLM 网关,填进去就能用。
- **不需要额外部署向量模型。** 记忆和会话检索走关键词,不依赖 embedding。少一个要维护的组件,在离线环境里就是少一个坑。

两句实话,免得这一段显得太顺:第一,Ollama 这条路径上"思考模式"和"联网"两个开关是无效参数,不报错也不生效——这是代码缺陷,已记待办,所以我们不把它当功能讲。第二,管理台上那个"测试连接"按钮是空实现,点谁都显示成功,别指望它。

再说出站边界。运行期必须出网的只有三类:你选的模型、你接的外部系统、你连的 IM 平台。前两类的地址完全由你配置,指向内网就止步于内网。第三类不是配置项:飞书、钉钉、企业微信的 API 域名写死在源码里,没有开关可覆盖,因为那是平台方的公网服务——不用渠道,就没有这类流量。

除此以外的出站点都是配置:技能仓库可以指自建 GitLab,NPM 可以指私服 registry,上传的技能包走纯离线;邮件工具的 SMTP 主机由你填,内网邮件中继直接可用,而且每次发信要你确认;沙箱容器的网络模式可以设成 `none`,那条 AI 就在一个断网的房间里干活。

需要网络的是构建阶段:Maven、npm、基础镜像要在有网的地方拉。所以我们推荐的离线路径很朴素——在有网机器上构建出镜像,`save` 成文件,搬进内网 `load`。

### 五、数据到底落在哪一行

"数据是你的"这句话太空,得落到库、表、列,也得落到"谁把它建出来的"。

一次对话的正文,落在**你自己数据库**里 `agentscope` 库的 `agent_state` 表,`json_value` 那一列,类型 LONGTEXT,一整段 JSON。IM 里发的消息和网页上发的消息,进同一张表、同一份记忆。执行过程日志、工具调用日志、Token 用量在 `harnax_admin` 库;定时任务的账本和日志在 `harnax_scheduler` 库;文件与沙箱工作区快照在对象存储的四个桶里。

这里有一个细节值得每个运维看一眼:**库与表的创建者不是同一个人。** 五个库由 MySQL 容器首次启动时的初始化脚本建;业务表由各服务的迁移脚本建;而装着对话正文的那张 `agent_state` 表,是运行时代码在第一次用到它时自己 `CREATE TABLE IF NOT EXISTS` 建出来的。听起来像偷懒,但它意味着一件实用的事——你不需要准备任何"导入数据结构"的步骤,也不需要担心漏跑一个 SQL 文件;代价是,这张表的结构由代码拥有,你要备份的是**整个数据库**,不是我们提供的某份 schema。

**库、表、文件、桶,全在你维护的磁盘上;容量、备份、保留期,是你那条时间线上的事。** 这一句是本篇的主线,第六节把这笔账逐条摊开。

同一张库里,只有凭据类字段是密文:接入系统的密钥、外部服务的凭据、授权换来的令牌,以 AES-256-GCM 加密落库,每次加密带随机 IV。而对话正文、执行过程日志里的文本、定时任务的回执,是明文列。

删除是能落到语句上的。删一个会话时:运行时状态、计划便签、那个会话的沙箱容器、它产出的文件对象(包括对象存储里的实体)——**全部真删**;会话行本身是标记停用。而且有一条硬规则:如果运行时那部分删不掉,整个删除请求会被拒绝,不会给你一个"已删除"的假提示。

### 六、运维账单:这套系统里有一个进程,能创建你机器上的容器

前面两节讲的都是"数据不出门"。这一节讲它的另一面:**门在你手上,门内的权限也在你手上。**

先说最硬的一条。执行服务要在你机器上为每个会话创建沙箱容器,因此它挂了宿主机的 docker socket。这意味着**这个容器对你的 Docker 有完全控制权**——它能创建容器,也就意味着它能以 Docker 的权限做容器能做的事。这不是我们埋的雷,这是"在自己机器上跑代码执行"这件事的物理代价:总得有一个进程负责创建房间。

正因为这个原因,stdio 型 MCP(需要由执行服务直接拉起子进程的那种)**默认禁用,登记即拒**,运行期还有多层拦截。你确实可以在配置里把它打开,但请先想清楚那间房子有没有墙。

同样要说在前头:这套系统的隔离粒度是**租户,不是用户**。配置类对象按租户隔离,会话列表按"公开或创建者"隔离,跨租户的运行时访问由网关那一层挡住。一个部署给多人共用是支持的,但请把权限设计当成你自己的功课,别指望这套系统替你划清组织边界。

下面是这笔账,四档,七件事。上线前把它们写进你的配置和文档,比写进我们的宣传页有用。

**第一档:必须改的默认值**

1. **管理员口令。** 出厂有一个默认管理员账号,它的口令是一串公开在源码里的字符串,服务启动时还会把它打进日志,提醒你尽快修改。
2. **四把密钥。** JWT 签名密钥、字段加密密钥、服务间内部接口的 secret、对象存储的账号密码,出厂都有一串仓库里能搜到的默认值。**只有一处有硬拒**:网关在 Redis 集群模式下发现密钥还是占位串,会直接拒绝启动。其余情况,它只打一行 warning 就继续跑。密钥轮转也是你的事——系统没有轮转流程,换了密钥请确认所有实例同步生效。

**第二档:必须自己加的组件**

3. **入口:证书与暴露面清单。** HTTPS 是配好的——443 监听、TLS 1.2/1.3、80 上除了健康检查全部 301 到 https,compose 也把 443 发布出来并把宿主的一个目录挂进容器当证书目录。**但仓库里不带证书**:那个目录被 `.gitignore` 忽略,镜像里只建了个空目录,也没有自签脚本。所以这是你上线要做的第一件事——**不放证书,前端容器起不起来,而不是"退回去用 HTTP 访问"**。要么放自己的证书,要么在你前面那层负载均衡上收 TLS,然后把这两处的 80/443 改掉。另外安全响应头目前只有三个(X-Frame-Options、X-Content-Type-Options、以及已经废弃的 X-XSS-Protection),**没有 HSTS、没有 CSP**,这两样也得你在入口层自己加。顺手把暴露面列一遍:这些服务各自发布了哪些端口,哪些只该留在内网——比如 Redis 的端口默认就发布到宿主机上,会话归属、锁、路由状态都能从那儿写进去,它自己的配置注释也写了"所以不能不带口令跑";而调度服务在 compose 里刻意只 `expose` 不发布(它内部鉴权是关的),这个思路可以照抄。
4. **备份。** 我们没有备份脚本、没有恢复工具、没有导出通道,运维文档里对备份只有一句口头要求:"生产执行迁移前必须备份"。磁盘水位也一样:对话正文以 JSON 明文长在一张表里,调度域之外没有任何容量告警。这两件都是你的 `mysqldump` 和 cron 的事。
5. **日志保留期。** 调度域有两张表带保留期,执行日志 90 天、放触发锁的那张表 7 天——这两个数字目前是写死在代码里的常量,不可配置,也只覆盖这两张表。除此之外:过程日志、工具调用日志、Token 统计、网关调用日志**没有任何清理任务**,它们会一直长;对象存储没有生命周期规则,快照不会自己过期;日志文件本身由 Docker 的默认驱动接管。要清理、要采集、要轮转,请挂你自己的那一套。

**第三档:我们没做的**

6. **登录保护是空的。** 没有失败锁定、没有退避;而且除管理台网页登录之外,移动端与 CLI 的登录连验证码都没有。公网暴露前,请在入口层自己做限流和失败计数。
7. **两件事说清楚。** 一、**没有 Kubernetes**:只有 Docker Compose,单机可运维,没有 Helm chart、没有 manifest,我们不会说"支持 K8s 编排"。二、**我们不说"开源"**:这个仓库目前没有 LICENSE 文件,准确说法是可完全私有部署 / 自托管,这两件事不一样,我们不混着讲。

**第四档:明确决定不做的事**

- **不给对话正文做加密存储。** 加密只做凭据类字段,范围第五节列过。这不是漏做,是取舍:正文要参与渲染、要能在页面上回看、要能被检索,把它加密等于把读取路径全拆掉。这句取舍的真实含义请一起读走:**数据库本身,就是你的敏感资产边界**——谁能连上你那台 MySQL,谁就能看到全部对话。把"全库加密"当卖点说出口的产品,通常是在赌你不会去查哪张表。
- **不给审计表开删改。** MCP 调用与授权相关的表,在 SQL 层刻意不给删除和更新语句,只有写入。一张应用可以随手改写的表,不能算审计表。这条是决定,不是没做完。

写全这些不是为了显得坦诚。一个准备把 AI 收进内网的团队,真正要判断的是**这件事在自己身上要额外付出多少**。这套系统能替你换掉的,是"数据默认在别人那儿"和"运行期没有上报路径"这两条;其余条款,它交回你手上。边界讲清楚比讲全,对准备真动手的人更有用。

### 七、最后一个决定:一个实例,还是几个

网关有一个开关:`CACHE_TYPE`,出厂默认 `local`——单机形态,状态放进程内存,不依赖 Redis 也能跑;compose 里把它设成 `redis`、同时激活名为 `cluster` 的 profile 之后,会话归属、幂等、限流这些共享状态才进 Redis,多个实例才可以横向铺。顺带澄清一句,免得两个词长得太像:**这个 profile 叫 `cluster`,连的仍然是一台独立的 Redis,和 Redis Cluster 不是一回事。**

但集群形态有一个必须知道的前提:**有两处状态只活在某一台进程的内存里。** 一处是外部系统授权流程中的 `state` 和 PKCE 校验码,发出去和收回来必须是同一个进程;另一处是登录验证码和微信扫码登录的中间态。所以会话不能被随便分到另一台机器上——这不是负载均衡写得好不好,而是**会话保持在这个系统里不是一条运维技巧,是产品语义**。多实例部署还得注意两条 Redis 前提:它不支持 Redis Cluster(配上会故意让启动失败),并且要求实例使用 `noeviction` 驱逐策略——共享状态被内存淘汰掉,等于会话归属被抹掉。另外,Redis 不可用时实例注册表的降级是**停止路由**,不是乱投。

这件事值得单独一篇:一个正在干活的会话不是无状态的,它写过的文件、它停在半路等你确认的那一步,全都在某一台进程的内存和磁盘上。第 9 篇讲这套系统怎么给每个会话定下归属、机器挂了活怎么办,以及一条我们坚持的规矩:宁可报错,绝不编造一个空结果给你。
