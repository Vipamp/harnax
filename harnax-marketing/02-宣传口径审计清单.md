## 五、成稿阶段补录的核实项(逐条查过源码)

**可以放心说(第 3 篇已用)**

- **调度故意同步执行**:线程存活是调度器判断"这一班还在干"的唯一依据;扔给后台线程等于谎报完成,故障接管、关停等待、禁止重叠三样会同时失效(AbstractAgentTaskJob.kt:23-28)
- **不是自己排的班不上手**:收到本节点从未登记的任务触发直接拒绝并交还;禁用调度的实例连库都不读,以免删掉别人拥有的 job(AbstractAgentTaskJob.kt:44-58)
- **触发时回库重读当前指令/状态**,不吃任务仓库里的滞后副本;手动"试跑"不受 taskStatus 限制(点击即当下意图)
- **跨实例执行锁 + 禁止重叠检查**:同一任务同一时刻只有一个实例在跑(AbstractAgentTaskJob.kt:100-108)
- **定时任务会话固定"免确认"模式,且会话内不可改**:`InternalApiController.kt:455`;`DefaultAgentRunner.kt:952-954`、`:1025-1027`。口径:"白班靠人点头,夜班靠事前划界"——约束在排班时给工具与指令,而不是夜里临时放行
- **账本纪律**:只有产生结果的执行线程可写终态;超过超时 1.5 倍的残行由回收路径判超时(承接节点宕机),误判的真实结果可覆回

**必须收窄**

- 每次定时触发是一个独立临时会话(`task-{taskId}-{agentId}-{uuid}`),跑完即清 → **不要说"夜班之间互相记得"**;要连贯得把上下文写进指令
- 主管"技能仍会加载",但它没有文件工具去读 → 第 4 篇只说"它可以有领域知识,但没有手",不展开技能投影细节

**纠正一条早先的理解(第 5 篇成稿时核实)**

- **DONT_ASK 不是"无人值守放行",而是"自动拒绝危险工具"。**五种模式对外一律采用管理台官方文案(`webui/src/locales/zh-CN/pages.ts:871-875`):默认(危险工具需确认)/自动执行(无需确认)/接受编辑(自动批准文件操作)/探索模式(只读)/禁止执行(自动拒绝危险工具)。早期资料里"DONT_ASK=无人值守"的说法作废。
- 危险命令与危险路径的**常量表在第三方 `ToolDangerousPathConstants` 内**,文章里只能以"这一类"举例(rm -rf、sudo rm、chmod 777、kill -9;.env、.bashrc、.ssh),**不可写成完整清单**。
- 扫描命中的处理是"转 ASK 并附 `safety:` 理由",不是直接拒绝;"免确认模式下也不跳过这一档"仅由本仓 KDoc 对引擎契约的描述支撑(DangerousInputCheckingTool.kt:19-21),引擎实现在 jar 内不可复核——第 5 篇已按"不宣称绝对拦死"的口径写,并保持这个降级。
- 产物取件上限真实数值:只扫输出目录、扩展名白名单、单文件 50 MB、一次最多 5 个;工作区读写是内部端点经网关代理,**不要写成"公网可直连沙箱文件"**。

**第 6 篇成稿时核实(技能生命周期域)**

可以放心说:

- **技能来源三型**:GIT / NPM / ZIP / BUILTIN,每一型都有硬约束。Git 走协议白名单,`file://`、`ext::` 这类能碰到本地或外部程序的地址被显式排除;NPM 安装带 `--ignore-scripts`,不给包里的 `preinstall` 钩子执行机会;ZIP 有解包上限(条目数 5000、单文件 20 MiB、总量 200 MiB、深度 512),越界直接抛 `SecurityException` 而不是截断。BUILTIN 只读,运行期不可改。(SkillSourcePolicy / ZipSkillLoader / SkillInstaller)
- **内容安检在入库之前**:9 条规则命中即把命中项写进同步返回的扫描报告,技能以停用态入库,人工确认后才可用;扫描不会覆盖手工创建的技能。有绑定的技能被判定不安全时**可强制停用**,这是"绑着不能停"这条规则的唯一例外。(SkillContentScanner / SkillServiceImpl)
- **双锁互锁**:`active=0` 的技能不能绑给 Agent;仍有绑定的技能不能停用/删除(安全判定除外)。想删先解绑,顺序由后端拒绝,不靠前端提示。
- **每轮收敛而非追加**:投影清单落在 `.harnax-skills.json`,按 sha256 比对,**只删除自己写过的目录**——无差异零写入;落在预期位置之外的产物归入 rejected 并保留;投影失败只 WARN 不阻断对话。(SandboxSkillProjector)
- **团队级技能给主管**,Agent 级技能给成员;主管没有文件工具读不到投影,系统对此专门打 WARN——这是"主管只有知识没有手"的实现层证据。
- **一次装配的技能数量上限 1000**(`MAX_SKILLS_PER_REQUEST`),超出即拒绝,不是静默截断。

必须收窄 / 不能说:

- **AI 自产技能未实现**:工作区技能写入开关默认关闭(`disableDefaultWorkspaceSkills`),技能仓库对 agent 只读,`enableSkillManageTool` 在代码里从未被调用。可以写成"这个能力我们做了但主动关掉了,并有注释说明为什么关",**不可写成"AI 能自己写技能但存在风险"或暗示已开放**。
- **无版本历史、无回滚**:技能表只有一个当前版本指针,改了就是改了,回不去。文章里当作"我们没做的事"明说,不要包装成"版本管理在规划中"以外的承诺。
- **无审核工作流**:`status` 只有 0/1 两值,"待审"在数据模型里就落在停用格上,不存在审批队列、多级审核、责任人流转这些字段。
- 技能消失/取不到时的报告状态是 `stale`,**只做标记不删除**,不要说"自动清理失效技能"。
- 技能包**不能从管理台下载导出**,只有入库路径没有出库路径;别写成"技能资产可迁移"。
- 扫描规则的具体正则与绕过手法属于安全边界,文章只说"这一类"(递归删根、管道执行远程脚本、反弹 shell、凭据外传等),不给出可复现的绕过样例。

**⚠️ 全系列重大订正(第 11 篇审计时发现):工作区 ≠ 仓库,审计必须读 HEAD**

本仓有 4 个未提交的本地修改(`git diff --stat`:`.dockerignore` +1、`harnax-deploy/docker-compose.yml` 55、`harnax-deploy/nginx.conf` 58、`harnax-webui/config/config.ts` +5)。用户已明确"暂时不管,也不要提交",所以**不得改动工作区**;但这意味着读这两个部署文件时必须用 `git show HEAD:<路径>`(或 `git diff` 对照),不能直接读文件。此前对 nginx/compose 的读取走的是工作区版本,导致下面三条口径错误:

- **❌ 旧口径"没有 HTTPS、出厂只有 80"是错的。** HEAD 的 nginx.conf 有完整 HTTPS server:`listen 443 ssl`、`ssl_certificate{,_key} /etc/nginx/ssl/server.{crt,key}`、`ssl_protocols TLSv1.2 TLSv1.3`、`ssl_session_cache`,`proxy_buffering off`;80 那个 server 除 `/health` 外**全部 `return 301 https://$host$request_uri`**。HEAD compose 发布 `"80:80"` 与 `"443:443"` 并挂载 `./ssl:/etc/nginx/ssl:ro`,前端镜像 `EXPOSE 80 443`(`Dockerfile.frontend`)。**准确说法:HTTPS 配好了,但证书不进仓库**——`ssl/` 被 `.gitignore:47` 忽略、HEAD 不跟踪该目录,全仓无 openssl/自签脚本;不放证书时 nginx 在配置加载阶段就起不来(且 80 会把人 301 到 443),**表现是"入口不可用",不是"退化成 HTTP"**。安全头那一条仍成立:HEAD 只有 `X-Frame-Options`/`X-Content-Type-Options`/`X-XSS-Protection`(`nginx.conf:242-244`),**无 HSTS、无 CSP**。

**第 8 篇定稿采用的叙事口径**

- **落点不是"比谁家更保密"**:私有部署退到基础设施层,只作"地形图"讲(第二节),不单独承担卖点;卖点由两个内部机制承担——**亮点一**运行期无任何上报/回连/主动推送指标(第三节),**亮点二**模型可以完全不出门(第四节)。开篇的"三个答不上来的问题"必须紧跟一句边界声明:不讲另一家后台做得怎样,只讲你自己那台机器上要做什么。
- **"这套东西本来就得有人当操作系统"是全篇主线**,磁盘/进程/时钟/权限/备份五样不会自动出现。"谁在维护你的时钟"这类句子只做引子,不做口号。
- **第五、六节的分工**:第五节只讲数据落点与生命周期(哪张表哪一列、谁建的、删除落到语句上);第六节"运维账单"承担四档——必须改的默认值 / 必须自己加的组件 / 我们没做的 / 明确决定不做的事,共七件事。**默认口令全篇只在第六节出现一次**,不得在两节各铺。
- **可引用的新落库细节**:五个库由 mysql 首启初始化脚本建、业务表由 Flyway 迁移脚本建、**只有 `agent_state` 由运行时自动建**——落点表述为"库与表的创建者不是同一个人",并顺势落到"你要备份的是整个数据库"这一条运维动作上。
- **第七节(单机还是集群)须交棒第 9 篇**:两处只活在 JVM 内存里的状态——MCP OAuth `state` + `code_verifier`、登录验证码与企微扫码登录中间态(`docs/deploy-harnax-admin.md:158-159`);表述为"会话保持不是运维技巧,是产品语义"。
- **禁用句式与措辞**:不写"我们比你更懂你的数据";不用"与其…不如"(红线 4);本篇不出现"底座""员工/岗位/值班表"类比喻词(产品名词除外);"数据不出门"不作标题主张,靠边界取胜——**边界讲清楚比讲全,是卖点**。

**第 9 篇成稿时核实(会话路由 / 故障转移 / 进程内状态)**

可以放心说(缩写 `R=` harnax-session-router/src/main/kotlin/com/agnetix/harnax/router,`A=` harnax-agent/harnax-harness-core/src/main/kotlin/com/agnetix/harnax):

- **三张时钟**:执行服务每 **10 秒**发一次心跳(`agent/harnax-agent-service/.../registrar/AgentServiceRegistrar.kt:57`、`application.yml:143` `AGENT_HEARTBEAT_INTERVAL:10000`);网关每 **5 秒**复查注册表里的心跳时间戳(`R/health/HeartbeatHealthChecker.kt:47`,读的是注册时间戳而非 HTTP 探针);心跳超过 **30 秒**判不健康(`application.yml:99`)。进程停下到被发现,落在 20–35 秒之间。
- **熔断三态**:累计 3 次可重试失败开环,开窗 30 秒,到期由 `allowRequest` 授予 30 秒半开探测租约;探测成功即闭环删键,失败重新计时(`R/service/impl/RedisCircuitBreaker.kt:43-66,101-124,180-188`)。数值是 `application.yml:130-133` 的**字面量**,无 `${ENV}` 占位,只能靠 Spring 属性覆盖。
- **粘性判定的取舍**:绑定的实例只要 `isHealthy && !isDraining` 就沿用,**故意不看熔断**(`R/service/SessionRouterService.kt:538-541`,理由见 `R/service/InstanceCircuitBreaker.kt:12-17`)——一条正在稳定输出的会话,不该因为一次抖动被搬走。
- **首次分配是按会话数加权随机**(`1/(sessions+1)`),方法名叫 `selectLeastLoadedInstance` 但实现不是取最小值(`RedisSessionMappingService.kt:518-539`);**真·取最小值的只有故障转移目标**(`HeartbeatHealthChecker.kt:139-144`)。
