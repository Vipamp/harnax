# 版本控制方案

## 1. 概述

### 1.1 需求背景

系统需要发布三个版本:个人版、企业版、公网版,不同版本支持不同的功能。需要在代码中能够判断当前打包的是哪个版本,根据不同版本做不同的业务逻辑限制。

### 1.2 版本定义

| 版本  | 标识         | 说明            | 目标用户     |
|-----|------------|---------------|----------|
| 个人版 | personal   | 基础功能          | 个人开发者    |
| 企业版 | enterprise | 增加团队协作、高级管理功能 | 企业用户     |
| 公网版 | public     | 全功能版本         | SaaS服务运营 |

### 1.3 核心原则

1. **编译时确定**: 版本信息在打包时写入代码,运行时不可修改
2. **不对外暴露**: 用户无法通过浏览器查看或修改版本信息
3. **代码可判断**: 在前后端代码中都可以通过工具类判断当前版本
4. **简单易用**: 通过 `isPersonal()` 等方法直接判断,无需复杂配置

## 2. 后端方案

### 2.1 技术方案

**核心思路**: 通过 Maven Profile 在编译时将版本信息注入到 properties 文件,运行时通过工具类读取。

### 2.2 实施步骤

#### Step 1: 配置 Maven Profile

**文件**: `vipclaw-admin/pom.xml`

在 `<project>` 标签内添加:

```xml

<profiles>
    <!-- 个人版(默认) -->
    <profile>
        <id>personal</id>
        <properties>
            <edition.current>personal</edition.current>
        </properties>
        <activation>
            <activeByDefault>true</activeByDefault>
        </activation>
    </profile>

    <!-- 企业版 -->
    <profile>
        <id>enterprise</id>
        <properties>
            <edition.current>enterprise</edition.current>
        </properties>
    </profile>

    <!-- 公网版 -->
    <profile>
        <id>public</id>
        <properties>
            <edition.current>public</edition.current>
        </properties>
    </profile>
</profiles>
```

#### Step 2: 创建版本配置文件模板

**文件**: `vipclaw-admin/src/main/resources/edition.properties`

```properties
# 版本信息(打包时通过 Maven 过滤替换)
edition.current=@edition.current@
```

#### Step 3: 启用资源过滤

**文件**: `vipclaw-admin/pom.xml`

在 `<build>` 标签内添加:

```xml

<resources>
    <resource>
        <directory>src/main/resources</directory>
        <filtering>true</filtering>
        <includes>
            <include>**/edition.properties</include>
        </includes>
    </resource>
    <resource>
        <directory>src/main/resources</directory>
        <filtering>false</filtering>
        <excludes>
            <exclude>**/edition.properties</exclude>
        </excludes>
    </resource>
</resources>
```

#### Step 4: 创建版本工具类

**文件**: `vipclaw-admin/src/main/kotlin/com/vipamp/vipclaw/admin/config/EditionUtil.kt`

```kotlin
package com.vipamp.vipclaw.admin.config

import org.springframework.beans.factory.annotation.Value
import org.springframework.stereotype.Component

/**
 * 版本工具类
 * 用于在代码中判断当前打包的版本
 */
@Component
class EditionUtil {

    companion object {
        const val EDITION_PERSONAL = "personal"
        const val EDITION_ENTERPRISE = "enterprise"
        const val EDITION_PUBLIC = "public"
    }

    @Value("\${edition.current}")
    private lateinit var currentEdition: String

    /**
     * 判断是否是个人版
     */
    fun isPersonal(): Boolean = currentEdition == EDITION_PERSONAL

    /**
     * 判断是否是企业版
     */
    fun isEnterprise(): Boolean = currentEdition == EDITION_ENTERPRISE

    /**
     * 判断是否是公网版
     */
    fun isPublic(): Boolean = currentEdition == EDITION_PUBLIC

    /**
     * 获取当前版本名称(用于调试日志,不对外暴露)
     */
    fun getCurrentEdition(): String = currentEdition
}
```

### 2.3 使用示例

#### 示例1: 登录接口 - 返回支持的登录方式

**文件**: `vipclaw-admin/src/main/kotlin/com/vipamp/vipclaw/admin/controller/AuthController.kt`

```kotlin
@RestController
@RequestMapping("/api/auth")
class AuthController(
    private val editionUtil: EditionUtil
) {

    /**
     * 获取当前版本支持的登录方式
     */
    @GetMapping("/login-methods")
    fun getLoginMethods(): Result<Map<String, Any>> {
        val methods = mutableListOf("username") // 所有版本都支持用户名登录

        // 企业版和公网版支持手机号和邮箱登录
        if (editionUtil.isEnterprise() || editionUtil.isPublic()) {
            methods.add("phone")
            methods.add("email")
        }

        return Result.success(
            mapOf(
                "methods" to methods
            )
        )
    }
}
```

#### 示例2: MCP创建接口 - 限制传输模式

**文件**: `vipclaw-admin/src/main/kotlin/com/vipamp/vipclaw/admin/controller/McpController.kt`

```kotlin
@RestController
@RequestMapping("/api/mcp")
class McpController(
    private val editionUtil: EditionUtil
) {

    @PostMapping("/create")
    fun createMcp(@RequestBody mcp: McpEntity): Result<Unit> {
        // 企业版和公网版不支持 stdio 模式
        if ((editionUtil.isEnterprise() || editionUtil.isPublic()) &&
            mcp.transportType == "stdio"
        ) {
            return Result.error("当前版本不支持 stdio 模式")
        }

        // 创建 MCP 逻辑...
        mcpService.create(mcp)
        return Result.success()
    }
}
```

## 3. 前端方案

### 3.1 技术方案

**核心思路**: 通过环境变量在打包时将版本信息注入到代码中,通过工具类提供版本判断方法。

### 3.2 实施步骤

#### Step 1: 创建版本环境文件

**文件**: `vipclaw-webui/.env.personal`

```bash
REACT_APP_EDITION=personal
```

**文件**: `vipclaw-webui/.env.enterprise`

```bash
REACT_APP_EDITION=enterprise
```

**文件**: `vipclaw-webui/.env.public`

```bash
REACT_APP_EDITION=public
```

#### Step 2: 创建版本工具类

**文件**: `vipclaw-webui/src/utils/edition.ts`

```typescript
/**
 * 版本工具类
 * 用于在代码中判断当前打包的版本
 */

// 从环境变量获取版本(打包时确定)
export const EDITION = process.env.REACT_APP_EDITION || 'personal';

export const EDITION_PERSONAL = 'personal';
export const EDITION_ENTERPRISE = 'enterprise';
export const EDITION_PUBLIC = 'public';

/**
 * 判断是否是个人版
 */
export const isPersonal = (): boolean => EDITION === EDITION_PERSONAL;

/**
 * 判断是否是企业版
 */
export const isEnterprise = (): boolean => EDITION === EDITION_ENTERPRISE;

/**
 * 判断是否是公网版
 */
export const isPublic = (): boolean => EDITION === EDITION_PUBLIC;
```

#### Step 3: 添加构建脚本

**文件**: `vipclaw-webui/package.json`

```json
{
  "scripts": {
    "build:personal": "REACT_APP_EDITION=personal npm run build",
    "build:enterprise": "REACT_APP_EDITION=enterprise npm run build",
    "build:public": "REACT_APP_EDITION=public npm run build"
  }
}
```

**本地测试**：
```shell
# 公网版 - 显示"立即注册"
REACT_APP_EDITION=public npm run dev

# 个人版 - 不显示"立即注册"
REACT_APP_EDITION=personal npm run dev

# 企业版 - 不显示"立即注册"
REACT_APP_EDITION=enterprise npm run dev
```

### 3.3 使用示例

#### 示例1: 登录页面 - 动态显示登录方式

**文件**: `vipclaw-webui/src/pages/user/login/index.tsx`

```tsx
import React from 'react';
import { Tabs } from 'antd';
import { isPersonal } from '@/utils/edition';
import UsernameLogin from './components/UsernameLogin';
import PhoneLogin from './components/PhoneLogin';
import EmailLogin from './components/EmailLogin';

const { TabPane } = Tabs;

const LoginPage: React.FC = () => {
  // 直接在组件中判断版本
  const showPhoneLogin = !isPersonal();
  const showEmailLogin = !isPersonal();
  
  return (
    <div className="login-container">
      <Tabs defaultActiveKey="username">
        {/* 用户名登录 - 所有版本都显示 */}
        <TabPane tab="用户名登录" key="username">
          <UsernameLogin />
        </TabPane>
        
        {/* 手机号登录 - 仅企业版和公网版显示 */}
        {showPhoneLogin && (
          <TabPane tab="手机号登录" key="phone">
            <PhoneLogin />
          </TabPane>
        )}
        
        {/* 邮箱登录 - 仅企业版和公网版显示 */}
        {showEmailLogin && (
          <TabPane tab="邮箱登录" key="email">
            <EmailLogin />
          </TabPane>
        )}
      </Tabs>
    </div>
  );
};

export default LoginPage;
```

#### 示例2: MCP创建页面 - 限制传输模式选项

**文件**: `vipclaw-webui/src/pages/mcp/components/McpForm.tsx`

```tsx
import React from 'react';
import { Select, Form } from 'antd';
import { isPersonal } from '@/utils/edition';

const { Option } = Select;

interface McpFormProps {
  // ...
}

const McpForm: React.FC<McpFormProps> = (props) => {
  // 个人版支持所有模式,企业版和公网版不支持stdio

          <Option key={type} value={type}>
            {type}
          </Option>
        ))}
      </Select>
    </Form.Item>
  );
};

export default McpForm;
```

## 6. 注意事项

### 6.1 版本切换

- 版本信息在编译时确定,**运行时不可切换**
- 如需切换版本,必须重新编译打包
- 建议在 CI/CD 流水线中配置不同版本的构建任务

### 6.2 安全性

- 版本信息不对外暴露,用户无法查看当前版本
- 前端编译后的代码中版本号会被打包工具混淆
- 后端版本信息存储在 classpath 中,外部无法访问

### 6.3 扩展性

- 可以随时添加新的版本判断逻辑
- 支持任意复杂的版本限制规则
- 不影响现有代码结构和业务逻辑

### 6.4 兼容性

- 默认版本为个人版,保证向后兼容
- 新增功能默认所有版本都支持,根据需要添加版本限制
- 建议在新功能开发时就考虑版本差异

## 7. 常见问题

### Q1: 能否在运行时动态切换版本?

**A**: 不可以。版本信息在编译时确定,运行时不可修改。如需切换版本,必须重新编译打包。

### Q2: 如何添加新的版本限制?

**A**: 在需要的地方注入 `EditionUtil`,然后使用 `isPersonal()`、`isEnterprise()`、`isPublic()` 方法判断版本即可。

### Q3: 前端版本信息会不会被用户看到?

**A**: 前端版本信息会被打包工具编译混淆,用户无法直接查看。同时前端只是展示控制,真正的权限校验在后端。

### Q4: 如何测试不同版本?

**A**: 使用不同的 Maven Profile 和 npm 构建脚本分别打包,启动后验证功能是否符合预期。

### Q5: 能否同时支持多个版本?

**A**: 一个编译产物只对应一个版本。如果需要同时支持多个版本,需要分别编译多次,生成不同的部署包。
