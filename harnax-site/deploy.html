部署形态
部署形态

它跑在你自己的机器上，代价写在这页

一套 compose、一个构建脚本、十个服务块。这一页把它们的资源上限、上线顺序，以及上线之后必须由你补上的那一串，逐条摆出来。

十个服务块，和它们各自的资源上限

这张表是仓库里那份 compose 的全部内容：9 个服务块是系统本体，第 10 块是自带的天气示例 MCP，用来演示外部工具怎么接进来——它不在构建脚本的六个镜像清单里，由 compose 就地构建。

除入口的 80 与 443，其余发布到宿主的端口一律是 2 开头的五位数，为的是避开本机已经占着常用数据库与缓存端口的别的项目。
服务角色是否发布到宿主该块 limits
mysql 四个业务库的承载者：库由首次启动的初始化脚本建（脚本还建了一个裸名 harnax 库，全仓没有任何连接串用它），表由管理、路由、调度三家的迁移脚本建——引擎状态那个库的表是运行期首次使用时建的，渠道服务的迁移默认关着 是 1 核 / 1024M
redis 共享路由状态：会话绑定、实例注册表、重选锁与熔断态。只支持 standalone 或 Sentinel，且必须保持 noeviction——内存压力一旦把路由键挤掉，会话就悄悄失去绑定、锁也一起没了，比写失败更糟 是 0.5 核 / 768M
minio 对象存储：沙箱工作区的跨重启快照、CLI 包归档 是 1 核 / 512M
admin 管理台后端，也是业务库的主要写入者 是 2 核 / 1024M
router 会话网关：按会话绑定把请求送回同一台执行服务实例、健康复查、熔断与流式代理 是 2 核 / 1024M
scheduler 定时触发与执行，Quartz 集群状态在它自有的库里；compose 里不写副本数，由部署脚本的 SCHEDULER_REPLICAS 决定，默认两个 否，只在容器网络里可达 1 核 / 768M
agent-service 执行引擎与沙箱生命周期，容器里挂着宿主 Docker 套接字去开沙箱 是 2 核 / 2048M
channel-service IM 接入面：飞书、钉钉、企业微信的长连接与回调 是 1 核 / 768M
mcp-server 自带的天气示例 MCP，演示外部工具的登记、授权与调用长什么样 是 0.5 核 / 256M
frontend nginx：SPA 静态资源、到各服务的反向代理，以及 443 入口——HTTPS 配好了，但证书需自备 是，80 与 443 1 核 / 256M

按服务块算：limits 合计 12.0 核 / 8448M，reservations 合计 4.5 核 / 2688M。调度默认起两个副本，所以实跑口径是 limits 13.0 核 / 9216M、reservations 5.0 核 / 2944M。

这些合计不构成起步建议。全仓没有最低配置要求文档，它们是这份 compose 自己写下的上限，不是「你需要一台多大的机器」。机型请按你自己的会话量、沙箱并发和模型位置测。

上线顺序：一个脚本，四步

构建期确实需要网络——Maven 与 npm 要拉依赖，这一步不藏着。运行期没有上报路径，出站的都是你配的地址或你启用的能力。

  1. 预装 mvn / node / docker。构建脚本会检查前两个是否存在，缺了就停下告诉你缺哪个。
  2. 跑 bash build.sh。它产出六个服务镜像——admin、router、agent-service、scheduler、frontend，以及承载飞书、钉钉、企业微信接入的 channel-service；另外准备默认沙箱镜像与 CLI 包货架。
  3. 放入自有证书。443 那个 server 指向 /etc/nginx/ssl/server.crt 与 .key，而 ssl/ 目录不进仓库，全仓也没有自签脚本。不放证书的表现是「入口起不来」——nginx 在配置加载阶段就失败；80 上除了一处给容器健康检查用的 /health 直答 OK，其余路径一律 301 到 443，所以它不会退化成 HTTP 继续服务。
  4. 跑 bash deploy-all.sh。它是冷启动：整栈停掉再起，包括全部 scheduler 副本。副本数由脚本环境变量 SCHEDULER_REPLICAS（默认 2）带进 --scale，compose 里不写 deploy.replicas——它和逐台停起的 roll-scheduler.sh、replace-one 会互相冲突。只想换某个服务的镜像，走 deploy-service.sh，scheduler 会逐台停起。
冷启动这段时间会堆触发。整栈停到 mysql 健康门 + JVM 起来之间，错过的过期触发按 concurrent=0 任务的 DoNothing 策略直接丢弃，不补发、不重试、也不告警。请挑安静时段跑，日常换镜像走单服务滚动。

上线之后要还的运维清单

四档：必须改的、必须自己加的、我们没做的、明确决定不做的。最后一档不是谦虚，是设计选择。

必须改的默认值

出厂口令与三类密钥都是仓库里公开的字符串：管理口令、JWT 密钥、AES 密钥、内部接口 secret、对象存储与数据库口令。对占位值的检查只有三处，强度不一样：会话网关的 redis 模式（它要求缓存侧 noeviction）撞上占位密钥直接拒绝启动；管理台对内部接口 secret 打一条 WARN，同时把它当作「没配过」而拒绝用作凭据——照着默认值来调的服务会拿到 401；对 AES 密钥只打一条 WARN 然后照跑。渠道、调度、执行三服务这里不设检查。

加密只覆盖密钥类字段（AES-256-GCM）；对话正文与工具入参是明文入库。口令走 BCrypt，JWT 两小时过期。

必须自己加的组件

证书（见上一步）；备份与恢复——全仓没有导出脚本，只有规范文档里一句「迁移前必须备份」，而你要备份的是整个数据库，不只是会话表。

Prometheus 抓取配置与告警规则；容器 stdout 的轮转与上限取决于宿主 Docker daemon 的配置，compose 里没有这一节。

我们没做的

容器编排化——这份 compose 就是全部，没有第三种运行形态。告警出口——失败之后没有人在管，只有日志、指标和 health 状态。

观测表清理任务：调度域两张表有硬编码保留期（执行日志 90 天、执行守护记录 7 天，都不可配），且那条 90 天的删除会跳过超时与停止状态的行；Quartz 自己的那些表没有人清。工具调用明细可配，HARNAX_METRICS_RETENTION_DAYS 默认 90 天，且某一天的行要等它先折进小时表才丢；CLI 归档也可配，HARNAX_CLI_ARCHIVE_RETENTION_DAYS 默认 7 天。其余几张表这里不设删除语句，也没有分区与容量兜底。

明确决定不做的

stdio 型 MCP 的运行：那条路径要由执行服务容器拉起进程，而这个容器挂着宿主 Docker 套接字，运行侧没有隔离，所以开关默认关闭。

AI 自产技能：能力做了，写入开关默认关闭，技能仓库对 Agent 只读。这两条是决定，不是待办。

它会往外发什么：四组路径

运行期无遥测、无版本检查、无许可证校验，指标只被动由你抓取。下面四组是它够得着外界的全部路径：前三组由配置项决定去不去，第四组只在你启用对应能力时才出现。

模型

三类协议族：DashScope、OpenAI 兼容、Ollama。地址是配置项，OpenAI 兼容的 baseUrl 可以指内网；Ollama 默认 localhost:11434，且这条协议族根本不读 API Key。

外部 MCP

你在管理台登记的那个 url，任意地址，同样可以指内网。自带示例 MCP 也走这条路。关掉或未登记，就没有这一类流量。

OAuth 型要多走两跳：按 RFC 8414 读那个授权服务器的 /.well-known 元数据，再访问它报上来的令牌端点换发。地址仍由服务器元数据决定，不是你填的 MCP url。

IM 平台

飞书、钉钉、企业微信三家的接入域名写在源码常量里。渠道是逐个启用的：不启用某个渠道，就没有指向它的连接。

启用才有

技能来源仓库：git 克隆，地址由你填，白名单只管协议（https / http / ssh / git / git@）不管主机，180 秒超时。

邮件发送：SMTP 的宿主与凭据是挂在 agent 上的环境参数，填了才会有这条连接。沙箱镜像构建：只有 CLI 包声明了系统依赖时，构建期才会 apt-get 拉包，基础镜像也得拉得到。

对象存储：沙箱快照与 CLI 归档写的那台，compose 默认指栈内的 minio 服务，可 MINIO_ENDPOINT 本身就是配置项——你把它指到外部 S3 兼容地址，那也是一次出站。

「私有部署」在这里的准确含义：出站的是上面四组路径，全部由你的配置和启用范围决定，运行期没有上报路径——而不是「它一定不与外界通信」。构建期需要网络（Maven、npm、模型依赖都要拉），检索是关键词实现、连 embedding 模型都不需要，这两句话说的是同一件事的两面。
