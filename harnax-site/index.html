部署形态
自托管的多智能体运行平台

把 AI 从一次调用，做成能长期运行的系统

它有自己的岗位说明书、工具箱、排班表和一群同事。你要做的，是决定它跑在哪台机器上。

看部署形态 它具体在干什么

运行期没有遥测与上报路径，指标只被动抓取——暴露抓取端点的只有三个服务。出站点不止模型一类：外部 MCP、技能来源仓库、邮件发送与对象存储都算，而 IM 平台的域名写在源码常量里。

一条群消息的完整链路

看得见的入口

你看得见的四件事

不是演示效果。四个入口每一个都能说清它走哪条链路、在哪一步会停下来等人。

其一

在群里派活

群里统一解析 10 类斜杠命令，大小写不敏感（/approve、/deny、/clear、/stop、/compact 只是其中几个，适配飞书、钉钉、企业微信等渠道），确认请求发回同一个群，放行后挂起的那一步继续跑。有一处要说在前面：带参数的命令在群里只剩命令名，转发时参数会丢。断线指数退避重连；多副本下一把 MySQL 命名锁决定谁在听。

其二

你睡着的时候它在上夜班

cron 表达式加 5 个常用预设；任务、触发锁与执行日志落在调度服务自有库，重启不丢。执行日志六个状态，超过该行超时 1.5 倍仍未收尾的残行，由回收路径批量判死。

其三

一个 AI 干不完的活，交给一个团队

主管只保留 3 个编排工具，不带业务工具、不接 MCP、不给沙箱；成员各自保留自己的工具与技能。委派上限 20 次、成员单轮 900 秒、产物单文件 20 MiB 并在运行期拦截——但它们是配置项的默认值，不是写死的常量，改了就按新的拦。

其四

它会停下来等你签字

命令与文件操作在独立容器内执行，参数级扫描危险命令与敏感路径，命中即转人工确认并附 safety 理由。停机前工作区打快照，跨重启靠对象存储接回。

群聊与团队是两个独立场景：团队模式只挂在 web- 这一种会话前缀上（网页端与 iOS 复用同一个创建入口），mp- 与 chn- 两种前缀创建时都不带团队字段——IM 群里跑的是单个 AI 员工，两者不叠加。
运行期机制

你看不见的四个机制

四件事决定它能不能长期运行：状态放在哪、这一发归谁、技能怎么入库、每一步留下什么。

图 1 · 哪些状态扛得住换一台机器

会话为什么要粘在一台机器上

问题

Agent 的一部分可变状态不在库里，而在某个进程的内存与本地磁盘上：ReAct 循环的上下文、沙箱工作区。「无状态服务 + 轮询负载均衡」那套模型在这里会失效。

做法

等确认这一步分两条路，不能混说：普通会话命中工具确认时本轮直接收尾，待确认的调用以 ASKING 状态落库、放行时按 id 重建，换一台实例也读得回来；团队子运行才是那个被 future.get() 占住的线程，窗口 600 秒、每 30 秒切片补发一次心跳，物理上搬不走。三张时钟把「进程停下」变成可判定：10 秒上报、5 秒复查、30 秒判死，发现窗口落在 20–35 秒之间。新会话按 1/(会话数+1) 的倒数加权随机分配；故障转移时若候选负载比平均值的双倍还高，就改挑更小的那台。

代价

每轮结束才落快照，崩掉会丢最后一段；那一轮的半截输出不重放。流式请求只对连接类失败转移，且仅在第一事件吐出之前。

固定的是执行服务实例，网关本身多副本共享同一份绑定——粘性是为「有人在等它回话」服务的，不是为负载均衡服务的。那份共享绑定表放在 Redis 上：只支持 standalone 或 Sentinel，且需 noeviction。

图 2 · 两层锁，和一个别混读的窗口

「只触发一次」和「只做一遍」是两件事

问题

调度副本调到 3 台，一条早八点的任务三台一起敲吗？敲的那台在触发前一刻挂掉，这一天的简报还发得出来吗？

做法

两层锁：Quartz 集群行锁管谁拿到触发器，我们再往触发锁表撞唯一键 (task_id, trigger_time) 管这一发归谁。接管窗口 22.5–52.5 秒，小于 60 秒的 misfire 阈值。

代价

死在触发之后不补发：仍未收尾的行要等到「超过自身超时 1.5 倍」才被回收轮次改成超时，按默认 300 秒算是 7.5 分钟起、最坏 12.5 分钟，而远端那次执行还在跑、没人认领。幂等这套系统给不了你，它得做在你的业务里。

接管窗口是纸面推导：集成测试 ClusterSingleFireIT 只覆盖单次触发，不覆盖接管，也不覆盖负载均衡与真实调用链路。

图 3 · 先关押，再审查，才准上岗

技能不是提示词片段

问题

技能包是会被解压进沙箱、被文件工具读取的一堆文件。它进库之前，该不该有人把关？

做法

入库前过 9 条内容扫描规则，命中即写进同步返回的扫描报告、技能以停用态入库，人工确认后才可用。会入库的来源三型各有硬约束（系统自带的那类不走这条路）：Git 走协议白名单、npm 安装带 --ignore-scripts、ZIP 有四项上限且越界直接抛 SecurityException。投影按 sha256 清单每轮收敛，无差异零写入。

代价

没有版本历史与回滚，改了就是改了；技能自身的状态只有两值。但审批队列是真在的：AI 提出的草稿走待审 / 通过 / 驳回 / 过期四态，记下审阅人、审阅时间与驳回理由，晋升时再复扫一次并留日志——缺的是指派与多级会签，不是队列本身。AI 自产技能这个能力做了，写入开关默认关闭，技能仓库对 Agent 只读。

图 4 · 六张表，只有三处读得回来

写了六张表，读得回来三处

问题

「记下来了」和「看得见」是两件事，「看得见」和「算得清」又是两件事。

做法

用量表一次模型调用一行，流式与非流式同一读数；网关日志只记哪次、多久、成没成，刻意不带正文，且是异步批量落库。工具调用留痕也走异步：默认攒够 64 行或到了刷新间隔才落一次，入参与返回值各截到 2000 字符，整条采集还能直接关掉。剩下三张（用量、过程、MCP 令牌授权）才是同步单条写入，而那张 MCP 表记的是令牌的签发、刷新与吊销，不是 MCP 调用本身。

代价

两张留痕表应用层只写不读，要看就得自己连库。fee 恒为 0，那一列的精度连「分」都存不下，全仓也没有单价表——可看板照样渲染着一张 ¥0.00 的卡。没有配额、阈值与告警，限流器限的只是每分钟请求数；调用链没有全局标识，能串的只有会话 id。

边界摘要

四件我们没做的事

写在首页，是因为它们会在上线第一周就找到你。承认边界比讲全卖点更难，也更值钱。

没有

备份与恢复工具

你要自己做的：备份范围不止一个库——会话与观测在管理库，任务与执行日志在调度服务自有的库里，路由表又在一个库里，备份计划得自己排，恢复演练也得自己做。

没有

告警出口

你要自己做的：夜班失败不会有人通知你。抓取端点只有网关、调度、渠道三个服务暴露，管理台与执行服务没有；抓取、阈值和值班路由都是你的活。

没有

版本回滚与责任人流转

你要自己做的：技能只有当前版本指针，没有回滚。草稿审批链上确实记着状态、审阅人、审阅时间与驳回理由，但那是队列不是流转——没有指派，也没有多级会签。

没有

容器编排化

你要自己做的：交付形态只有 compose。要把这十块搬到多机上编排，清单得自己写。
