# Harnax 官网设计（分层叙事 · 中英双语 · 零构建静态）

## 1. 目标与范围

- 目的：对外说明 Harnax 是什么、凭什么能长期运行、能以什么形态跑在自己的机器上；全站唯一主 CTA 落在部署页。
- 交付：`harnax-site/`，4 个页面 × 2 种语言 = 8 份 HTML，共享一份 CSS 与一份 JS。
- 不做：文档站、博客渲染、仓库入口、开源相关表述、任何需要后端接口的表单。

页面清单：

| 路径 | 磁盘文件 | 职责 |
|---|---|---|
| `/` | `harnax-site/index.html` | 首页，分层叙事全部七屏 |
| `/capability.html` | `harnax-site/capability.html` | 四个运行期机制各一节，配示意图 |
| `/deploy.html` | `harnax-site/deploy.html` | 三种运行形态 + 运维账单四档 |
| `/boundaries.html` | `harnax-site/boundaries.html` | 边界页：没做的、要收窄的、口径从哪来 |
| `/en/…` | `harnax-site/en/` 同名四文件 | 英文版，结构与锚点与中文版逐一对应 |

## 3. 首页逐屏规格与实际文案

### 屏 1 · Hero

- 眉标：自托管的多智能体运行平台
- 主标（中）：把 AI 从一次调用，做成能长期运行的系统
- 主标（英）：Turn AI from one call into a system that keeps running
- 副标（中）：它有自己的账号、岗位说明书、工具箱、排班表和一群同事。你要做的，是决定它跑在哪台机器上。
- 副标（英）：Its own credentials, job description, tool belt, duty roster and teammates. Your only decision is which machine they live on.
- 主按钮：看部署形态 → `/deploy.html`；次按钮：它具体在干什么（页内滚至屏 2）
- 右侧视觉：静态示意——一条消息从 IM 进来，经网关粘到某台执行实例，工具在容器里执行，结果回群。不带任何真实数据。

Hero 不写「赋能」「颠覆」「下一代」，不出现客户名与任何规模承诺。

### 屏 2 · 你看得见的四件事

卡片标题 + 一句机制 + 一个具体数，四张：

1. **在群里派活**：各渠道统一解析 `/approve`、`/deny`、`/clear`（适配飞书、钉钉、企业微信），确认请求发回同一个群，放行后挂起的那一步继续跑。断线指数退避重连，多副本下一把 MySQL 命名锁决定谁在听。
2. **你睡着的时候它在上夜班**：cron 表达式加 5 个常用预设；任务、触发锁与执行日志落在调度服务自有库，重启不丢。执行日志六个状态，超时 1.5 倍的残行由回收路径判死。
3. **一个 AI 干不完的活，交给一个团队**：主管只保留 3 个编排工具，不带业务工具、不接 MCP、不给沙箱；成员各自保留自己的工具与技能。委派上限 20 次、成员单轮 900 秒、产物单文件 20 MiB 全部是代码常量并在运行期拦截。
4. **它会停下来等你签字**：命令与文件操作在独立容器内执行，参数级扫描危险命令与敏感路径，命中转人工确认并附 safety 理由；沙箱工作区跨重启靠对象存储快照接回。

### 屏 3 · 你看不见的四个机制

四节，每节一张内联 SVG + 三段式（问题 / 做法 / 代价）：

1. **会话为什么要粘在一台机器上**——可变状态不在库里，而在某个进程的内存与磁盘上：等确认那一步是一个被 `future.get()` 占住的线程，窗口 600 秒，物理上搬不走。三张时钟：10 秒上报、5 秒复查、30 秒判死。代价写在同屏：崩掉丢最后一段、半截输出不重放。
2. **「只触发一次」和「只做一遍」是两件事**——两层锁：Quartz 集群行锁管谁拿到触发器，我们再往触发锁表撞唯一键 `(task_id, trigger_time)` 管这一发归谁。接管窗口 22.5–52.5 秒，小于 60 秒 misfire 阈值。诚实标注：纸面推导，`ClusterSingleFireIT` 不覆盖接管与真实链路。
3. **技能不是提示词片段**——9 条内容扫描规则命中即写进同步报告并以停用态入库，人工确认后才可用；来源三型各有硬约束（Git 协议白名单排除 `file://` 与 `ext::`、npm 带 `--ignore-scripts`、ZIP 四项上限越界即 `SecurityException`）。投影按 sha256 清单收敛，只删自己写过的目录，无差异零写入。
4. **写了五张表，读得回来两张**——用量表一次模型调用一行，流式与非流式同一读数；网关日志记哪次、多久、成没成，刻意不带正文。另三张留痕表应用层只写不读，要看就自己连库。这一节把「记下来了」和「看得见」分开讲。

### 屏 4 · 三种运行形态

三档并排，替代常见的价格表位：

| 形态 | 内容 |
|---|---|
| 单机 | `CACHE_TYPE=local`，SQLite + 进程内缓存，零外部依赖；同一套路由逻辑照样选实例、重试、熔断 |
| 集群 | MySQL + Redis；限 standalone 或 Sentinel，且需 `noeviction`；会话绑定读改写由一条 Lua 脚本完成 |
| 模型可完全本地 | 三类协议族 DashScope / OpenAI 兼容 / Ollama；Ollama 默认 `localhost:11434` 且不读 apiKey；OpenAI 兼容的 baseUrl 可为内网地址；检索是关键词实现，连 embedding 模型都不需要 |

### 屏 5 · 规模事实（数字条，替掉 logo 墙）

11 个顶层 Maven 模块 + 14 个子模块 · 后端主代码全量 Kotlin · 一套 compose 10 个服务块（9 个系统本体，1 个自带示例 MCP）· limits 合计 12.0 核 / 8448M · 持久层用 Testcontainers 起真实 MySQL · 运行期无遥测，指标只被动 pull。

明确注一句：全仓无最低配置要求文档，以上数字是 compose 自己写的资源上限，不是起步规格建议。

### 屏 6 · 边界摘要

四行小卡：没有备份与恢复工具 / 没有告警出口 / 没有版本回滚与审核工作流 / 没有 Kubernetes。每行一句「所以你要自己做的」，整块链到 `/boundaries.html`。

### 屏 7 · 系列文章 + 底栏

《AI 员工图鉴》十期标题列表（第 7 期标注暂缓并入第二季），只列标题与一句摘要，不渲染正文。底栏四栏：产品（三页）／形态（三档）／文章（十期）／口径（本页所有断言的判据来源与更新日期）。

## 4. 二级页规格

- **`capability.html`**：屏 3 四节的展开版，每节含示意图、机制分解、失效面清单、锚点导航（左侧粘性目录）。不新增首页没有的断言。
- **`deploy.html`**：① 一套 compose 起 10 个服务块的拓扑表（服务 / 端口 / limits / 是否发布到宿主）；② 上线顺序：先跑构建脚本（要求预装 mvn / node / docker）再起 compose，措辞用「一个脚本」，不用「一条命令」；③ 运维账单四档——必须改的默认值（出厂口令与三类密钥都是仓库里公开的字符串，只有一处有拒启动检查）、必须自己加的组件（证书、备份、Prometheus 抓取、日志轮转取决于宿主 Docker）、我们没做的（K8s、告警、清理任务）、明确决定不做的（stdio 型 MCP 运行、AI 自产技能开关）；④ 出站面清单：模型 / 外部 MCP / IM 三类，前两类地址可配内网，第三类不启用即无流量，构建期确实需要网络。
- **`boundaries.html`**：三节——「不能说清的功能」（stdio 仅登记、文件直发按渠道能力、迭代上限不可配、渠道页无能力开关）、「要收窄的表述」对照表、「口径从哪来」（判据方式与更新日期，声明任何一条与代码不符即为缺陷）。

## 6. 双语机制

- 中文四页在站点根，英文四页在 `en/` 同名文件，锚点 id 与 DOM 结构一一对应，仅文案不同。两树内所有资源与站内链接一律写成绝对路径（`/assets/site.css`、`/deploy.html`），不出现 `../` 与 `./` 两套相对写法。
- 顶栏语言开关互链；每页 `<head>` 双向 `hreflang`（zh / en / x-default 指向中文版）+ 单一 `canonical`。
- 默认落地 `/`（中文）；`en/` 靠开关与 hreflang 进入，不做 UA/语言嗅探重定向。
- 图标、CSS、JS 不复制，两树共用 `assets/`。

## 7. 验证

1. **口径机器闸**（`harnax-site/tools/check.mjs`，无第三方依赖）：
   - 禁用词扫描：2.1 词表对 8 份 HTML 全站零命中，中英文各查一遍；
   - 数字白名单扫描：正则抽出站内所有阿拉伯数字串，逐个对 2.3 清单比对，白名单外即失败；
   - 限定语成对检查：2.2 每条主张的前半句出现时，后半句关键短语必须在同一节内出现；
   - 双语结构对账：两份树的 section id 集合、卡片数、链接数逐项相等，hreflang 双向闭合。
2. **对比度**：从 `site.css` 的 `:root` 解析 token，对「前景/背景」实际使用组合算 WCAG 相对亮度，正文要求 ≥4.5:1、大字 ≥3:1；脚本自己算，不靠肉眼。
3. **渲染取证**：因为站内链接是绝对路径，`file://` 打开取不到样式与脚本，一律先起本地静态服务（`python3 -m http.server` 指向 `harnax-site/`）。无头 Chrome 对 8 份页面各出 `--screenshot`（桌面 1440×3200、移动 390×2200）与 `--dump-dom`，断言 DOM 内必备标题与 CTA 文案存在、无未替换占位符（`TBD`/`Lorem`/`{{`）。
4. **语法地板**：`site.js` 与 `check.mjs` 用 `node --check` 校验语法，不引入任何解析器依赖；每份 HTML 用一次真实解析（浏览器 dump-dom 成功即算通过）而不是正则数标签。
5. **人工抽查**：逐页看深底 Hero 与示意图在两种语言下的换行与溢出，英文比中文长 15–25%，卡片必须有余量。

## 8. 明确不做

- 不做文档站、不做博客正文渲染、不做搜索。
- 不放仓库地址、不放下载物、不提许可证与开源。
- 不做注册/登录/表单，主 CTA 只指向站内部署页。
- 不做真实管理台截图，证据一律为示意图与机制数字。
- 不引入任何 npm 依赖与构建步骤。
