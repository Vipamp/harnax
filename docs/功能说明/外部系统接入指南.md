# 外部系统接入指南（Router 服务）

> 本文档面向需要把 Harnax 对话能力集成到自己系统里的开发者。通过会话路由服务（Router，默认端口 8081），外部系统可以创建会话、发送消息、接收 AI 的流式回复。

## 接入前准备

1. **申请 API Key**：请管理员在「系统管理 → API Key 管理」中创建，Key 格式形如 `hnx_sk_live_xxxx`，**明文只在创建时显示一次**，请妥善保存
2. **确认服务地址**：Router 服务地址形如 `http://<router-host>:8081`
3. **了解限流**：每个 Key 默认 60 次/分钟（创建时可调整 1 ~ 10000），超限返回 HTTP 429，响应头带 `Retry-After`

## 鉴权方式

所有请求在 Header 中携带 API Key：

```
X-Api-Key: hnx_sk_live_xxxxxxxx
```

| 状态码 | 含义 |
|---|---|
| 401 | Key 缺失、无效或已过期（Key 被撤销后最长 5 分钟内仍可能通过缓存校验） |
| 429 | 触发限流，按 `Retry-After` 头等待后重试 |
| 503 | 后端暂无可用的智能体实例 |

## 接口一览

所有接口前缀为 `/api/router/agent`，响应统一包络 `{ code, message, data, timestamp }`，`code = 200` 表示成功。

### 核心接口

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/chat` | 发送消息，一次性返回完整回复 |
| POST | `/chat/stream` | 发送消息，SSE 流式返回（**推荐**） |
| POST | `/command` | 会话控制命令（中断、清空、开关能力等） |
| POST | `/confirm` | 确认 / 拒绝工具调用（SSE 返回后续回复） |

### 辅助接口

| 方法 | 路径 | 用途 |
|---|---|---|
| DELETE | `/session/{sessionId}` | 清除会话 |
| GET | `/chat/history/{sessionId}` | 获取对话历史 |
| GET | `/session/{sessionId}/plans` | 获取会话全部任务计划 |
| GET | `/session/{sessionId}/current-plan` | 获取当前执行中的计划 |
| GET | `/workspace/{sessionId}/files?path=` | 浏览工作空间文件 |
| GET | `/workspace/{sessionId}/read?path=` | 读取文件内容 |
| POST | `/workspace/{sessionId}/upload` | 上传文件（multipart） |
| GET | `/workspace/{sessionId}/download?path=` | 下载文件（上限 50 MB） |
| GET | `/workspace/{sessionId}/status` | 查询会话沙箱状态 |

## 完整调用流程

```
拿到 API Key
    │
    ▼
POST /chat/stream  ──── 发送消息（自定义 sessionId 即自动创建会话）
    │
    ▼
接收 SSE 事件流 ──── 思考 → 工具调用 → 文本回复 → 结束
    │
    ├── 收到 ToolConfirmEvent？ ──→ POST /confirm 批准或拒绝
    │
    ▼
收到 EndEvent，本轮对话结束
```

### 第一步：发送消息

```bash
curl -N -X POST http://router-host:8081/api/router/agent/chat/stream \
  -H "X-Api-Key: hnx_sk_live_xxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "sessionId": "my-session-001",
    "message": "帮我写一个快速排序",
    "requestId": "req-20260731-001",
    "type": "CHAT"
  }'
```

请求字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `sessionId` | 是 | 会话标识，自行定义；同一 sessionId 的消息共享上下文 |
| `message` | 是 | 用户消息文本 |
| `imageUrls` | 否 | 图片列表（URL 或 Base64），用于多模态提问 |
| `requestId` | 否 | 幂等去重键，60 秒内相同 ID 的重复请求会被拒绝（仅非流式接口生效） |
| `type` | 是 | 固定填 `"CHAT"` |

### 第二步：解析 SSE 事件流

每个事件为一行 `data: {...}`，通过 `eventType` 字段区分，共 7 种：

| eventType | 含义 | 关键字段 |
|---|---|---|
| `ThinkingEvent` | AI 思考过程 | `message`、`isLast` |
| `TextEvent` | 文本回复分片 | `message`、`isLast` |
| `CallToolEvent` | 正在调用工具 | `toolId`、`toolName`、`arguments` |
| `ToolResultEvent` | 工具执行结果 | `toolName`、`message`、`success` |
| `ToolConfirmEvent` | 等待你确认的工具调用 | `pendingCallTools`（含 `isDangerous` 危险标记） |
| `ErrorEvent` | 出错 | `code`、`message` |
| `EndEvent` | 流结束 | — |

每个事件可携带 `tokenUsage`（输入 / 输出 / 总 Token、耗时），便于自行统计用量。

#### 各事件完整字段示例

**ThinkingEvent — 思考过程**（流式分片，`isLast: true` 表示本段思考结束）：

```json
{
  "eventType": "ThinkingEvent",
  "message": "用户需要一个快速排序的实现，我先考虑用 Python…",
  "isLast": false
}
```

**TextEvent — 正式回复**（流式分片，逐段拼接即为完整回答）：

```json
{
  "eventType": "TextEvent",
  "message": "以下是快速排序的实现：\n\n```python\ndef quick_sort(arr):…",
  "isLast": false
}
```

**CallToolEvent — 开始调用工具**：

```json
{
  "eventType": "CallToolEvent",
  "toolId": "tool-1",
  "toolName": "code_execute",
  "arguments": { "language": "python", "code": "print(quick_sort([3,1,2]))" }
}
```

**ToolResultEvent — 工具执行完成**：

```json
{
  "eventType": "ToolResultEvent",
  "toolId": "tool-1",
  "toolName": "code_execute",
  "message": "[1, 2, 3]",
  "success": true
}
```

**ToolConfirmEvent — 等待确认**（收到后流会暂停，需调用 `/confirm` 才继续）：

```json
{
  "eventType": "ToolConfirmEvent",
  "pendingCallTools": [
    {
      "toolId": "tool-2",
      "toolName": "file_delete",
      "arguments": { "path": "/workspace/tmp.txt" },
      "isDangerous": true
    }
  ]
}
```

**ErrorEvent — 出错**（`code` 为业务错误码，如 `6011` 表示暂无可用实例）：

```json
{ "eventType": "ErrorEvent", "code": "6004", "message": "LLM 调用失败" }
```

**EndEvent — 流结束**（携带整轮的最终用量）：

```json
{
  "eventType": "EndEvent",
  "tokenUsage": { "inputTokens": 15, "outputTokens": 120, "totalTokens": 135, "costTime": 2.5 }
}
```

#### 分片拼接规则（isLast）

- `ThinkingEvent` 和 `TextEvent` 是流式分片：同类事件按到达顺序把 `message` **依次追加**即可
- `isLast: true` 表示该段落结束，此时事件通常携带 `tokenUsage`
- 思考和文本可能交替出现多轮（思考 → 调工具 → 再思考 → 再回复），请按 `eventType` 分开累积，不要混拼

#### 客户端处理建议

| 收到事件 | 建议处理 |
|---|---|
| `ThinkingEvent` | 渲染为可折叠的"思考中"区域，或仅记日志，不作为正式回答 |
| `TextEvent` | 追加到回答区，实时展示打字机效果 |
| `CallToolEvent` | 展示"正在执行 xxx 工具"状态提示 |
| `ToolResultEvent` | 展示工具结果；`success: false` 时提示执行失败，AI 通常会自行处理并继续 |
| `ToolConfirmEvent` | **必须响应**：向用户展示待确认工具（`isDangerous: true` 的高亮警示），然后调用 `/confirm`；不响应则本轮对话停在等待状态 |
| `ErrorEvent` | 展示错误信息；`6011` 等服务类错误可提示稍后重试 |
| `EndEvent` | 结束本轮，关闭连接，记录 `tokenUsage` 用量 |

> 解析注意：SSE 每条事件以 `data: ` 开头、空行分隔；请忽略空行和心跳注释行（以 `:` 开头）；单条 `data:` 内容是完整 JSON，按 `eventType` 路由处理，遇到不认识的事件类型建议忽略而非报错，以便未来平滑升级。

示例事件流：

```
data: {"eventType":"ThinkingEvent","message":"用户需要快速排序…","isLast":true}

data: {"eventType":"CallToolEvent","toolId":"tool-1","toolName":"code_execute","arguments":{...}}

data: {"eventType":"ToolResultEvent","toolId":"tool-1","toolName":"code_execute","message":"执行成功","success":true}

data: {"eventType":"TextEvent","message":"以下是快速排序实现…","isLast":true,"tokenUsage":{"inputTokens":15,"outputTokens":120,"totalTokens":135}}

data: {"eventType":"EndEvent"}
```

### 第三步（按需）：确认工具调用

收到 `ToolConfirmEvent` 后，调用 `/confirm` 决定是否放行，响应仍为 SSE 流（AI 继续执行后的回复）：

```bash
curl -N -X POST http://router-host:8081/api/router/agent/confirm \
  -H "X-Api-Key: hnx_sk_live_xxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "sessionId": "my-session-001",
    "toolResults": [
      { "toolId": "tool-1", "toolName": "code_execute", "confirmed": true, "alwaysAllow": false }
    ],
    "type": "CONFIRM"
  }'
```

- `toolResults` 支持逐个工具批准 / 拒绝，`alwaysAllow: true` 可将该工具加入白名单，后续不再询问
- 也可用 `isConfirmed: true/false` 批量统一处理

## 会话控制命令

通过 `POST /command` 对会话进行控制：

```json
{ "sessionId": "my-session-001", "command": "ENABLE", "args": "thinking", "type": "COMMAND" }
```

| command | 作用 | args |
|---|---|---|
| `INTERRUPT` | 中断当前回复 | — |
| `CLEAR` | 清空会话历史 | — |
| `COMPACT` | 压缩上下文，节省 Token | — |
| `APPROVE` / `DENY` | 批准 / 拒绝待处理操作 | — |
| `ENABLE` / `DISABLE` | 开关会话能力 | `thinking`（深度思考）/ `search`（联网）/ `plan`（计划模式） |
| `PERMISSION` | 设置权限模式 | `DEFAULT` / `BYPASS` / `ACCEPT_EDITS` / `EXPLORE` / `DONT_ASK` |
| `STOP_SANDBOX` | 停止会话沙箱 | — |
| `REFRESH` | 刷新会话配置 | — |

> 深度思考、联网、计划模式是**会话级开关**，设置一次持续生效，不需要每条消息都传。

## Java / Kotlin SDK（推荐）

平台提供官方客户端 SDK，免去手写 HTTP 和 SSE 解析。

### 方式一：无 Spring 环境（harnax-single-client）

基于 JDK 21 内置 HttpClient，零框架依赖：

```kotlin
val client = SingleHarnaxClient.builder()
    .baseUrl("http://router-host:8081")
    .apiKey("hnx_sk_live_xxxx")
    .connectTimeout(Duration.ofSeconds(5))
    .readTimeout(Duration.ofSeconds(30))
    .streamTimeout(Duration.ofMinutes(10))
    .build()

// 同步调用
val result = client.chat(ChatRequest(sessionId = "sess-1", message = "你好"))

// 流式调用（Kotlin Flow）
client.chatStream(ChatRequest(sessionId = "sess-1", message = "你好"))
    .collect { event -> println(event) }
```

### 方式二：Spring Boot 项目（harnax-springboot-client）

引入依赖后在 `application.yml` 配置即可自动装配：

```yaml
harnax:
  client:
    base-url: http://router-host:8081
    api-key: hnx_sk_live_xxxx
    connect-timeout: 5s
    read-timeout: 30s
    stream-timeout: 10m
```

```kotlin
@Service
class MyService(private val harnaxClient: HarnaxClient) {
    suspend fun ask(sessionId: String, msg: String) =
        harnaxClient.chat(ChatRequest(sessionId, msg))
}
```

### SDK 能力清单

对话（`chat` / `chatStream`）、命令（`command`）、工具确认（`confirm`）、会话管理（清除 / 历史 / 计划）、工作空间（列文件 / 读取 / 上传 / 下载 / 状态查询），与 HTTP 接口一一对应。

SDK 异常分三类：连接异常（超时、DNS）、请求异常（参数构造错误）、服务端异常（含 HTTP 状态码和响应体）。

## 配置与可靠性细节

| 项目 | 默认值 | 说明 |
|---|---|---|
| SSE 流超时 | 10 分钟 | 超长任务请留意，客户端超时应设置不小于此值 |
| 幂等去重窗口 | 60 秒 | 同一 `requestId` 重复提交被拒绝（仅非流式） |
| 会话粘性路由 | 自动 | 同一 `sessionId` 固定路由到同一后端实例，上下文连续 |
| 故障自动转移 | 最多重试 2 次 | 后端实例宕机时自动切换到健康实例，调用方无感 |
| 熔断保护 | 连续失败 3 次熔断 30 秒 | 避免雪崩 |
| 文件下载上限 | 50 MB | 超出返回 HTTP 413 |
| API Key 缓存 | 5 分钟 | 撤销 Key 后最长 5 分钟才完全失效 |

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 401 `API key validation failed` | Key 无效 / 被禁用 / 过期，请管理员检查或重新生成 |
| 429 | 超出速率限制，按 `Retry-After` 等待，或请管理员调高限额 |
| `Duplicate request: xxx` | 60 秒内 `requestId` 重复，属幂等保护，换新 ID 即可 |
| SSE 流中 `ErrorEvent code=6011` | 后端暂无健康的智能体实例，稍后重试 |
| SSE 流意外断开 | 网络中断或故障转移失败，SDK 不自动重连，需业务侧自行重试 |
| 经 Nginx 代理后收不到流式数据 | Nginx 需对 `/chat/stream` 和 `/confirm` 关闭缓冲（`proxy_buffering off`），并将 `proxy_read_timeout` 调大 |
