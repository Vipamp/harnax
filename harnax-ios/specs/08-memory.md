# iOS 实现规格 08：记忆域（智能体记忆 + 会话记忆审批）

本域两件事：一是「智能体记忆」——登录用户自己的每台智能体的长期记忆，列表 + 单智能体详情 + 清除；二是「会话记忆审批」——会话那一层被抽出来形成的合并候选，三臂队列（待审 / 已批准 / 已驳回）+ 详情页的批准与驳回。行为逐条对齐 harnax-webui 现存页面。所有锚点均为仓库内真实读过的行号，格式 `相对路径:行号`；后端与 webui 用仓库根相对路径，iOS 用 `harnax-ios/` 相对路径。后端统一 `ResultVo<T>` 信封 `{code, message, data}`；admin 的 Jackson 3 **丢弃 null 键**（`harnax-admin/src/main/resources/application.yml:25`），因此除注明「必带」外，iOS DTO 一律可选——**键缺席是正常形状，不是错误**。

## 1. 范围与五条取舍

- **入口在「治理」**：智能体 tab 的第四段渲染枢纽（`Sources/HarnaxFeatures/Agents/AgentHomeView.swift:12` 的段定义、`Sources/HarnaxFeatures/Agents/AgentHomeView.swift:59` 的 `GovernanceHomeView(dependencies:)`），tab 栏固定四段（`Sources/HarnaxFeatures/Root/HarnaxTab.swift:6-9`），本域不新起一级。枢纽三行顺序为 会话记忆审批 → 智能体记忆 → 技能晋升（`Sources/HarnaxFeatures/Governance/GovernanceRoute.swift:21-27`），与控制台「优化治理」组同序（`harnax-webui/config/routes.ts:126-133` 排在 `harnax-webui/config/routes.ts:139-146` 之前）。三行各是它所通向那一队列在 App 上的唯一入口，会话域不通向本域任何队列。
- **枢纽按门面建行**：三行来自 `GovernanceRoute.allCases.filter { 对应门面 != nil }`（`Sources/HarnaxFeatures/Governance/GovernanceHomeView.swift:77-85`）。门面没接上的那一臂**整行消失**，而不是留一个点进去白屏的入口。控制台侧没有权限闸门可比：优化组每一行都没有 `access`，「每个登录用户看得见并清得掉自己的记忆」被写成了注释（`harnax-webui/config/routes.ts:139-141`）。
- **列表不分页**：`GET /api/admin/memory` 回的是裸数组，不是 `Page<T>`（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/controller/MemoryController.kt:54`），iOS 因此不给记忆列表挂分页状态机；只有队列侧用 `PagedState`。
- **会话自己那一层永远不读正文**：路由不存在，只有长期层的两条读（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/controller/MemoryController.kt:49`、`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/controller/MemoryController.kt:64`），所以界面上那一层只能以一个整数出现（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/service/impl/MemoryStoreGateway.kt:108`，计数实现 `harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/service/impl/MemoryStoreGateway.kt:468-472`）。文案因此说「还没并入」，不说「等你审批」——驳回并不会带走那一层（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/service/impl/MemoryDraftServiceImpl.kt:320-338`），同一份内容下一轮还会再提。
- **清除只给一句话的代价说明**：对话框必须点名被前缀清扫带走的三样东西（整理稿、全部每日记录、尚未并入的会话记忆），少说一样就是低估这一次删除（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/service/impl/MemoryStoreGateway.kt:153-165`，删除按前缀取全部对象）。
- 不在本域：按会话读记忆正文、批量清除、记忆的编辑写入（写入路由属 `/api/admin/internal/` 前缀，只有 agent-service 用共享密钥调，边界见 `harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/controller/MemoryController.kt:32-35`）。

## 2. 后端契约：七条路由、两个拒绝通道

记忆三条：`GET /api/admin/memory` · `GET /api/admin/memory/{agentId}` · `DELETE /api/admin/memory/{agentId}`（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/controller/MemoryController.kt:42`、`:49`、`:64`、`:83`）。
候选四条：`GET /api/admin/memory-drafts` · `GET /api/admin/memory-drafts/{id}` · `POST .../{id}/approve` · `POST .../{id}/reject`（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/controller/MemoryDraftController.kt:43`、`:51`、`:89`、`:106`、`:124`）。
前缀 `/api/admin`，Bearer + `X-Tenant-ID`，`APIClient` 现有装配即可。这两组都不是内网路径：`InternalApiAuthFilter` 只 gate `/api/admin/internal/` 前缀（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/controller/MemoryController.kt:32-35`），而服务身份在两条链上都被直接拒（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/service/impl/MemoryServiceImpl.kt:99-101`、`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/service/impl/MemoryDraftServiceImpl.kt:500`），共享密钥因此列不出任何人的记忆桶。

| 动作 | 参数 | 响应体 |
|---|---|---|
| 记忆列表 | 无 | `List<MemoryAgentResponse>`，**裸数组** |
| 单智能体记忆 | 路径 `agentId`（运行时名字） | `MemoryDetailResponse`；查无 → 信封 `code:404` |
| 清除 | 路径 `agentId` | `MemoryDeleteResponse{agentId, deletedObjects}` |
| 队列 | `pageNum`=1 · `pageSize`=20 · `status` · `agentName` · `sessionId` | `Page<MemoryDraftResponse>` = `{pageNum,pageSize,total,records}` |
| 候选详情 | 路径 `id` | `MemoryDraftDetailResponse` |
| 批准 | 路径 `id` + body `{expectedDigest}` | `MemoryDraftDecisionResponse` |
| 驳回 | 路径 `id` + body `{reason}` | `MemoryDraftDecisionResponse` |

三条容易照抄错的形状：

1. **队列没有 `/page` 后缀**（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/controller/MemoryDraftController.kt:51`），iOS 前缀落在 `Sources/HarnaxAPI/MemoryDraftEndpoint.swift:12`。记忆侧路径参数 `{agentId}` 绑的是**运行时智能体名字**而不是数据库 id（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/controller/MemoryController.kt:70`、`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/controller/MemoryController.kt:89`），所以必须按单个路径段百分号编码（`Sources/HarnaxAPI/MemoryEndpoint.swift:19`、`Sources/HarnaxAPI/MemoryEndpoint.swift:23` 走 `Endpoint.segment`，实现 `Sources/HarnaxAPI/Transport/Endpoint.swift:99-101`）；带 `/`、`?`、`#` 的名字否则会被读成多一段或一条查询。
2. **默认值全在服务端**：`pageNum` 缺省 1、`pageSize` 缺省 20（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/controller/MemoryDraftController.kt:59`、`:63`，常量 `harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/controller/MemoryDraftController.kt:144`），`status` 缺省 PENDING（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/controller/MemoryDraftController.kt:74`）。iOS 仍恒发 `status`（`Sources/HarnaxAPI/MemoryDraftEndpoint.swift:25-30`），因为不发就永远拿不到已决的两臂；`agentName` 与 `sessionId` 只在有值时上 URL（`Sources/HarnaxAPI/MemoryDraftEndpoint.swift:31-36`）。服务端把页码夹到 `>=1`、页长夹进 `1...1000`（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/service/impl/MemoryDraftServiceImpl.kt:176-177`，上限常量 `harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/service/impl/MemoryDraftServiceImpl.kt:597`）。
3. **「空列表」与「读失败」是两个事实**：一次成功的空列表就是「还没有记忆」，KDoc 写死了这条（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/controller/MemoryController.kt:36-37`）；单智能体读不出来才回错误信封 `code:404` + `message:"No memory for this agent"`（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/controller/MemoryController.kt:73`），iOS 的判据是 `code == 404 && message == APIError.noMemoryMessage`（`Sources/HarnaxCore/Contract/Memory.swift:74`、`Sources/HarnaxCore/Contract/Memory.swift:82-84`）。名字非法是第三种：`BizException("Invalid agent id")` 用默认 400（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/service/impl/MemoryServiceImpl.kt:57-60`、`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/exception/BizException.kt:10-12`），走错误横幅而不是空态。

拒绝分两类，界面处置完全相反：

1. **谁都动不了的拒绝走错误信封**：未知 `status`（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/service/impl/MemoryDraftServiceImpl.kt:173-175`——宁可拒绝也不回空页让人以为「没东西等」）、批准不带 `expectedDigest`（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/service/impl/MemoryDraftServiceImpl.kt:227-229`）、驳回不带理由或理由超长（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/service/impl/MemoryDraftServiceImpl.kt:320`、`:321-323`）、候选不属于这个账号（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/service/impl/MemoryDraftServiceImpl.kt:450` 的 404）、记忆桶不可达（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/service/impl/MemoryDraftServiceImpl.kt:234-236` 的 503）。iOS 一律落到 `APIError.business`（`Sources/HarnaxAPI/Transport/ResponseMapper.swift:22-24`），按错误横幅渲染，界面不再据此自动做任何事。
2. **界面必须据以再动作的拒绝随 HTTP 200 + `code:200` 回来**，判据是 `data.outcome` 而不是状态码：`APPROVED` / `REJECTED` / `DRAFT_CHANGED` / `ALREADY_REVIEWED` / `STALE_BASE`（常量 `harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/dto/MemoryDraftDecisionResponse.kt:68-80`；KDoc `harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/dto/MemoryDraftDecisionResponse.kt:6-17` 逐条说明每种拒绝需要哪个附加字段才可执行，`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/dto/MemoryDraftDecisionResponse.kt:44-45` 声明 `reason` 文案不是契约）。iOS 用带 `.unknown(raw:)` 兜底的枚举接（`Sources/HarnaxCore/Contract/MemoryDraft.swift:151-182`），遇到第六个值时按拒绝呈现并把 token 原样带上屏。
3. **丢写竞态是唯一一个按信封 code 分支的拒绝**：`BizException(409, …)`，两处——某个日子文件在跑动中被改（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/service/impl/MemoryDraftServiceImpl.kt:278`）、长期层在跑动中被改（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/service/impl/MemoryDraftServiceImpl.kt:285`）。两处都把 DB 声明随事务回滚、候选仍是 PENDING，**重读就是修复**；详情 VM 因此在这一支里先落提示再调 `load()`。

批准的门序本身是契约：digest → 桶可达 → 长期层版本 → 每个日子文件版本 → 抢 DB 声明 → 写（日子在前、整理稿在后）→ 清源文件（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/service/impl/MemoryDraftServiceImpl.kt:220-306`，取舍理由见 `harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/service/impl/MemoryDraftServiceImpl.kt:195-219` 的 KDoc）。`alreadyLanded`（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/service/impl/MemoryDraftServiceImpl.kt:246-247`）让「上次写了三层然后丢了桶」的下一次点击把活干完而不是重写一遍，所以 `APPROVED` 有 `approved` 与 `alreadyApplied` 两个工厂（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/dto/MemoryDraftDecisionResponse.kt:82-125`），在 iOS 侧是同一个成功提示，差别只在 `longTermVersion` 是否等于 `baseVersion + 1`。一次批准写 `1 + K` 个对象，K 是候选点名的日子文件数（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/dto/MemoryDraftResponse.kt:96-97` 的 `targets`）。

### 两种时间戳，不许混

`MemoryAgentRow.lastModified` / `MemoryDetail.lastModified` / `MemoryDailyEntry.lastModified` 是**字符串**，由存储层直接给出 `Instant.toString()`，形如 `2026-09-30T08:00:00Z`，取不到存储时间才退回写者嵌在信封里的原串（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/service/impl/MemoryStoreGateway.kt:787-790`）。候选的 `createTime` / `updateTime` / `reviewedAt` 是 Kotlin `LocalDateTime`（`harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/dto/MemoryDraftResponse.kt:40-50`、`:102-112`），序列化不带时区。iOS 因此：**记忆两屏只显示日期部分**（切 `T` 或空格，并要求 `4-2-2` 形状，`Sources/HarnaxFeatures/Memory/MemoryListView.swift:254-260`），因为打印一个不带区的钟点就是把手持机的偏移当成事实；候选屏切的是无区墙钟（`Sources/HarnaxFeatures/MemoryDrafts/MemoryDraftListView.swift:273-291`，切片函数 `Sources/HarnaxFeatures/MemoryDrafts/MemoryDraftListView.swift:317-321` 同时接受空格、`T` 与点号分隔），两者不能共用一个格式化器。`harnax-admin/src/main/resources/application.yml:23` 请求的 `yyyy-MM-dd HH:mm:ss` 与 `harnax-admin/src/main/kotlin/com/agnetix/harnax/admin/config/JacksonConfig.kt:12` 记录的 Jackson 3 ISO 默认并不一致，客户端对两种写法都切片。
