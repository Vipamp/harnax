# Harnax iOS 客户端功能与逻辑说明

这份文档说明 iOS 客户端提供的功能和它的运行逻辑：每一屏能做什么、规则怎么判、失败的时候怎么表现。全文只写功能与逻辑，不涉及实现方式，读者不需要接触代码即可完整了解这款应用的行为。

**阅读约定**

- 规则一律写成「触发条件 → 结果」的形式。
- 文中出现的接口路径只用于说明某项功能依赖哪个服务端动作，例如 POST /api/admin/auth/cli-login，它们不是实现说明。
- 所有数字与阈值（分页条数、等待时长、超时、字段长度上限）都是当前生效值。
- 界面文案以中文原文给出；深色与浅色两档下，功能和规则完全一致，只有配色不同。
- 说明某项功能做不到什么的小节（如 3.18 当前行为边界、5.10 本域的失败口径）写的是行为界限本身：这些位置就是这样设计的，不是待办清单。

## 1. 启动、鉴权与全局规则

本章说明 app 从冷启动到主界面的全部判断分支、登录与凭据的每条规则，以及作用于所有界面的横切逻辑：外观、错误口径、身份边界、本地存储与隐私声明。

### 1.1 启动与身份核对

**冷启动第一步只读本机，不联网。** 启动后读钥匙串里的访问令牌与身份卡，据此判断是否已登录，判断分支如下。

- **钥匙串里没有访问令牌，或令牌为空** → 按未登录处理，直接呈现登录页。
- **有令牌、但没有身份卡** → 按未登录处理，呈现登录页。
- **有令牌、身份卡也在** → 判为已登录，先渲染主界面，随后向服务端核对。
- **有令牌、身份卡读出来了但本机无法解析** → 按未登录处理，需要重新登录才能恢复。
- **钥匙串拒绝这次读取**（返回的是系统错误码，而不是「条目不存在」）→ 这次读取不配给结论；界面停在加载态是死路，所以按未登录落到登录页，等下一次读取再判断。
- **加载中的呈现**：整屏居中一个进度指示，配文案「加载中…」，没有副标题、没有按钮。这一帧只覆盖一次本机读取的时长，不等网络。

**身份核对用的接口是 GET /api/admin/auth/me，三个时机各发一次**：冷启动判为已登录之后、生物识别解锁成功之后、每次打开「我的」页。核对结果决定四件事。

- **答成功**：用服务端的资料重写本机身份卡（用户名、昵称、邮箱、租户编号、管理员标记）。核对答复只给租户编号、不给租户名；若这次给出的租户编号与本机缓存的不是同一个，身份卡上的租户名一律清空，界面上显示「未知租户」。
- **答 401 或 403**：会话就此结束，本地凭据清除，界面切回登录页；已选中的 tab 保持不变，登录回来仍落在同一个 tab。
- **答网络不可达、超时、或服务端 5xx**：不做任何下线动作，也不更新身份卡；本机已判定的登录态继续可用。在隧道里冷启动照样进主界面，只是数据读不到。
- **核对结论落地前**，界面用的是钥匙串里那张身份卡；账号改名、降级、换租户会在下一次核对后被纠正。

### 1.2 登录页

**页面构成**：品牌字标与副标题「智能体管理台」，两个输入项，一个主按钮，底部一个服务器地址入口。

- **用户名**：单行输入，占位文案「用户名」，关闭自动大写与拼写纠正。
- **密码**：安全输入行，占位文案「密码」，密文显示。
- **主按钮**：文案「登 录」；请求在途时文案变为「登录中…」并禁用，重复提交被忽略。
- **服务器入口**：次要按钮「服务器地址设置」，以浮层打开两个基址的编辑页；下方「服务器」横幅显示当前两个地址的主机与端口，形如「管理接口 主机:端口 · 路由接口 主机:端口」，浮层关闭时重新读取一次，不设定时刷新。

**提交条件**：用户名去掉首尾空白后非空，且密码非空；两者缺一律不发出请求，只在字段下方给出「请填写用户名和密码。」。真正发出的登录请求是一次 POST /api/admin/auth/cli-login，请求体只有用户名与密码两项：不带图形验证码字段，也不带自动登录选项。

**失败提示的每一种情况**：失败都以同一条红色横幅呈现，标题固定为「出错了」，正文是下面对应的那句；除注明者外，输入框内容保留不动。

- **用户名或密码为空** → 「请填写用户名和密码。」
- **凭证被服务端拒绝**（业务错误码或 401）→ 优先显示服务端那句话，服务端没给句子时显示「服务器拒绝了本次请求。」
- **设备没有网络**（未联网、连接中途断、主机名解析不到）→ 「当前网络不可用，请检查网络连接。」
- **连不上服务器**（地址已知但连接没建立、证书不被接受、服务没起）→ 「无法连接到服务器，请确认服务已启动。」
- **请求没能发出**（钥匙串拒读、本机读不出可用的服务器地址）→ 「请求未能发出，请稍后重试。」
- **存的地址不成其为地址** → 「服务器地址格式不正确。」
- **请求超时** → 「请求超时，请稍后重试。」
- **等待期内再次提交** → 「尝试次数过多，请 N 秒后再试。」，N 为剩余秒数向上取整
- **失败次数触顶** → 「失败次数过多，请重新输入密码。」，同时清空密码框
- **答复结构与本机约定不符** → 「服务器未返回数据。」
- **答复根本读不出来** → 「无法解析服务器返回内容。」

**登录成功后拿到哪些东西**：一次成功登录带回访问令牌、令牌类型、有效期（总寿命或绝对到期时刻，两种都可能出现）、当前租户编号、该账号可进入的租户列表、账号资料（用户标识、用户名、昵称、头像、邮箱、手机号、性别、管理员标记），以及一把路由接口密钥——这把密钥只有登录这条路径会返回。账号资料会被压成一张身份卡供离线渲染；只有访问令牌非空才算登录成功，令牌为空整次登录按失败处理。

### 1.3 连续失败后的等待策略

**只有被拒的凭证才计入失败次数。** 超时、连不上服务器、请求没能发出、答复读不出来这些情况一次都不计，避免一次网络抖动把用户锁在自己的账号外面。

- **等待时长按 2 的幂次增长**：第 1 次失败后等 1 秒，第 2 次 2 秒，第 3 次 4 秒，第 4 次 8 秒，以此类推，上限 60 秒。
- **计时起点是上一次失败的时刻**；等待期内的提交不发出任何请求，直接把剩余秒数报给用户。
- **连续失败达到 5 次**，规则升一级：不算等待，而是要求重输密码——提示「失败次数过多，请重新输入密码。」，密码框清空，同时整个失败计数归零，重输之后从零开始。
- **恢复条件**：一次成功登录清零；保存服务器地址（无论地址是否真的变了）也清零，因为失败的猜测属于另一套服务。
- **顺序上重输密码优先于等待提示**：两种情况用户都得清空密码框，先报等待会把这件事藏起来。

### 1.4 服务器地址配置

**两个基址**：管理接口与路由接口，成对配置、成对使用；界面上写明「两个地址需指向同一套 Harnax 服务。」

**入口两处**：登录页的「服务器地址设置」按钮（浮层）；「我的」页偏好设置分组里的「服务器地址」行（页面内推送，行上带当前地址摘要）。两处打开的是同一张编辑页，字段一致。

**校验规则**（两个字段各自独立执行，任一不过整次保存不落地）：

- 去掉首尾空白后必须能解析成一个绝对地址，协议只接受 http 与 https。
- 必须有非空主机名；允许带端口，端口原样保留。
- 不接受地址里的账号密码段，也不接受查询串。
- 路径允许保留，末尾斜杠逐个去掉，最终存下的是「协议://主机[:端口][/路径]」这一种规范化结果。
- 任一条不过：字段下方提示「服务器地址格式不正确。」，本机存着的地址不变，也不发出任何网络请求。
- 保存成功后，两个字段回写为规范化后的值（而不是用户敲进去的原文），出现「服务器地址已更新。」，随后出现「确定」按钮用于关掉这一页。

**首启默认值**：本机从没存过地址时，管理接口取 http://172.20.10.2:28080，路由接口取 http://172.20.10.2:28081。

**改动之后对已登录会话的影响**：新地址与已存地址只要有一项不同，旧地址那套服务签发的访问令牌就没有意义了，所以保存动作会连带清除本地凭据（令牌、路由接口密钥、租户编号、身份卡），两个地址本身保留。凭据一清，任何页面上的会话都会立刻切回登录页，已选中的 tab 保持。两个基址按每次请求现取，改动从下一个请求起生效。

**极端情况**：地址已经写进去、本地凭据却没能清除时，整次保存按失败上报，字段下方出现「服务器地址格式不正确。」那句话，界面不会显示「已更新」。

### 1.5 生物识别解锁

**开关位置**：「我的 → 偏好设置」分组里的「启动时解锁」行，副标题写明「下次启动 app 时，先要求生物识别或设备密码，才打开已保存的登录。」。只有这台设备具备本机认证能力（有生物识别且已设设备密码）时这一行才出现；不具备时整行不显示，免得承诺一个下次启动兑现不了的门槛。

**生效时机**：这个开关的值只在启动时被读一次。当场打开或关闭，对本会话没有任何作用，要到下一次冷启动才生效。

**弹出条件**：冷启动时三件事同时成立才立起闸门——开关已打开、设备具备认证能力、钥匙串里读出一个已登录会话。闸门不是叠加在登录表单之上，而是把用户名与密码两个字段连同「登 录」按钮一起盖掉；页面上只剩「使用生物识别解锁」按钮、说明「本机已保存登录凭据，解锁后直接进入。」、一条「改用密码登录」链接，以及底部的服务器地址入口。解锁请求文案为「解锁 Harnax」，接受生物识别，也接受设备密码。

**闸门期间的每一条失败路径**：

- **解锁通过** → 闸门消失，读出本地会话并立刻走一次身份核对；闸门不是身份结论，凭据本身仍要服务端认。
- **用户主动取消系统面板** → 没有任何提示文案，闸门原地保留。
- **用户在系统面板上选了密码入口又放弃** → 没有任何提示文案，闸门原地保留。
- **生物识别或设备密码被拒** → 提示「解锁失败，请改用密码登录。」，闸门保留。
- **设备能力在过程中消失**（生物识别被移除、进入锁定、设备密码被关掉） → 闸门撤掉，提示「这台设备已无法使用生物识别，请改用密码登录。」，此时只剩密码一条路。
- **在闸门上提交空的或不通过的账号密码** → 闸门不解除：只有真正换到凭据的那次提交才算回答闸门。
- **闸门立着时，任何页面重新读取会话**都得到「未登录」的界面结论，钥匙串里的令牌不会被绕过。
- **连续点按解锁按钮只会开一个系统面板**，第二个请求被忽略。

**闸门是门槛不是锁**：密码登录始终可用，凭据始终留在钥匙串里；解锁通过只表示这台设备的使用者现在可以使用它。

### 1.6 主界面信息架构

**底栏四个 tab，从左到右**：对话、智能体、上下文、我的。冷启动进入主界面时落在「智能体」。

- **对话**：会话列表为根，点开一个会话进入对话页。
- **智能体**：顶部一个三分段——智能体、团队、定时任务，默认停在「智能体」。
- **上下文**：顶部一个五分段——模型、工具、MCP、技能、CLI，默认停在「模型」。
- **我的**：账号卡，账户分组里的租户切换，偏好设置（主题、语言、服务器地址、启动时解锁），标题为「管理」的一组入口——参数、API Key 管理、渠道、Token 监控，最后是退出登录。可见条目随身份变化。
- **本账号的永久密钥没有界面入口**：读它与重新生成它的路径仍然存在，但 app 里任何一屏都不显示这把 Key，也不提供重新生成的按钮。

**保持规则**：

- **tab 选择跨得过一次登录打断**：会话中途被服务端判定失效、界面切回登录页时，整个 tab 子树会被丢弃重建，但选中的 tab 记在根上，登录回来仍落在原来那一个。
- **各 tab 内部推送出去的详情页不在这个保证之内**：详情页随子树一起被丢弃，登录回来落在该 tab 的根列表。
- **点「退出登录」是另一种要求**：界面回到「智能体」页，而不是回到当前页。
- **切换租户会让整棵主界面重建**，所有页面按新租户重新读取。
- **分段选择与搜索词不属于保持范围**：离开一个分段再回来，该分段的状态重建、第一页重新拉取。

### 1.7 凭据的存放与会话维持

**存储介质是系统钥匙串**，八个条目各存一格、互不覆写：访问令牌、路由接口密钥、租户编号、令牌到期时刻、令牌总寿命、管理接口地址、路由接口地址、身份卡。前六项属于会话，后两项属于配置；轮换令牌不会重写服务器地址。

**钥匙串条目在设备首次解锁之后即可读取**，因此息屏状态下后台的令牌续期照样拿得到令牌。

**请求怎么带上凭据**：走管理接口的请求都带访问令牌与界面语言，并按本机存的租户编号一并带上租户信息；语言标记每次请求现取，app 内切换语言后下一个请求就用新语言。唯一不带租户信息的例外是团队产物下载，它只凭访问令牌发出，租户由服务端从会话本身读出。走路由接口的请求在本地存了路由密钥时只带这把密钥，既不带访问令牌也不带租户编号，租户由密钥本身决定。

**令牌续期**：

- **主动续期**：每次带令牌的请求发出前先看剩余有效期，低于总寿命的三分之一就先换新令牌再发；本机只存了绝对到期时刻、没有总寿命时按 60 秒余量兜底；没有到期记录的一律视为该续期。
- **被动续期**：带令牌的请求收到 401，先续一次令牌再把原请求重放一次。
- **什么情况算会话真的死了**：只有服务端明确说「这个凭证无效」——续期请求本身答 401，或续期后重放仍答 401——才清除本地凭据。续期请求超时、地址不可达、服务端 5xx，原因原样报回界面，不做下线。
- **不参与续期的请求**：登录、登出、令牌刷新本身。登出即便答 401 也不会引发第二次登出，也不会用一个新令牌去撤销用户刚扔掉的那个。
- **持有路由密钥的那条腿不参与续期重放**：永久密钥不过期，它换来 401 说明密钥本身被拒，换个更新的访问令牌也改变不了什么。

**退出登录做了什么**：「我的」页底部「退出登录」是红色样式按钮，点了先弹确认框「退出当前设备的登录状态？」，两个选项：确认按钮同样写着「退出登录」，另一个是「取消」。确认后：界面立刻切为未登录并回到「智能体」页，闸门与解锁失败提示一并清掉；随后在令牌还在钥匙串里的时候发出 POST /api/admin/auth/logout 让服务端吊销它；服务端答什么都一样——本地凭据一律清除，两个服务器地址保留。第二次点退出不会发出任何请求，因为已经没有令牌可带。

### 1.8 全局横切规则

**深色与浅色两档**：外观三档可选——跟随系统、浅色、深色，在「我的」的偏好设置里由「主题」一行左描述右下拉选定，选中即刻生效、无需重启；这一行右边显示的就是当前档位。

- **界面里没有硬编码颜色**：所有颜色都是语义位（底色、卡面、备选卡面、分隔线、主文字、次文字、辅助文字、品牌色、品牌上的文字、成功、警告、危险等），同一个语义位在浅档与深档各有一个取值，绘制时按当前生效的那一档取色。
- **「跟随系统」不写覆盖值**，由设备外观决定；选「浅色」或「深色」时把窗口的界面样式固定下来，固定到窗口层意味着系统控件与桥接颜色一起走这一档。
- **浅档对过淡的颜色做了压暗处理**，保证这些颜色承载文字时达到对比度下限 4.5:1；深档对应位置整体提亮。两档各自成表，组件允许使用的颜色组合逐条列举并逐条校验，新用法要先进这张表。
- **语言同样即时生效**：可选跟随系统、English、简体中文；语言决定界面全部文案，也决定下一个请求携带的语言标记，服务端返回的句子按这个语言给。
- **头像由显示名生成**：拉丁名取首词与次词的首字母（最多两字母并大写），中文名取第一个字，空名落一个圆点；底色从六个语义色里按名字稳定取值，同一个名字每次同一颜色。账号资料里的头像地址不参与这一步。

**实体列表的工具栏只有一种长相**：名称搜索留在搜索框里，其余条件一律收进右上角的一枚漏斗，新增实体是同一角落的加号，加号在左、漏斗在右。两枚都排在导航栏尾部，因为前导角落是返回按钮的位置，推到那一级详情页上就会撞车。漏斗在没有任何条件生效时是空心、任一条件生效时是实心；菜单里的当前项打勾。状态一类的筛选不进列表本身：跟在行里的那条控件会跟着行一起消失，一旦筛到零条，能把筛选撤销的东西就不在屏上了。

**错误呈现的统一口径**：任何一处失败都归到下面几种长相，句子来自全 app 共用的文案表。

- **未登录**：句子「登录已过期，请重新登录。」，同时本地凭据被清除、界面切回登录页；服务端答 401 与答 403 在这里算同一件事，都按会话事件处理，而不是当成一句话展示。
- **对象不存在**：列表读到零条时是全平台同一个空态——图标加「暂无内容」，副标题「有数据后下拉刷新即可查看。」，列表页确实支持下拉重读。产物这类依赖对象存储的内容，服务端答「这条路径没注册」时单独成型，提示「服务器未开启对象存储，产物无法下载。」，并按空态呈现、给出「重新加载」；单个文件确实不存在或不属于当前会话时，那只是普通业务错误。
- **调用没走通**：一次请求在拿到答复之前失败的几种情况各有各的句子，绝不共用一句——设备没有网络「当前网络不可用，请检查网络连接。」、连不上服务器「无法连接到服务器，请确认服务已启动。」、请求没能发出「请求未能发出，请稍后重试。」、这一请求被自己的界面取消「请求已中断，请重新加载。」（读被取消时这句不出现，见下面第二条）、请求超时「请求超时，请稍后重试。」。五种都不导致下线；确实没有网络时身份卡照样显示，界面不闪回登录页。服务端答了零条不属于这里任何一种，那是上面那条空态。
- **下拉刷新不改屏上的东西**：一次重读不许把正在被下拉的那张卡换成整屏转圈——刷新控件本身就是进度，换卡等于把下拉所挂的那层拆掉。只有从没答过的首屏才显示整屏转圈，而那时它本来就在转。所以下拉之后，有行还是有行，空态还是空态。
- **没人等的回答不写结论**：一次读取被取消（读的人已经不在了）时界面什么都不改——不变红、不出横幅、不立错误句，屏上留的还是取消之前的样子。这类取消在写入那一类失败里才会说话。
- **业务错误**：服务端给了句子就原样显示那句话，没给就显示「服务器拒绝了本次请求。」；服务端句子实际只随请求语言给出中文或英文两种。
- **呈现载体**：页面内联的是一条带图标的横幅；整屏没有内容时是居中的三态视图，可带「重试」；读失败但行还在屏上时，原因写在行旁边而不是把行换成一句错误。有具体原因时，那一层通用套话不出现。

**租户与管理员身份的影响**：

- **管理员标记来自服务端核对**，在「我的」页账号卡上以徽标显示「管理员」或「成员」。
- **每条管理列表上的编辑与删除按同一规则开放**：管理员可以动任意一条；非管理员只能动创建者是自己那一条；一条数据没写创建者时对非管理员不可操作。数据是否公开不参与这条判断。
- **「公开」开关单独一条规则**：管理员和新建时可以任意设置；非管理员只能把自己那条私有的数据改公开，已经公开的回不去私有，别人创建的一律不能改。
- **「我的」里管理分组的条目随身份增减**：管理员看到参数、API Key 管理、渠道、Token 监控四项；非管理员看不到 API Key 管理这一项，其余三项照常。
- **密钥表单里的租户字段只对管理员出现**。
- **租户切换是常驻一行，左描述右下拉**：这一行在「我的」的账户分组里，无论账号能进几个租户都显示；能进两个以上时下拉可以打开，选中的名字即当前租户，选另一项当场切换，只有一个租户时这一行照样摆着但下拉不给开。下拉里只列带有租户编号的行，编号是唯一发出去的东西。
- **租户列表读失败单独成一条提示「租户列表读取失败」**，不会退化成「这个账号只有一个租户」而把这一行空掉；读不到可选行时这一行只显示租户名（名字缺失显示「未知租户」），没有下拉。
- **请求归属哪个租户由钥匙串里那个租户编号决定**，切换成功后先落盘再算成功；落盘失败时整次切换报失败，界面上仍是原来的租户。

**隐私与本地能力声明**：

- **隐私清单**：不追踪、追踪域名列表为空、采集数据类型列表为空；唯一申报的需要理由的系统能力是应用偏好存储，理由代码为「仅本 app 使用」。没有接入任何第三方服务组件。
- **相机用途说明**：随安装包声明一句，用途限定为给消息拍照。
- **本地能力清单**：钥匙串（存凭据与服务器地址）、系统生物识别与设备密码认证（启动解锁）、系统相机与系统相册选择器（对话里附图）、短时后台任务（离开前台时兜住正在流式返回的回答，系统额度用尽后这一轮按真实状态收尾）、仅竖屏显示。
- **明文访问**：安装包允许对配置的服务器地址使用明文 http 连接，以支持自建与局域网部署。
- **偏好存储里只有三项**：外观档、语言档、「启动时解锁」开关；凭据与服务器地址一律走钥匙串。
- **每次请求携带的语言标记**由 app 内语言决定，只可能是中文或英文两种。

## 2. 智能体、团队与会话管理

### 2.1 页面入口与分段

**底部页签的固定顺序。** 界面底部依次为「对话」「智能体」「上下文」「我的」四个页签；冷启动落在「智能体」，退出登录后也把页签重置回「智能体」。登录状态不是已认证时整棵页签树不出现；登录成功后按当前租户建树，切换租户会重建导航树，因此切租户时正在浏览的详情弹窗不会被保留。

**智能体页签内部分三段。** 顶部段选为「智能体」「团队」「定时任务」；离开某一段时那一段的状态持有者被丢弃，回到这一段后关键词与状态筛选都回到初始值，需要重新输入。

**资源条目不在这个页签里。** 模型、工具、MCP、技能、CLI 五种资源在「上下文」页签的五个分段里管理，与本章的三块内容不共用页面。

### 2.2 智能体列表

**搜索。** 顶部搜索框提示「搜索智能体」；停止输入 500 毫秒后发出一次查询，连续输入期间不发请求，结果替换整份列表并回到第一页。

**筛选与新建。** 右上角两枚，加号在左、漏斗在右。加号点开向导的新建模式；漏斗给三项：「全部」「启用」「停用」，当前项打勾，选中项变化后立即重读第一页，图标在未筛选时是空心、筛选后是实心。

**分页规则。** 每页 20 条；滚动到最后一行时请求下一页，列表底部显示「加载中…」；能不能继续翻页取决于已取回条数是否小于接口报回的总数，达到总数后停止请求。

**追加页失败。** 列表内容不清空，顶部出现红色「出错了」横幅并写明服务器原话；页码保持不动，下一次滚动重试同一页。

**下拉刷新。** 手势下拉重读第一页；刷新期间到达的追加请求会被记住并在刷新落地后补发一次；同一时刻只有一次刷新在路上，后到的回答以最后一次为准，过期的回答不得改写行数据、总数与页码。

**空态与失败态分开。** 接口成功返回零条时显示整页空态，带关键词或筛选时文案是「没有符合条件的智能体」，否则是「暂无智能体」；一条数据都没有且首次读取就失败时显示整页错误态，附服务器原话与「重试」；已有数据在屏上时，后续任何失败都只是顶部横幅。

**没有排序能力。** 列表上既没有排序控件，也不向分页接口传排序参数，可见顺序完全由接口给回的顺序决定。

### 2.3 智能体卡片与统计下钻

**卡片的可见内容。** 自上而下是头像、名称行、描述、彩色标记行、副信息行；名称只占一行且超出截断，名称右侧紧跟「启用」或「停用」徽章，该智能体对租户公开时再追加「公开」标记。

**副信息行的组成。** 依次拼接创建者、月-日、会话数三段，用「·」分隔；接口没给创建者或时间时对应段落整段省略；时间只保留月-日，格式解析不出来时省略；会话数只在大于 0 时出现「N 个会话」。

**标记行的内容与出现条件。** 依次是「模型 <名称>」「工具 N」「技能 N」「MCP N」「CLI N」；模型名为空时不出现模型标记，四个计数为 0 的维度各自不出现；五种标记一个都不成立时整行不渲染。

**标记行就是下钻入口。** 点击整行标记区打开以该智能体名称为标题的面板；面板内容全部来自这一行本身已经带回的关联项与会话清单，不需要第二次请求。段落顺序固定为「工具」「MCP 服务」「技能」「CLI 包」「会话」，某一段没有数据时整段不出现，不留空段落。

**名称取用规则。** 工具在中文界面按中文名、显示名、代码名依次取第一个非空值，在英文界面按显示名、代码名；三个名字列都为空时退成「工具 #<编号>」，连编号也没有时退成「未命名」；MCP、技能、CLI 名称缺失时同样退成「未命名」；会话行的标题依次退成会话名、「会话 #<编号>」、会话字符串标识、「未命名」。

**行内附加标记只在数据存在时出现。** 工具行按需追加「需确认」和「N 个参数」；MCP 行按环境参数个数追加「N 个参数」；技能行把所属仓库名作为标记；CLI 行追加包版本号与参数个数，描述缺失时用包内技能名以「·」拼接填进副行。

**卡片菜单能发起的操作。** 右上角「更多操作」依次是启用停用、「编辑」、「刷新关联会话」、删除；编辑与删除两项只有当前账号是管理员或该智能体的创建者时才出现在菜单里，启用停用与刷新关联会话对所有能看到列表的人都出现；这一行有写请求在路上时菜单图标变成沙漏且启用停用项禁用。

### 2.4 智能体表单向导

**总步数与步骤名称。** 共五步：「基本信息」「工具配置」「MCP 配置」「技能配置」「CLI 配置」；新建时标题为「创建智能体」，编辑时为「编辑智能体」。

**必填范围的判定。** 只有第一步必填，其余四步的提示句自带「（可选，可跳过）」并在底部提供「跳过」；最后一步的提交按钮在新建时是「完成」、在编辑时是「保存」，保存期间换成「保存中…」并禁用，且最后一步不显示「跳过」。

**步骤芯片可以自由跳转。** 顶部芯片点击即切换且不触发校验；被离开的步骤保留它上次被拒绝的内容，进入的步骤立刻显示属于它的拒绝；芯片配色区分当前步骤、仍有未解决项的步骤、已经通过校验的靠前步骤。

**候选数据按步骤懒加载。** 每一步的候选清单只在第一次进入该步时读取一次，来回走不重复请求；某一步候选读取失败时该区域显示错误状态与「重新加载」，这是这份清单唯一的重试出口。

**第一步收集的字段。** 智能体名称、描述、系统提示词、模型、所有者、是否公开；前三项是文本框，模型与所有者是行式控件，是否公开是开关。

**第一步的拒绝句子与阈值。** 依次为「请输入智能体名称」「智能体名称不能超过 100 个字符」「请输入描述」「请输入系统提示词」「请选择模型」；长度按字符的编码单元数计，与后端口径一致。

**模型候选的口径。** 一次读取 100 条模型，只保留处于启用状态的对话类型模型；模型行显示名称、服务商与价格，服务商缺失时写「未知服务商」，名称缺失时写「未命名模型」。

**保存回来的模型已经取不到时的处理。** 这一行仍显示在页面上方，名称后追加一句灰色说明指出该模型已停用、已删除或已不是对话模型，并用警示色标记；带说明的模型不进可选清单，避免一次点了等于没点的选择。

**模型能力不足时的整块降级。** 当前模型不支持工具调用时，工具步骤顶部出现「当前模型不支持工具调用，可切换支持的模型或直接跳过此步骤」，整块变暗且点击无效但内容仍可读；不支持 MCP 服务时同样处理，句子是「当前模型不支持 MCP 服务，可切换支持的模型或直接跳过此步骤」。

**所有者行与是否公开行。** 所有者只读并带锁形图标，新建时显示「自动填充为当前用户」，编辑时显示接口带回的所有者，两种模式下都不可点。是否公开在管理员或新建场景可以改，普通创建者只在当前为私有时可以改；其余情况开关禁用并在行下方显示「您没有权限修改此设置」，该行的说明句为「公开后其他用户也可以查看此智能体」。

**四类关联行的空行与重复规则。** 未选择的行被拒绝时分别给出「请选择工具，或删除这一空行」「请选择 MCP 服务，或删除这一空行」「请选择技能，或删除这一空行」；重复添加时分别给出「同一工具不能重复添加」「同一 MCP 服务不能重复添加」「同一技能不能重复添加」。

**技能的重复判定有两层。** 编号与别的行相同给「同一技能不能重复添加」；编号不同但名称与别的行相撞给「技能 <名称> 已经添加过了」。

**技能行的两步依赖。** 一行必须先选技能仓库再选技能；未选仓库时技能行禁用并半透明，选中仓库后才读取该仓库的技能清单；别的行已经选中的技能不出现在这一行的可选清单里。

**CLI 行的唯一性与状态保留。** 同一个包只能添加一次，可选包全部被占用后「添加 CLI」置灰不可用；每行的填写内容以包编号为键保存，删掉某行再重新添加同一个包时，上一次填过的环境参数会回来。

**必填环境参数的检查。** 一行被拒绝时报「<名称> 缺少必填环境参数 <参数名>」；判定“已填”的口径分维度：工具行即使声明了默认值也不算已填，MCP 行与 CLI 行把默认值算作已填。

**删除行的边界。** 工具可以减到零行；MCP 的最后一行不显示删除入口，只能用行内的「清除」把内容清空；技能的最后一行点删除是原地清空而不是减少行数；CLI 行可以任意删。

**保存前的整表复核与重入保护。** 在最后一步点提交会重新跑完所有步骤的校验；发现问题时跳到第一个有问题的步骤，并把该步骤的句子显示在红色横幅里；同一步骤内相同句子只显示一次；某一步通过不会让另一步的问题消音。上一次保存还在路上时再次点提交，界面显示警告横幅「已有保存在进行中」，并且不发出第二个请求。

**新建与编辑在提交内容上的差异。** 新建额外带上“启用”这一状态，编辑不发送任何状态字段，因此不会因为保存表单而把停用中的智能体启用；技能清单每次都按屏幕上的行顺序整表提交；CLI 只提交确实填了值的参数行；请求中某字段缺失表示“保持服务器已有内容”，提交空列表表示“清空”。

**保存成功后的界面走向。** 新建成功后直接关闭向导并让列表重读；编辑成功后先打开「刷新关联会话」面板，面板关闭时向导才随之关闭并触发列表重读，因为已存在的会话还带着保存时的原配置快照。

### 2.5 关联行内的环境参数编辑

**两种取值来源二选一。** 每个声明出来的参数行顶部是「引用变量」与「自定义」两个分段；切换分段会立即清空另一侧的内容，因此请求里不会同时带上变量编号与手填文本。

**引用模式的显示。** 选中变量后行下显示服务器给出的该变量当前值；敏感变量前带锁形图标且显示的是脱敏文本；引用的编号已落在可选清单之外时绑定保留，值的位置改成「不显示该变量的值」。

**自定义模式的显示。** 输入框直接承载文本，声明为敏感的参数使用密文输入框。

**默认值提示与必填口径同在一行。** 一行既没引用也没填值、且该维度确实会把声明里的默认值带进运行时（MCP 与 CLI）时，显示灰字「包内默认值：<值>」，工具维度不显示这行，因为它的默认值不会到达运行时；判定口径是引用一个非零变量编号即算已填，自定义文本必须去掉首尾空白后非空才算已填。

### 2.6 团队的列表、卡片与详情

**与智能体同一套列表骨架。** 搜索提示为「搜索团队」，右上角同样是加号在左、漏斗在右那两枚，筛选同样三项，分页同样每页 20 条、500 毫秒防抖、追加失败只出横幅，空态分「暂无团队」与「没有符合条件的团队」两句，同样没有排序控件。

**卡片标记行与副信息行的差异。** 标记行依次是「主管模型 <名称>」「成员 N」「主管技能 N」；只要存在已停用或已删除的成员或技能，额外出现红色标记「N 项引用失效」，计数是失效成员数与失效技能数之和。副信息行只有创建者与月-日两段，团队卡片不展示会话数。

**下钻面板只有两段。** 顺序为「成员」「主管技能」；成员名缺失时退成「智能体 #<编号>」，技能名缺失时退成「技能 #<编号>」；带失效结论的成员或技能行追加「已删除或已停用」徽章。

**主管自身的配置挂在团队这一行上。** 主管的模型与系统提示词是团队数据本身的列，不来自任何智能体；未选择主管模型时按“没有主管模型”展示，模型名称读不到时以「#<编号>」占位。

**卡片菜单没有权限前置。** 启用停用、「编辑」、「刷新关联会话」、删除四项对所有能看到列表的人都出现，这是团队与智能体在入口权限上唯一的行为差异。

### 2.7 团队表单：主管与成员

**总步数与步骤名称。** 共三步：「基本信息」「主管技能」「成员智能体」；标题新建时为「新建团队」，编辑时为「编辑团队」。

**必填范围。** 新建副标题直接写明「共三步：基本信息、主管技能、成员智能体；只有基本信息必填。」；只有「主管技能」这一步底部出现「跳过」，成员步骤不能跳过。

**编辑副标题是一句提醒。** 内容为已经运行中的团队会话会继续使用保存时的主管与成员配置，直到操作者主动刷新它们；这句提醒解释了为什么编辑成功后必然弹出刷新面板。

**第一步收集五件事。** 团队名称、团队描述、系统提示词、主管模型、是否公开；描述与提示词是多行输入框，前者折到 4 行、后者折到 9 行，两者都带独立字段名。这个表单没有所有者行，创建时由服务端把当前账号记为归属人；是否公开开关不受角色限制，也没有权限提示句，说明句为「设为公开后，其他用户可查看该团队」。

**基本信息层的五条拒绝句子。** 「请输入团队名称」「团队名称长度不能超过 100 个字符」「请输入团队描述」「请输入主管系统提示词」「请选择主管模型」。

**输入侧截断与校验侧拒绝并存。** 团队描述与每条委派说明在输入框处就按编码单元数截断，从编辑数据带回的超长值由校验句子拒绝，所以截断是输入止损而不是规则本身。

**主管技能步骤的口径。** 同样是先选仓库再选技能的成对行，别的行已选中的技能不出现在可选清单；这一步没有任何顺序把手；清空仓库会把整行清空；最后一行的删除按钮是原地清空而不是减行；接口带回的技能已经没有时保留其名称并追加灰色说明。

**成员步骤收集什么。** 每行是一个成员智能体加一条委派说明；行标题为「成员 #<序号>」；提示句为「该主管可以委派的智能体，至少需要一个，顺序会保留。」；委派说明的占位句为「选填；留空则沿用该智能体自身的描述」。

**成员候选的三段口径。** 初始候选是启用中智能体的前 200 条；步骤上的搜索框在停止输入 300 毫秒后按关键词读取 50 条并替换可选范围，关键词清空时回到初始候选；这次搜索读取失败时同样回到初始候选，而不是把可选清单变空。

**成员重复靠拒绝而不是隐藏。** 可选清单不会因为某个智能体已被别的行使用而把它摘掉，重复由行级校验拒绝。

**成员层的四条拒绝句子。** 「至少需要一个成员智能体」「请选择成员智能体」「同一智能体不能重复添加」「委派说明长度不能超过 500 个字符」。

**成员行可以调序，也可以删到只剩一行。** 每行有上移下移把手；只剩一行时删除图标消失，保证始终有一个可选择的入口；成员的智能体已停用或已删除时保留名称并追加灰色说明。

**主管模型引用失效时的差异。** 该模型会列在可选清单的第一位但不可点选，页面上方的模型行保留其名称并追加说明；这与智能体向导里“完全不出现在可选清单”的做法不同。

**整表复核的顺序。** 依次检查主管技能、基本信息、成员智能体，并跳到第一个有问题的步骤，因此同时缺技能与缺成员时先落在技能步骤。

**提交内容的差异。** 主管技能用集合语义判断：编辑时只有技能集合发生变化才带上这个字段，集合相同则整个字段缺席；空集合表示主管不挂任何技能；新建时总是带上技能；委派说明留空时该字段在请求中不出现；新建带启用状态，编辑不带。

**保存成功后的界面走向。** 新建成功直接关闭并重读列表；编辑成功先打开刷新面板，面板关闭后向导才关闭并重读列表；重入保护句为「已有保存在进行」。

### 2.8 启用、停用与删除

**谁能按这个按钮。** 智能体的启用停用不校验角色，编辑与删除要求管理员或创建者；团队的四个操作都不校验角色；会话的写入只要求这一行带有编号，包括别人共享给本租户的会话。

**启停发出的请求。** 智能体走 PUT /api/admin/agents/toggle/<编号>，团队走 PUT /api/admin/teams/toggle/<编号>，状态用查询参数以 0 或 1 表达。

**界面先把行切过去。** 点击后行上的徽章立刻反映新状态；请求被拒时把这一行显示回滚成服务器最后告知的值，并在列表上方显示红色横幅写明拒绝原话；请求期间该行菜单图标为沙漏且启停项禁用。

**智能体删除的确认与被拒。** 弹出确认层，标题「确认删除该智能体？」，破坏性按钮「删除 <名称>」，说明「删除后不可恢复，其会话与工具、技能绑定会一并移除。」，另一侧只有「取消」；确认后发出 DELETE /api/admin/agents/<编号>，成功时移掉该行并把总数减一，被拒时该行留在列表里不被移走，顶部横幅显示服务器原话。智能体的删除不做任何前置校验。

**团队删除是两步动作。** 点「删除」先向 GET /api/admin/teams/<编号>/related-sessions 取关联会话清单，菜单项此时显示「校验中…」并禁用；拿到回答后才弹确认层，标题「确认删除该团队？」。

**确认层的说明句按数量二选一。** 存在绑定会话时为「仍有 N 个会话绑定该团队，删除会被拒绝；请先删除这些会话。」，不存在时为「当前没有会话绑定该团队，删除可以正常执行。」。

**校验本身失败时不弹确认。** 只显示「关联会话列表加载失败，请重试」，删除流程停在菜单，不会发出删除请求。

**校验通过也可能被拒。** 校验到删除之间状态会变，此时接口把原话交回，横幅显示其中内容，句子里最多点名五个会话标识。

### 2.9 关联会话与「刷新受影响会话」

**什么时候需要刷新。** 智能体或团队保存后，已存在的会话带着保存时的配置快照，不刷新就一直按那份快照运行；面板也可以从卡片菜单「刷新关联会话」主动打开；CLI 包停用后用的也是这一个面板。

**面板顶部说明按来源分三句。** 智能体为「智能体「X」已保存。勾选的会话立即应用新配置，未勾选的将在约 30 分钟内自动生效。」；团队那句改说新的主管与成员；CLI 那句改说新包。三句都明确未勾选的会话约 30 分钟后自动生效。

**清单从哪读。** 打开即读该对象的关联会话列表，走 GET /api/admin/agents/<编号>/related-sessions 或 teams 下的同名路径，CLI 用自己的对应路径。

**面板的四种状态。** 「加载中…」；回答为空时显示「没有关联会话」；有数据时进入可勾选列表；读取失败时是错误状态，附服务器原话与重试，绝不显示成“没有会话依赖它”。

**每行显示什么。** 「渠道」或「会话」标记、显示名（没有真名时直接用标识本身）、归属人标记；标题确实是真名时才额外显示截到 24 字符的标识；所有条目默认勾选。

**一个都不勾时主按钮变成跳过。** 按钮文案从「刷新所选（N）」变为「跳过」，点它不发出任何请求，面板按已完成处理。

**提交是逐条判定。** 走 POST /api/admin/agents/refresh-sessions 或团队对应路径，回答里每个会话有自己的结论；全部成功时汇总为「已刷新 N 个会话」并自动关闭面板；存在失败时汇总为「N 个已刷新，M 个失败」，面板留在屏上、所有行的勾选状态锁定、每个失败行下方各自显示自己的原因。

**整体失败与逐条失败分开呈现，退出有两个口。** 整体回答非成功时在面板顶部显示「出错了」横幅，不写任何成功汇总；面板不会把带失败的一批报成干净。头部「取消」与底部「稍后处理」都直接关闭面板且不发请求，已经保存成功的智能体或团队不会因此回滚。

### 2.10 会话列表

**列表的真实范围。** 内容来自分页接口在租户内的可见性过滤：本租户内公开的会话加上本人创建的会话；界面不做二次过滤，因此这里可能看到别人共享的会话。

**顺序与筛选。** 服务端固定按创建时间倒序返回（最新的在最前），界面上没有排序控件；右上角的漏斗同样是三项状态筛选，加号排在它左边，搜索提示「搜索会话」，同样 500 毫秒防抖、每页 20 条。

**卡片的可见内容。** 头像取执行者名或标题；标题最多两行；徽章行只在“已停用”“是团队会话”“是公开”三者之一成立时出现，内容依次是「停用」「团队」「公开」；标题下依次是会话说明、执行者行「执行者：X」、标记行「模型 X」「技能 N」「MCP N」、以及整行等宽展示的会话字符串标识。

**打开聊天窗口的条件。** 标题下的内容区只有在该行带字符串标识时才可点，点击进入以该标识寻址的聊天窗口；没有标识的行内容区是静态文本。

**卡片菜单的七项。** 「会话详情」「工作区」「团队产物」「重命名」「启用」或「停用」「清空消息」「删除」；工作区项只在接入工作区读取能力且该行带字符串标识时出现；团队产物项只在团队会话且接入产物能力时出现，单智能体会话永远没有这一项；删除项只在可写时出现。

**各项的禁用条件。** 重命名与启用停用在该行没有编号时禁用，启用停用还在此行有写请求在路上时禁用；清空消息在没有字符串标识或有请求在路上时禁用；菜单图标在请求期间显示沙漏。

**空态与失败态。** 「还没有会话」与「没有符合条件的会话」按是否带关键词或筛选二选一；整页首次失败给错误态与「重试」；已有数据时的刷新或追加失败只出顶部横幅。

**重命名能改什么，改成之后怎么显示。** 只有标题；小表标题「重命名会话」，提示句「这里只改会话标题。」，保存按钮在保存期间显示「保存中…」；拒绝句为「请填写标题。」与「标题不能超过 100 个字符。」，两条都在本机判定，因为这条更新接口不会执行字段校验，只有数据库列宽会硬性拒绝。成功后这一行立即显示新标题，靠本地覆盖而不是回读，因为更新接口没有回答体；列表被重新读取时以接口值为准。

**清空消息走的是命令通道。** 确认层标题「清空这个会话的历史消息？」，破坏性按钮「清空「X」」，说明「会话本身仍留在列表里，只是丢掉它的历史消息。」；成功后运行端自己给的那句话原样显示在绿色横幅里，横幅标题为「历史消息已清空」；运行端明确表示拒绝时显示其原话或「运行端拒绝清空这个会话。」；接受但没给说明时显示「运行端已接受命令，但没有返回说明。」。

**删除的确认与拒绝。** 确认层标题「删除这个会话？」，说明「它的消息和团队产物会一并删除，而且无法恢复。」；被拒时列表上方横幅原样转述接口给出的阻碍说明，行不消失。

### 2.11 新建会话与重名检查

**入口与字段。** 只有装配了创建能力的宿主才在列表右上角显示加号按钮，点击打开标题为「新建会话」的表单，这是本应用创建会话的唯一途径。三个字段：标题必填且最长 100 个字符，描述可选且界面侧上限 500，执行者从「智能体」「团队」两组共用一个下拉里二选一；标题下的说明原文为「标题必填，最长 100 个字符。重名检查是全平台范围的，命中的可能是别的租户的会话。」，描述旁实时显示「已输入 N 个字符，最多 500」，执行者旁为「智能体与团队二选一，会话只运行在你选中的那一个上。」。

**执行者选项的写法与两组独立读取。** 每条选项为「名称 - 描述」，描述缺失时只有名称；两组分别独立读取，两组回答落地前下拉区显示「加载中…」，标题框不受影响可以直接输入。

**一组读不到时怎么提示。** 黄色横幅标题「执行者列表不完整」，正文为「<组名> 没能载入，仍可以从另一组里选择。」；两组都读不到时同一条横幅转为红色；读取失败那一行右侧另有「重试」。

**重名检查的触发与口径。** 走 GET /api/admin/sessions/check-title，停止输入 300 毫秒后查询一次；标题为空或超过 100 个字符时不查询；任何编辑都会把结论退回未检查状态；回答落地时若文本已被改动则该次回答作废；检查范围是全平台的，命中的可能是别的租户的会话，所以文案只说名字被占用而不声称本账号已有同名会话。

**结论的五种显示。** 未检查时不显示结论行；「正在检查标题是否可用…」（沙漏图标）；「标题可以用。」（绿色对勾）；「这个标题已经被占用，请换一个。」（红色）；检查失败时以警示色显示服务器原话（问号图标）。

**提交闸门。** 字段合法、执行者来源可用、标题结论为“可以用”、没有保存进行中，四个条件同时成立才允许提交；检查失败与还在检查都阻塞提交，不会猜测名字可用。

**拒绝的先后顺序。** 两组执行者都读不到 → 字段规则（「请填写会话标题。」「会话标题不能超过 100 个字符。」「会话描述不能超过 500 个字符。」「请选择一个执行者。」）→ 来源整体不可用 → 标题结论问题（被占用给占用句，还在检查给「标题还在检查，请稍等片刻再创建。」，检查失败给原话）→ 没有可点的执行者；所有拒绝都保留已输入的内容。

**创建成功后的行为。** 创建接口不回答新会话的标识，因此不跳转：表单关闭、列表重读，新会话按创建时间出现在最前。

### 2.12 会话详情面板与可修改项

**面板清单。** 弹窗标题「会话详情」，八个面板依次是「基本信息」「执行者」（团队会话这一格的名字是「团队主管」）、「工具」「外部服务」「技能」「CLI 包」「团队成员」，最后是「对话配置」；没有数据的面板整段不出现。

**基本信息的内容。** 会话标识以等宽整行显示并带复制按钮，另有标题、会话说明、公开状态、归属人、创建人、创建时间；任何一个字段没有值时该行不出现，不显示占位符；全部字段都没有时整页显示「这一行没有可展示的信息」。所有内容之后靠右显示「更新时间：<接口给的时间>」，这是这一行最后写入时间的唯一可见处。

**执行者面板的内容。** 名称（智能体名称或主管名称）、说明、模型、模型价格（形如「¥1.2/M」）、系统提示词；提示词默认折成四行，用「展开」与「收起」切换整段可见性。

**三个面板依赖一次执行者读取。** 「工具」「CLI 包」「团队成员」只存在于执行者自己的行里，弹窗打开时按会话指向读一次 GET /api/admin/agents/<编号> 或 GET /api/admin/teams/<编号>；这次读取回答前三个面板不出现，只有一条「正在读取执行者的工具与成员…」；被拒时三个面板继续缺席，把服务器原话与「重试」显示在面板区下方，不会给出“这个会话没有绑定工具”这类误读。

**「团队成员」只属于团队会话。** 单智能体会话的执行者回答里没有成员维度，这个面板因此永远不出现；「技能」面板不需要等这次读取，会话快照自带的技能清单会直接渲染。

**没有读取能力时的降级。** 宿主没接执行者读取时，弹窗只展示会话自身能回答的面板，也不显示任何说明行。

**「失效」标记的来源有限。** 只有团队回答会逐个说明成员与主管技能是否还在，此时对应行带红色「失效」徽章；会话快照与智能体回答都不携带可用性结论，因此「基本信息」「外部服务」「技能」在单智能体会话下不出现失效徽章。

**唯一可改的面板是对话配置。** 四项：「深度思考」「联网搜索」「开启计划」「权限模式」；权限模式的五个可选项原文为「默认（危险工具需确认）」「自动执行（无需确认）」「接受编辑（自动批准文件操作）」「探索模式（只读）」「禁止执行（自动拒绝危险工具）」。

**编辑入口出现的三个条件。** 装配了配置写能力、该行带有字符串标识、且会话处于启用状态；三者缺一时面板只读、开关灰显且没有「编辑」按钮；会话处于停用状态时要先在卡片菜单里启用。

**开关可用性的判定。** 模型不支持深度思考时该行灰显并附「该模型不支持深度思考。」；模型被设定为强制思考时灰显并附「该模型要求深度思考，无法关闭。」，且开关位置显示为开；模型不支持联网时附「该模型不支持联网搜索。」；开启计划不受任何模型能力限制。

**保存只带改动项。** 请求体永远写全四个键，未改动的键显式写空值以表达“保持原值”；没有改动任何一项时保存按钮不可点，绕过按钮的调用会收到「没有需要保存的修改。」。

**保存后的读回与界面锁定。** 配置接口没有回答体，成功后再读一次该行并显示「配置已保存。」；写入成功但读回失败时把值就地应用并显示「配置已保存，但未能读回最新值。」；写入被拒时草稿保留在屏上，已输入的内容不丢。保存进行中不允许下滑关闭弹窗，取消按钮禁用，同一时间的第二次保存请求被忽略。

**列表何时跟着重读。** 详情弹窗关闭时，只有在确实写过东西的情况下列表才重读一次；只读不写不会引起列表刷新。

### 2.13 顺序与排序

**列表本身不可排序。** 智能体、团队、会话三张列表都没有排序控件，也不传排序参数；会话顺序由服务端按创建时间倒序固定，另两者的顺序由分页接口的返回顺序决定。

**能调的顺序只有两处。** 智能体向导的工具、MCP、技能、CLI 四类行，团队向导的成员行，每行右侧有上移与下移箭头；条目只有一份时整对把手不出现，首行的上移与末行的下移为禁用；行控件同时为读屏提供「上移」「下移」两个动作。

**顺序在保存那一刻落地。** 提交数组的先后就是存储的先后，关联关系在保存时按提交顺序重建、读取时按存储编号回读，因此调序不需要专门接口，也不会单独发起写请求。

**顺序在写入前只是界面状态。** 关闭向导而不保存，调过的顺序不留痕迹；保存失败时顺序同样不落盘。

**主管技能步骤有意不给把手。** 这个字段用集合内容判断是否变化，集合相同就整个字段不提交，纯调序会被判定为没有改动并在下一次读取时回到存储结果；把顺序做成可见且可持久需要改动提交口径，这一步因此直接不提供调序入口。

## 3. 对话（聊天）

本章写清对话域在 iPhone 上的实际行为：一次对话怎么开始、历史从哪里来、回答怎么一页页长出来、输入区能做什么、快捷命令有哪些、危险工具怎么审批、以及离开页面或网络断掉时正在跑的那一轮会怎样。每条规则都写成「触发条件 → 结果」。

### 3.1 进入对话与首屏

**入口只有一个。** 会话列表每张卡片的信息区域整体是一个按钮，点击后用该行的字符串会话标识打开对话页。同一卡片右上角菜单里的「会话详情」「工作区」「团队产物」「重命名」「启用」「停用」「清空消息」「删除」都不进入对话。智能体、团队、定时任务等页面只列出关联的会话供查看，没有任何一条通向对话页的跳转。

**缺字符串标识的行进不去。** 一行没有可直接寻址的字符串标识时，信息区域渲染为静态文字，点击不产生任何响应；此时卡片菜单照常可用，只是对话入口不存在。

**打开对话页固定触发五件事：绑定会话、读取历史消息、读取该会话的对话配置、读取沙箱状态、读取上下文占用。** 五件事各自独立：历史读取失败不会跳过配置读取，配置读取失败也不会让已经画出来的气泡消失，占用读不到只是标题栏少一枚芯片（见 3.16）。

**首屏只可能是三种状态之一。** 没有任何气泡且历史读取进行中时显示加载状态；没有气泡且历史读取失败时显示带原因的错误状态并给出重试；没有气泡且该会话确实没有消息时显示「发一条消息，开始这个会话。」。三者互不冒充：读取失败不会被画成「这个会话没有消息」。

**三种首屏状态下输入框都可用。** 历史读取失败不会锁住发送，可以在一条历史都没有的情况下直接发新消息；错误状态里的重试只重新读取历史，不会碰输入框里已经写好的文字。

**换会话就重置。** 对话页换到另一个会话标识时，先中止上一次的读取再绑定新会话；气泡、输入草稿、已选图片、三个能力开关、权限模式、计划面板与工作区面板全部按新会话重建，中断提示与历史失败提示同时清空。

### 3.2 历史回放

**一次读全，没有分页。** 历史通过 GET /api/router/agent/chat/history/{sessionId} 一次返回整个会话的记录，接口没有分页参数，对话页也不会翻页；记录条数越多，首屏等待越长。

**顺序完全按接口返回。** 客户端不对记录排序，也不按时间戳调整位置：数组里是什么顺序，气泡就是什么顺序。

**连续的多条助手记录合成一个回答气泡。** 同一次运行留下的多条助手记录会聚合进一个气泡，气泡内部按记录顺序排成思考段、工具卡片、正文段；每条助手气泡尾部有该轮的时间（只有时分）与「正在回答」标记。

**没有内容的一轮不画气泡。** 一轮的正文、思考、工具卡片全为空时，屏幕上不出现空容器。

**系统记录与工具记录只作为归属依据。** 记录角色分为用户、助手、系统、工具四种：只有用户与助手记录变成气泡，系统记录与孤立出现的工具记录不产生任何行；工具结果通过它所属的那次调用显示在对应卡片里。

**图片不入历史。** 发送时附的图片只存在于内存里；重新进入会话时，用户气泡只有文字，那一轮当次附过的图片不会回放出来。

**读取与发送撞车时以发送为准。** 历史还在读取时用户发起了新的一轮，本次读到的记录会被丢弃且会话不算已加载，屏幕保留新对话；此时错误状态里的重试按钮还能再读一次。

### 3.3 气泡与排版

**用户气泡靠右、助手气泡靠左。** 用户气泡用强调底色、右下角收角；助手气泡用浮层底色、左下角收角，内部再嵌代码块与工具卡片时层次也分得清。

**长按气泡复制正文。** 助手气泡长按出现的复制项只提供该轮的文字段落，思考内容与工具参数、工具结果不在复制范围内；工具卡片、参数块、结果块各自有独立的复制项。

**正文不可选中，代码可选中。** 助手气泡的普通文字段不提供系统级选中拖动，代码块与工具参数、结果块提供选中；复制整段文字依靠长按菜单。

**一条回答由多段拼成。** 同一个助手气泡内按到达顺序排列：思考过程、若干工具卡片、正文段、若干产物行、若干确认面板；一段正文之后出现工具调用，工具结束后继续写的文字接着写进同一个气泡。

### 3.4 助手气泡支持的 Markdown

**这是一套手写的 CommonMark 加表格扩展子集。** 支持：1 到 6 级标题（含只用一行等号或减号的下划线式写法）、有序与无序列表并可嵌套、任务勾选框、围栏代码块（两种围栏字符都认）、引用（可嵌套）、管道表格（含列对齐）、分割线、粗体、斜体、删除线、行内代码。

**未闭合的围栏取到消息末尾。** 回答只写了开头的围栏却没有收尾围栏时，从该行到整条消息结束都按代码块渲染，不会退化成普通文字。

**四空格缩进不算代码块。** 用缩进表示代码的写法按普通段落渲染，只有围栏形式才得到代码块外观。

**不认识的语法原样显示。** HTML 标签、引用式链接、脚注这类语法不做解析，写成什么就在气泡里显示什么，不会报错也不会吞掉内容。

**链接只认三种协议。** 只有 http、https、mailto 协议的链接变成可点击样式，其余协议按普通文字呈现；链接在解析时校验一次，点击前再校验一次。

**远程图片只显示替代文字。** 回答里的图片链接不会去网络取图，只显示图片的替代文字。

### 3.5 流式输出的节奏

**回答走 POST /api/router/agent/chat/stream。** 请求体一次发出，服务端按帧推回八类内容：正文增量、思考增量、工具调用开始、工具结果、工具确认请求、本轮结束、本轮失败、保活心跳。

**正文增量按显示帧合并。** 一段回答的第一个增量立即上屏；此后到达的增量在窗口里累积，每显示帧（约 1/60 秒）一次性落到气泡里，因此快速打字机效果不会被逐字符刷新拖慢。

**状态类帧先结算窗口再应用。** 工具调用开始、工具结果、工具确认请求、本轮结束、本轮失败这五类帧到达时，窗口里累积的增量先写进气泡，再应用该帧带来的结构变化；屏幕不会把上一条回答的残留增量折进下一条。

**保活心跳不产生任何界面变化。** 心跳帧既不渲染内容，也不结束本轮；本轮只由本轮结束或本轮失败帧结束。

**无法解析的帧被跳过。** 单帧内容不完整或字段无法识别时忽略该帧，读取继续，本轮不会因为一帧坏掉而判定结束或失败。

**本轮结束携带文件清单。** 本轮结束帧带着这一轮产生的文件列表；收到后气泡停止打字状态，文件以产物行出现在气泡尾部，同时重新询问一次沙箱状态。

### 3.6 思考过程与工具卡片

**思考过程是气泡内的可折叠段。** 有思考增量到达时出现「思考过程」区块，标题行可开合；正文开始时思考段已经停在原位，不会挤掉文字。

**工具调用渲染成状态卡片。** 每次调用一行卡片，标题为工具名，状态依次是「执行中」「待确认」「已完成」「失败」「已中断」，另有「已确认」「已拒绝」结论徽标；卡片可展开查看「参数」「结果」「失败输出」三块，参数按稳定顺序展示。

**折叠时机固定。** 卡片在调用开始时出现并显示「执行中」；结果帧到达时换成完成或失败；本轮结束时还没有收到结果的卡片一律标为「已中断」；思考类与计划类调用不产生卡片。

**空增量不打开段落。** 正文或思考的增量内容为空时不会创建一个新的空段。

### 3.7 团队会话

**成员的话有独立气泡。** 主管把任务委派给成员后，成员运行的每一帧按成员运行标识归到各自气泡；成员气泡插在主管气泡之上，形状与主管一致但在左边缘有一条竖向色带标明这是被委派的一轮。

**归属只认运行标识的连续性。** 同一成员运行标识的帧进同一气泡；标识变化即开新气泡；实时流与历史回放使用同一套判定，因此回放出来的成员划分与当时直播一致。

**成员气泡头部显示归属与状态。** 头部一行是成员名称与状态文字：「正在执行」「等待确认」「已完成」「已失败」；下方是任务描述，超过 48 个字符处截断，可展开看全文。

**成员的运行结束只关自己的气泡。** 成员的结束或失败帧只把该成员气泡收口并写状态，主管的气泡与输入框的可发送状态由主管自己的帧决定；主管那一轮还在读取时输入框保持不可发送。

**成员气泡默认在运行时展开。** 运行进行中自动展开，运行结束后自动收起；用户手动点开或收起过一次之后，以用户的选择为准。

### 3.8 计划卡

**开关与出现条件。** 「开启计划」开关打开后，本轮出现打开计划的工具调用时，对话流里内联出现「执行计划」卡，同时自动打开计划抽屉；开关关闭或宿主没有接入计划读取能力时，卡片不出现，工具调用也不会因此失败。

**轮询只在四个条件同时成立时进行。** 计划开关为开、卡片处于展开状态、存在未结束的计划、有人正在看这张卡，四者同时满足时每 2 秒读一次当前计划；任一条件不成立即刻停止轮询。

**内容重复不会重写卡片。** 连续两次读到完全相同的计划时，第二次不产生任何界面改动，流里不会多出重复卡片。

**计划历史只在打开与手动刷新时读。** 抽屉里的「历史计划」在抽屉打开时读一次，之后仅由「刷新」按钮再读；新读到的记录按标识增量插到列表头部，已经存在的条目就地更新而不重复。

**卡片内容与状态。** 计划卡展示「当前计划」「子任务」「描述」「预期结果」「实际结果」「创建时间」「耗时」，子任务状态为「待处理」「进行中」「已完成」「已放弃」；有未结束计划时显示「实时更新中」，没有时按开关状态显示「暂无当前计划」或「打开「启用计划」后，智能体会自动创建计划。」。

**计划结束时气泡断开。** 本轮出现计划结束的调用结果时，计划阶段终止、轮询停止，气泡在此处断开，之后的文字写进一个新的助手气泡。

**失败但有内容时不清空。** 计划读取失败而卡片已有内容时，卡片保留并就地显示一条失败说明；抽屉关闭只收起界面、不清数据，切回前台时按开关状态恢复轮询。

### 3.9 输入区与发送条件

**输入框按需长高，最多半屏。** 输入框从 2 行起随内容增长，上限是屏幕高度的一半再减去 20 点的上下内边距（至少 2 行；屏幕尺寸尚未测得时按 6 行）；超过上限后内部滚动，不会把回答挤到看不见的地方。

**发送按钮的可用条件。** 当前没有正在读取的回答，且（去掉空白后正文非空，或者已附上至少一张图片）时，发送可用；只有图片没有文字同样可以发送。

**回答进行中按钮变成停止。** 一轮开始读取后，发送按钮位置换成「停止」，占位文案换成「正在回答…」，此时按发送不会有第二条消息排队。

**清空与回填的时机。** 发送成功后输入框立即清空、图片条一并清空；快捷命令行只带走文字，已选图片留在条上。读取在第一个帧到达前就失败、且此刻输入框为空时，那条消息的文字与图片被放回框内；用户已经在框里写了新内容则不覆盖。

**芯片行的顺序与状态。** 输入框上方一行依次是「图片」「深度思考」「联网搜索」「开启计划」「权限模式」「停止沙箱」「清空记录」，横向可滑。前四项按模型能力灰显但保持可点，点击给出一句说明；「停止沙箱」「清空记录」在本轮读取期间灰显且点击无效。

**提示横幅。** 芯片被拒、命令失败、图片超限等说明以「提示」横幅出现在芯片行上方，点横幅即收起；它不遮挡已发送的消息。

**回到底部按钮。** 上滑离开尾部超过 120 点后出现圆形向下箭头按钮，无障碍标签为「回到底部」；回到尾部附近自动消失。新内容到达时只有在用户正处于尾部才会自动跟随。

### 3.10 图片输入

**只有本机数据能作为附件。** 附件以 base64 数据串形式写在请求体里，指向远程地址的图片链接一律无效；不是数据串的内容被丢弃并提示「只能附加图片，其余内容已忽略」。

**取图先问来源。** 点「图片」后出现「图片从哪里来？」询问，选项为「相册」「拍照」；选相册进入系统图片选择器（只列图片类型），选拍照进入系统相机。

**两道闸门。** 当前模型不支持图片时，相册与拍照都在闸门处被拒，提示「当前模型不支持图片输入」，选择器不打开；模型支持但本机没有相机时，拍照一行给出「这台设备没有相机，请改从相册选择」，相册照常可用。已经选好的图片在模型切换为不支持图片后照样能发送。

**字节上限按整条消息算。** 一次请求体上限为 1,048,576 字节，其中附件可用 983,040 字节（留出 65,536 字节给正文与信封）；附件按选中顺序逐张计量，装得下的入条，装不下的丢弃并提示「图片太大，一条消息放不下，未附上。」，不会因为一张超限丢掉整批。数量本身没有上限，限制只在字节。

**拍照的两次压缩。** 拍摄的原图先按长边 1600 像素、质量 0.8 压成 JPEG 计量；还是超过附件额度时再按长边 1024 像素、质量 0.6 压一次；两次都超限的图交给上一条规则拒绝，不会静默发送。

**类型从字节头判断。** 相册图片的类型按文件头识别为 PNG、JPEG、GIF、BMP、WebP 之一，识别不出时按 PNG 提交。

**删除。** 图片条上每张图都有移除项，文案为「移除图片」，删除只影响尚未发送的附件。

### 3.11 快捷命令

**解析规则。** 正文去掉首尾空白后以「/」开头才可能被认作命令；「/」之后先去掉空白，命令名到第一个空格或第一个冒号处切断，取较早出现的那个，因此「/permission bypass」与「/permission:bypass」是同一条命令；命令名大小写不敏感，其后的参数原样去掉首尾空白传递；整行只有「/」或只有空白时按普通消息处理。

**认识的九个命令词。** interrupt、stop、clear、compact、approve、stop-sandbox、enable、disable、permission；其中 stop 与 interrupt 指向同一个中断动作。

**不认识的命令词按消息发送。** 「/hello there」这类不在表面上的行不报错，直接作为普通消息发给模型，走完整流式回答。

**命令走独立通道。** 命中的命令以数据提交到 POST /api/router/agent/command，一次请求一次应答，不建立流；用户输入的那一行本身成为一条用户气泡，应答作为一条助手侧说明行写在它后面，应答内容是服务端给出的句子，服务端没说话时成功显示「已完成」、失败显示「命令未执行」。

**需要二次确认的两个命令。** clear 先弹确认，标题「清空这个会话的历史消息？」，按钮为「清空「会话标题」」；stop-sandbox 先读一次沙箱状态：读不到时提示「无法确认沙箱状态」且不弹确认，状态不是运行中时提示「该会话的沙箱未在运行」，同样不弹确认；确认后才提交。其余命令直接发出。

**确认被取消时不留痕。** 二次确认里选择取消，不发送任何请求，输入框里那一行命令文字保持原样。

**能力开关是同一通道的另一用法。** 「深度思考」「联网搜索」「开启计划」三个芯片分别提交 enable 或 disable 加能力名 thinking、search、plan；提交前界面先把开关拨到新状态，服务端答「不」或请求失败时拨回原样并给出说明；不支持深度思考的模型给出「当前模型不支持深度思考」，被要求必须思考的模型给出「当前模型必须深度思考，无法关闭」，不支持联网的模型给出「当前模型不支持联网搜索」。

**权限模式同通道。** 权限菜单选择后提交 permission 加模式名；同样的先拨后回逻辑。模式名为「默认（危险工具需确认）」「自动执行（无需确认）」「接受编辑（自动批准文件操作）」「探索模式（只读）」「禁止执行（自动拒绝危险工具）」。菜单提交的是服务端认可的大写名称；手打「/permission bypass」时参数按输入原样送出，写成小写会被服务端拒绝。

**定时任务会话锁权限。** 会话标识以 task- 开头时，权限菜单不出现，换成一枚带锁的灰显芯片显示当前模式，点击提示「定时任务的会话不能修改权限模式」。

**命令通道缺失时的说明。** 命令通道未接入的主机上点任何命令，一律提示「命令通道尚未接入，无法执行」，不发出请求。

### 3.12 工具确认

**面板出现条件。** 流里到达工具确认请求时，在对应气泡内出现标题为「等待确认」的黄色面板；那一轮暂停期间输入框保持不可发送。

**每一行是一个工具。** 每行显示工具名、风险徽标「低危」或「高危」、参数摘要，行右侧是选择菜单：「允许执行」（默认）、「总是允许」、「拒绝」。

**批量入口在标题行。** 非成员运行时，面板标题行右侧有批量菜单：「全部批准」「全部总是允许」「全部拒绝」；面板底部固定一句「这一轮已暂停，等你决定这些工具能不能执行。」和一个「确定」按钮，无论几行都只有这一个提交入口。

**成员运行按整轮作答。** 待确认的工具属于某个成员运行时，标题行不出现批量菜单，底部多一句「成员运行按整轮批准或拒绝，不按单个工具。」，提交时带上被暂停的那个成员运行标识。

**提交形态两种。** 所有行选同一个答案且不含「总是允许」时，一次提交整轮结论；各行答案不同或含「总是允许」时，逐工具提交，每个工具带自己的结论与是否长期放行。

**答完就地变结论。** 提交后面板立即落定，每行右侧的选择菜单换成结论徽标「已批准」「已设为总是允许」「已拒绝」；应答本身作为恢复后的新一轮读取，后续帧继续写进同一个气泡，运行再次卡在确认上时面板下方出现新的待确认块。

**送不出去时退回待答。** 应答没有送达（请求失败或一条帧都没收到）时，面板重新回到可选择状态，保留用户已做的选择，并给出「确认提交失败：…」的失败横幅。

**没答就结束算中断。** 本轮以其他方式结束时，未被作答的确认块停止提供选择，卡片状态标为「已中断」；用户发起新一轮会丢弃上一轮遗留的选择。

**只读展示形态。** 应答通道缺失时，面板只显示工具内容与一句说明，不提供任何提交入口，避免出现点了必然失败的按钮。

### 3.13 中断

**停止按钮是一等动作。** 回答进行中点「停止」：立刻取消本机读取、归还系统后台时间、把窗口里最后一段未上屏的文字先落到气泡里，再把本轮标为已中断；同时向命令通道提交一次中断，让服务端停止计费。

**停止保留已显示的内容。** 中断不会删除已经出现的所有文字与工具卡片，未完成的工具卡片标为「已中断」；中断也不回填输入框，因为那一条消息服务端已经收到。

**输入框在停止后恢复可用。** 中断后发送按钮恢复为「发送」，占位文案恢复为「想问点什么…」。

### 3.14 会话配置

**对话页的配置来自一次读取。** 打开对话页时按字符串会话标识读取该会话的四个配置列：深度思考、联网搜索、开启计划、权限模式，外加模型侧的三个能力位（是否支持图片、是否支持推理、推理是否强制）；接口没有返回能力列时按「支持」处理，配置列缺失时按关闭处理。

**会话详情里的配置编辑。** 会话详情面板的「对话配置」区可编辑同样的四项，可编辑需要三个条件同时成立：该主机具备配置写入通道、这一行有字符串会话标识、该会话处于启用状态；任一不成立时只显示值，不给编辑入口。

**编辑时开关的可用性。** 深度思考开关在模型不支持推理时不可拨并说明「该模型不支持深度思考。」，被强制推理时不可拨并说明「该模型要求深度思考，无法关闭。」；联网搜索在模型不支持时不可拨并说明「该模型不支持联网搜索。」；开启计划与权限模式不设模型门槛，进入编辑即可动。

**只提交差量。** 保存只写实际改动过的项，未改的不进请求体；一个字段都没改时提示「没有需要保存的修改。」并直接返回。写入路径 GET /api/admin/sessions/{sessionId}/config 与 PUT /api/admin/sessions/{sessionId}/config，写接口不返回内容，因此写成功后立刻读回一次：读回成功提示「配置已保存。」并以读回值显示，读回失败提示「配置已保存，但未能读回最新值。」，写入失败时草稿留在屏幕上并显示服务端原因；上一次写入还在途中时再点保存不会有第二次请求。

**改完的影响范围。** 配置改动只作用于这一个会话；详情面板写过内容，关闭面板时会话列表重新读一次当前页。

### 3.15 工作区与产物

**工作区入口只在沙箱运行时出现。** 对话页工具栏的工作区按钮只有当沙箱状态读取明确回答「运行中」时才出现，本轮结束时重新问一次；读取失败按「没有入口」处理，不显示错误。

**抽屉先问状态再列目录。** 打开工作区先读沙箱状态：只有运行中才请求根目录列表，未运行或状态读不到时显示「该会话没有运行中的沙箱」并且完全不请求文件列表；根目录是 /workspace，面包屑从它的名字起。

**列表规则。** 目录在前、同类按名称排序；每行显示名称，非目录行附带类型与大小，类型分为「文件」「目录」「链接」「未知」；点目录进入下一级，点上层级面包屑或向上按钮回到上一级，向上按钮在根目录不出现；路径只在列表成功后才写入，被拒绝的跳转留下原来的行与面包屑。

**预览。** 点文件把内容读进列表下方的预览块；读取失败的句子直接写在预览块里，旁边的列表照常可看；服务端截断时预览块右上角显示「内容被截断」；空文件显示「（空文件）」；进入新目录时上一份预览被丢弃。

**下载只走分享。** 工作区文件、消息气泡里的产物行、团队产物抽屉的行，下载一律把字节交给系统分享面板，应用自己的存储里不留文件；成功后给出「已分享 文件名」。

**上传。** 工作区工具栏的上传按钮只在沙箱运行时可用，一次选一个文档，写入当前所在目录，成功后重新读一次当前列表并以「已上传 文件名」提示；本机打不开选中的文件时提示「无法读取所选文件，请重试」，在选择器里点取消不提示任何内容。

**失败分两种形状。** 列表已经有一屏行时，失败只在顶部横幅里说明，行不消失；一行都没有时整个抽屉变成错误状态并给出重试。下拉刷新与「刷新」都是再读一遍：已知沙箱在运行时只重读当前目录，其余情况从状态读取到根目录列表整趟重走。

**产物行。** 本轮结束带来的文件在气泡尾部成为一行：文件名加大小，右侧下载按钮；具备产物下载通道时才出现下载入口，否则该行只显示名称与大小。产物取不到时有两种含义（文件不存在、该部署未开启对象存储），界面按传输给出的那句显示，未开启对象存储的文案是「服务器未开启对象存储，产物无法下载。」。

**团队产物抽屉。** 入口只在「这一行是团队会话且有字符串标识」时出现在会话卡片菜单；列表一次返回全部、按发布时间新到旧，没有搜索、排序与分页；行内容为名称、类型与大小、8 位短引用（长按复制完整标识）与「发布于 时间」；没有产物时显示「还没有成员发布产物」，对象存储未开启时显示「服务器未开启对象存储，产物无法下载。」，两者是不同的状态。

### 3.16 上下文占用与压缩

**标题栏一枚只读芯片。** 对话页标题栏显示「上下文占用」，正面只有两个信息：一个百分比，和它的口径（账单／估算）。点开是一份五行明细：上次调用输入（账单）、本地估算、上下文消息数、模型窗口（连同这个分母从哪一档来）、自动压缩阈值。这枚芯片只报告，不改动上下文的任何部分。

**读数只有一个来源。** GET /api/router/agent/context/{sessionId}，由会话路由器转发到当前持有这个会话的实例。进入会话读一次，本轮结束时再读一次；读取正常结束与读取抛错都算本轮结束。

**报不出来的两种形状整块不显示。** 这个会话从未绑定过实例时，服务端回一句成功但什么内容都不带；绑定的实例此刻不持有这个会话时，服务端回业务失败。两种情况标题栏都不出现这枚芯片，绝不显示「0%」——读不到，和上下文是空的，是两件事。

**百分比跟的是最近一次已计费的调用。** 会话还没有过一次模型调用时按本地估算显示，口径写作「估算」；有过一次调用之后按账单显示，口径写作「账单」。因为分子是「上一次调用实际花掉的输入」，点一次压缩不会当场把百分比降下来，要等下一轮结束后的那次重读才动。

**分母来路写在标签上。** 三档：模型配置、上游表、兜底值。出现这一版没有名字的新档位时按服务端原词显示，不借用「兜底值」的说法。

**到达自动压缩阈值时芯片转为警示色。** 到了那个点上，下一轮无论有没有人去按都会压缩一次。

**压缩入口在输入区芯片行。** 名称「压缩上下文」，排在权限模式之后、停沙箱与清空之前，不需要二次确认；读屏在芯片名之后补一句「把较早的轮次在模型上下文里归纳成摘要；聊天页仍然显示全部原始消息。」回答进行中芯片变灰、不响应。

**点按与手敲是同一条命令。** 都提交到 POST /api/router/agent/command，一次请求一次应答，不建立流；手敲时可以带一个参数，是一个可选的正整数（保留多少 token），写成非数字就按服务端默认。

**应答的四句话。** 压成时说「已压缩上下文：N 条 → M 条」，应答没带计数时只说「已压缩上下文」；没有可压的内容时说「当前会话还太短，不需要压缩」；被服务端拒绝时显示服务端原话——定时任务会话、团队成员自身的会话、本轮正在应答这三种各有自己的句子，原话读不到时是「压缩失败」。点按的应答以横幅出现，压成和「还太短」用平静色、被拒用警示色；手敲的应答作为一行助手说明写进气泡。

**成败只认成功旗标。** 一条应答没有带成功旗标就被读成失败并给警示横幅：命令通道承诺这个字段一定在，读不到旗标等于没读到命令体，这种情况绝不说「已压缩上下文」。

**压缩只改模型上下文，不改画面。** 屏幕上的气泡全部来自逐条追加的会话记录，压缩之后仍然显示全部原始消息，也不会多出一条摘要气泡。

**停止一次压缩的应答后仍然补读。** 取消丢掉的是横幅与气泡；这条命令已经在服务端跑过，占用数字照旧重读一次。

**重叠的读取只有最后一次询问算数。** 同时问了几次时，先问的那次即使后回来也直接丢掉；答复落地时若已经切到别的会话，同样丢掉——旧会话的数字不会挂到新会话的标题下。

**读数被写坏时显示数字而不是退出。** 分母异常导致百分比大得超出可表示范围时，芯片显示一个钳到上限的数字。

### 3.17 离开页面、后台与网络异常

**离开页面即结束本轮的读取。** 对话页消失或换到别的会话时，先中止读取再收起界面，计划的轮询与抽屉一并停止；服务端那一轮继续跑，但客户端不会重连，回到同一会话也接不上那条流，只能靠重新读取历史看已落库的部分。

**切到后台靠系统给的宽限时间兜住。** 每条打开的流独占一份后台时间许可；宽限期内回答到达即正常结束并归还许可；许可被系统收回时按用户停止处理（中止并补发中断命令），同时提示「系统收回了后台时间，回答还没有到达，这一轮已中断，请重新发送。」

**流关闭但没有结束帧算中断。** 读取正常结束却没收到本轮结束时，气泡标为已中断；若这一帧内容都没到达，另外给出「还没收到任何内容，连接就断了。」的警告条。

**第一个帧到达前抛错算失败。** 请求在流建立前抛出（网络不可用、超时、被拒绝等）时，本轮标为已中断，出现标题为「回答已中断」的红色横幅，正文为传输给出的那句；输入框此刻为空则把那条消息还回去。

**服务端错误帧。** 收到本轮失败帧时，横幅正文写成「智能体返回错误：〈服务端句子〉」，服务端没给句子时用统一的业务失败说明「服务器拒绝了本次请求。」。

**登录过期只在发流前兜一次。** 请求在流建立前收到 401 时，先刷新访问令牌再重试一次；再次失败则交由全局登录状态处理，对话页不弹这句话。

**超时口径。** 单条流式请求 180 秒内没有任何数据即判定超时，同一条请求最长 2100 秒；服务端把无输出的流静默切断时，表现与流关闭没有结束帧那种中断状态相同。

### 3.18 当前行为边界

**历史一次读全。** 长会话的首屏等待取决于记录条数，界面没有分段读取入口。

**图片不入历史。** 回放里用户气泡只有文字，附件无法在重进会话后查看。

**不重连。** 离开页面、切后台超时、网络断开这三种情况下，进行中的一轮都不会自动接回，需要重新发送。

**Markdown 是子集。** HTML、脚注、引用式链接、缩进代码不解析；远程图片不取；正文不可逐字选中，只能整段复制。

**命令应答是纯文本行。** 命令通道返回的句子不做 Markdown 渲染，也不带工具卡片。

**字节上限先于数量上限。** 附件限制只有一个：整条消息的字节预算 983,040 字节；单张大图经两次压缩还是超限时被拒绝。

**成员归属只认运行标识。** 没有成员运行标识的帧一律归主管；成员气泡的开合以用户点击为准，运行结束时的自动收起只在用户没有手动操作过时生效。

**权限与开关的作用面。** 三个能力开关与权限模式写在会话配置列上，只影响这一个会话；定时任务会话不接受权限改动。

**下载不落盘。** 所有文件出口都是系统分享面板，应用内没有文件管理界面，也没有「保存到本机」的中间状态。

## 4. 上下文：模型、工具、MCP、技能、CLI 与环境变量

**本章范围**：模型厂商与模型、内置工具、MCP 服务、技能来源与技能、CLI 包、环境变量这六类可被智能体与团队绑定的资源，以及它们被引用之后的失效标记。全部内容按设备上当前的界面与判定规则描述。

**共同规矩**：六类资源的列表屏共用一套动作口径，各类只在字段与门控上有差别。

- **进入即重读**：上下文是一排分段切换，默认落在「模型」。一段只在被选中时才建、离开即销毁，因此搜索词不跨段保留，每次回来都重读第一页。
- **关键词等待 500 毫秒**：停止输入 500 毫秒后才发一次请求；连续输入只会留下一笔在途读。
- **同一时刻只允许一笔刷新**：刷新在途时再次触发（下拉、按钮、改筛选都算）会被记下，本轮落地后立刻补跑一次；最后到达的那笔答案才拥有行、页码与总数，被顶掉的旧答案不得改写其中任何一项。
- **翻页与追加**：滚到最后一行才要下一页；追加在途时若正好有刷新在跑，追加被记下、刷新结束后补发。追加失败时保留已有行与页码，下一次滚动重试同一页，不重置列表。
- **开关先落屏再核实**：启停开关立刻改状态、把该行标为写入中；写被拒时状态弹回，服务端的原话显示在列表上方的红色横幅里。
- **有行的报错与没行的报错分两式**：已有行在上、刷新失败时只在顶部挂一条横幅；屏幕上一行都没有时才让整屏进入错误态。筛选后为空与从来没有数据是两句话。
- **被拒绝要说人话**：服务端以业务码非成功回的拒绝，界面原样显示那一句，绝不折算成网络错误。
- **重试与刷新同路**：整屏错误态与空态都自带重试动作，重试走与下拉刷新完全相同的一笔读，不另开一条捷径。
- **横幅的寿命**：列表上方的行内横幅在下一次刷新成功时被清掉；写入被拒留下的那一句会一直留在屏幕上，直到被读过、或列表被重新拉过。
- **五段的固定顺序**：模型、工具、MCP、技能、CLI，各段的标题与图标由这五段自己的配置给出；环境变量不在这排分段里，它在「我的」的管理分组里。
- **每页条数**：厂商每页 8 张，模型、MCP 服务、技能来源、技能表、CLI 包、环境变量各每页 20 条；这些数字是屏自己的取数口径，界面上没有任何地方可以让操作者改它。
- **搜索提示语写明搜什么**：依次为「搜索厂商」「搜索模型」「搜索工具名称或描述」「搜索 MCP 服务」「搜索来源」「搜索技能」「搜索 CLI 名称」「搜索 Key 或描述」，提示语与后端真正的匹配范围一致。

### 4.1 模型

- **两级结构**：第一级是厂商卡片列表，点某张卡进入第二级、也就是那一家厂商名下的模型列表；模型永远挂在某个厂商之下，界面上没有跨厂商的模型总表。
- **厂商卡每行显示**：厂商名称、厂商类型标签、描述（没有则「暂无描述」）、密钥掩码行、创建者与创建时间、三个统计（共 N 个模型 / N 个启用 / N 个停用），以及启用或停用徽标。
- **统计另读一次**：卡片可见时逐个读该厂商的统计，每页落地后再并发补读一轮；读不到时该行写「仅本人创建的厂商可见模型统计。」，绝不显示成零，因为共享给他人的厂商这一路本就不给数。
- **厂商类型标签**：认识的类型给中文名（阿里云百炼、OpenAI、Ollama）；不认识的类型直接显示存下来的原值，原值也没有时写「未知类型」，同时头像配色退回默认档。
- **厂商列表的条件**：只有关键词（按厂商名匹配）与状态筛选两项，没有类型筛选，也没有价格条件。
- **厂商分页**：每页 8 张卡。
- **厂商表单字段**：厂商名称、厂商类型、基础地址、API 密钥、描述，共五项。类型只在新建时可选，编辑时该控件灰着不可动。
- **厂商字段上限**：名称 100 字，描述 500 字，密钥 500 字，基础地址 500 字且必须像一个完整地址；地址留空表示不改动，提交时这一位整个不发。
- **密钥的保密口径**：密钥栏永远从空白开始，旁边写明「当前已存密钥 sk-****abcd，留空表示不修改。」掩码形如前缀加四位尾号，不超过 6 位的整把密钥掩成「****」；掩码这一位是空的，含义是这条厂商根本没有存凭据，于是编辑界面也无从预填。
- **新建即启用**：新建与编辑的写体里都没有状态位，一条刚建的厂商就是启用状态，要停用得回列表用行上的开关。
- **保存之后重读**：新建与编辑的应答是空体、不带编号，所以保存成功后一律重读列表，界面看到的行与统计来自这一次重读。
- **连通性测试的用法**：入口在卡片菜单里，是一项纯文字动作；点了先显示「正在请求服务端…」。
- **连通性测试的结果**：服务端只回一个是或否，没有耗时、没有原因、没有明细。界面按三种结果呈现：「服务端返回通过」、「服务端返回不通过」、被拒时红色横幅加服务端的原话；并附一句固定说明「服务端尚未实现真实探测，该结果不代表连通。」
- **厂商停用被拒的条件**：该厂商名下还有启用中的模型时，停用会被拒，开关弹回并显示服务端那句原话。
- **厂商删除被拒的条件**：名下任何模型还挂着时删除会被拒；确认里的固定话术是「删除后不可恢复，其下的模型不会被一起删除，需要先迁移或删除。」
- **谁能改厂商**：编辑与删除只在这条厂商由本人创建、或本人是管理员时出现在菜单里；没有创建者署名的行一律不可管理。管理员可达任意行，与该行是否公开无关。
- **厂商卡菜单的排列**：依次是启用/停用、连通性测试、编辑、删除，后两项只在有权限时存在；启用/停用在写入在途时禁用，测试项不设这道禁用，测试途中再按一次就再发一笔探测、这一行的结论以最后落地的那一次为准；写入在途时菜单按钮的图标转为沙漏。
- **两级各自的空态都是两句话**：厂商给「暂无厂商」与「没有符合条件的厂商」，模型给「暂无模型」与「没有符合条件的模型」，用当前有没有条件来选其中一句。
- **给绑定向导的候选读**：智能体与团队的模型选择用的是另一条不带任何筛选条件的候选读，按请求的数量截断；它与本章这两屏的列表读互不相干，一边翻页不影响另一边看到的内容。
- **模型列表的分页与条件**：每页 20 条；右上角漏斗里是三组，用分隔线隔开——状态一组、模型类型一组（「全部」与对话、向量逐档）、五个能力位一组（联网、推理、工具、MCP、视觉）。前两组是单选、当前项打勾；能力位那一组可叠加，有勾即在该集合内，再点一次把它取出来，任一改动都立刻重读，上送前按固定次序重排过一次再逗号拼接，因此与点选先后无关。只有最低价格与最高价格两个输入框留在行上方，跟着关键词的 500 毫秒节拍一起上送。
- **价格区间的解析**：空、非数字、无穷大都视为该端不填，参数整个不上送；接受用逗号写小数；区间两端都是闭区间。
- **筛选中的判定**：只有真的上了线的条件才算「在筛选中」，此时漏斗转为实心，两个价格输入框照常留在行的上方；筛到空时把它们撤销的两处路径都还在屏上，操作者看得见是自己筛掉了它们。
- **模型行显示**：标题按显示名、模型名称、未命名模型依次取；技术名与标题相同时不重复一行；徽标顺序固定为「强制思考」（危险色）排在最前，其后是能力位，最后是价格。
- **共享标记与能力位的取数**：厂商卡与模型行都按公开标记等于 1 判定为共享、并挂一枚共享徽标；五个能力位各读各自的一列，缺列按未具备计。
- **价格的写法**：单位是每百万 token 的元数，四位小数并去掉尾随的零与尾随的小数点，因此 0.0000 读作 0；低于 0 的价格按 0 记账。
- **思考模式控件**：三档菜单「不支持思考 / 可选思考 / 强制思考」，脚注写明它与推理位的耦合关系；读取时先认这一档，这一档缺失时才回落到推理能力位。
- **类型与能力的联动**：把类型从「对话」切走时，五个能力位同时全部关闭，表单里就写着这句：能力位仅适用于对话模型，切换到其他类型会全部关闭。
- **模型表单字段**：显示名称、模型名称、模型类型、单价、描述、五个能力位、公开开关。名称与模型名称各限 100 字且都必填，描述限 500 字，单价必须可解析且不小于 0、留空按 0 计。
- **公开开关的门控**：管理员和新建场景可调；其他账号只能把自己私有的行调成公开，公开的行调不回私有，别人创建的行一律不可调。开关是灰的而不是消失，旁边给原因。
- **启用模型被拒的条件**：所属厂商处于停用状态时，启用该厂商名下的模型会被拒，开关弹回。
- **删除模型被拒的条件**：智能体、团队或会话还在引用它时会被拒，服务端那句话里带着点到的数量，界面原样显示。
- **编辑的数据来源**：这一路没有单条模型的明细读，所以编辑表单从行数据回填，改完写回。

### 4.2 工具

- **只读**：这一列没有新建、没有删除、没有开关，列表上方固定一句「工具由代码注册，这里只能查看。」界面上不存在对工具做写的入口。
- **一次读全量**：内置工具表不分页、没有页码概念，只读一次；关键词与状态都只在本机比对已有行，因此翻动筛选不产生请求，只有下拉刷新会发请求。
- **关键词的比对范围**：名称、显示名、中文名、描述四列，任一列忽略大小写命中即留下；没有值或空白列不可能命中。关键词只去掉首尾空白来判断「到底有没有关键词」。
- **状态筛选的口径**：与状态列的原始值直接比对，因此状态列没送到的行只在「全部」下出现。
- **工具行显示**：头像、标题、代码名一行、描述、徽标（需确认、必选、停用、环境参数数）、创建者一行。必选工具在投递时强制注入，绑定向导里从来不列它。
- **详情内容**：两段，参数在前、实现在后，没有内容的段落整段消失。参数行是名称、描述与默认值、以及必填与敏感两个徽标；当参数明细为空但声明里有必填键名时，只列出这些键名并各带一个必填徽标。实现段只给容器对象名与方法名两行。
- **详情的读法**：打开详情不发请求；只有右上角的重读按钮会按编号再读一次，行里没有编号或正在重读时该按钮不可用；重读失败时已显示的信息留着，失败另挂横幅。三个名字列全空时标题退到编号，连编号也没有时用占位文案。
- **行的次序**：就是服务端给出名称的次序，本机不做任何重排，因此筛出来的相对顺序与那一次答案一致。
- **空态的两句话**：没有任何工具时写「还没有注册的工具。」有条件却筛空时写「没有符合筛选条件的工具。」
- **参数数徽标的下钻**：点它进入那张参数声明表，逐条给出参数名、用途、必需与敏感两个标记，以及有默认值时的默认值一行；敏感参数在这一层能读到的也只是服务端已经掩过的文本，标题写「参数」。

### 4.3 MCP

- **列表分页与条件**：每页 20 条；右上角的漏斗里放两枚选择器——状态与连接方式，连接方式给「全部 / STDIO / SSE / Streamable HTTP」。STDIO 留在菜单里是为了找得到历史行：该传输被服务端的运行策略挡掉，老数据仍在表内。
- **关键词的口径**：按名称与描述匹配；条件为空时这一位整个不上送，而不是上送空串。
- **卡片显示**：标题（没有则「未命名服务」）、启用徽标、描述、地址行（stdio 行显示它的命令，其余显示地址）、徽标（连接方式、公开、按用户授权、请求头数、环境参数数）、创建者一行，以及一条可关闭的结果横幅。
- **菜单四项的可用性**：测试连通性在测试进行中禁用；启用/停用在该行写入在途时禁用；编辑与删除受创建者权限门控；删除被按下后先显示检查中的状态。
- **连通性测试的时限**：15 秒。到点显示「15 秒未响应，测试已超时。」，这一次探测不取消、由它自己跑完；结果共三种：成功、失败（带服务端给的原因原话）、超时。
- **删除前的关联读**：删除先读「谁绑定了这台服务」。读到才弹窗：零个时写「当前没有智能体绑定该服务，删除可以正常执行。」；有绑定时写「N 个智能体绑定了该服务（名单），删除会一并移除这些绑定。」名单最多列 5 个、超出用省略号，一个名字都拿不到时退化为只报数量。关联读失败时根本不弹窗，只在列表上方显示失败原话，删除项可再次点击重试。确认后该行就地移除。
- **表单字段**：名称、描述、连接方式、服务地址或执行命令、请求头列表、环境参数列表、认证方式、授权服务器与作用域等 OAuth 附加项、状态与是否公开。
- **连接方式的可选项**：新建时列表里根本没有 stdio；只有被编辑的行自己存的是 stdio，才把它排在首位供显示。认证方式里 stdio 不配 OAuth 2.1；Basic 已停用于新建，但存下这条值的行仍会显示它并提示换一种再保存。
- **字段的随动**：非 stdio 才显示地址与请求头，只有 stdio 才显示环境参数；切换连接方式会清掉另一族的全部字段并把认证从 OAuth 顶掉；切到 OAuth 会清掉授权服务器、作用域与 Audience 并把资源标识复位。
- **表单校验**：名称必填且不超 100 字；stdio 必须填执行命令，其余必须填服务地址且是带域名的 http(s)、不含账号与口令；填了授权服务器就必须是带域名的 http(s) 且不含 userinfo；请求头名称不得重复；参数名称不得重复；标为必需的参数必须给出默认值。
- **地址变更的额外确认**：改动地址会让这一台服务上所有用户已换取的凭据一起作废，因此提交前先弹「服务地址已变更」的确认、说明需要重新授权，确认后才重新提交同一次保存。
- **新建的可见性**：新建表单明确按「私有」提交，因为这一位漏写时服务端的默认解读是公开。
- **新建不许测试**：新保存路径上没有测试按钮，屏幕写明「请先保存该 MCP 服务，再进行连通性测试。」
- **新建入口与空态**：工具栏的新建动作是漏斗左边的一枚加号，此外没有别的创建入口；没有任何服务时写「暂无 MCP 服务」，有条件却筛空时写「没有符合条件的 MCP 服务」。
- **两类列表条目**：请求头条目一行三样（名称、值、敏感开关），环境参数条目一行四样（参数名、描述、默认值、必需与敏感两个开关），都可以逐条增删。
- **带着掩码载入的条目**：编辑时某条目的值或默认值读回来是掩码，该行挂一枚「保留原值」标签，说明这一位不动；把内容擦干净再保存等于明确要抹掉它，界面对擦掉的位上送的是空值而不是省略。
- **只提交动过的内容**：编辑的写体里只放真正改过的字段，两个列表只在被动过、或内容与读到的不同时才整份上送，因此没碰过的表单不会改写任何一位。
- **缺编号的保存**：这条服务在答案里没有编号时保存被拒，屏幕写明「该服务缺少 id，无法保存。」因为编号是这一路唯一的地址。
- **详情的读次数**：三次读：服务行本身、它的工具清单、你的授权状态；除此之外不发请求。头部是启用开关与测试按钮。
- **详情显示的配置项**：地址或命令（按连接方式取其一）、认证方式、请求头、公开或私有、描述、创建者与创建时间、更新时间。请求头这一栏只列名称，值一律不列。stdio 行下方固定一段说明：该类型已在服务端禁用、无法新建、这条历史数据可见、服务端不会连接它。
- **详情的刷新**：这一屏的下拉刷新重跑那三笔读，配置、工具清单与授权状态一起跟上最新答案。
- **工具清单的四态**：未启用（服务已停用，未获取工具列表）、载入中、已载入、失败。空清单显示「暂无工具」；只有被拒的那一次读才提供重试。开关变动会清掉旧的测试结论并重新拉一次工具清单。
- **工具卡的字段**：工具名、无参数或参数数徽标、参数行（名称、类型徽标、描述或「暂无描述」）。这一路的清单不携带哪些参数必填与取值范围，因此界面上也不显示这两项。
- **按用户授权的可见条件**：只有被标记为「每个用户各自授权」的服务才有这一区；服务级配置只写授权服务器，授权本身是每个人的事，界面写明这份授权只属于当前账号，其他用户要各自完成。
- **授权状态徽标**：只有「已授权」和「需要授权」两种说法，没有第三种状态可供声称。
- **可执行的动作**：去授权、在本应用授权、我已在浏览器完成授权、撤销；正在换令牌时显示「正在完成授权…」，正在等待时显示「正在等待浏览器完成授权…」。
- **授权区逐行列出的内容**：状态读到之后，有已授予作用域就单独一行按逗号并列；有最近错误就单独一行原样给出那一句；这一轮的授权地址存在时整条显示在「浏览器授权地址」一行里（最多三行）；等待与换令牌各占一行并带进度指示；撤销的答复单独一行。
- **授权请求的来路**：授权请求由服务端组装，内含 PKCE 与一次性的 state；设备侧只拿到一个授权地址。这个地址按敏感材料处理：只在屏幕上显示出来，绝不写入任何存储，也因此无法被重复使用。
- **两条授权路**：一条交给系统浏览器；一条在本应用内打开网页，但必须同时拿到授权地址与回跳地址，否则写明「这次授权请求没有带回跳地址，本应用无从等待。请改用浏览器完成授权。」
- **应用内截获的规矩**：本应用内的网页用一份不落盘的会话存储，页面关闭这份 Cookie 即消失；导航在页面加载完成前就被判定，授权码从回跳地址里取出。一次授权只截一条回跳：同一个 state 花第二次是这条流程唯一不可做的事；回跳被取走之后，同一个地址再访问就是普通页面，用过的授权码不会被送到回调页。中途取消明确报「已取消授权。」
- **浏览器路的收尾**：登记的回调地址是控制台自己的页面，应用观察不到回跳，因此由操作者按下「我已在浏览器完成授权」后重读状态；本机没有能打开该地址的浏览器时给出对应文案，等待随即结束。
- **换令牌与它的失败样子**：拿到授权码后立刻换令牌。这一请求不带 MCP 编号，state 认出的那笔待处理请求决定这次同意算在哪台服务上。换失败不以错误码回来，而是以成功应答里「未授权」的形式回来，界面因此回到「需要授权」，不会谎报失败原因。
- **等待与轮询**：授权后按 2 秒一次、最多 60 次读状态，合计 120 秒；等待按四分之一个节拍切片，每片结束都先看这一轮是否已被新的一次顶掉，只有没被顶掉才显示「仍未查到授权。请在浏览器完成后再次确认。」离开这一屏即停止等待。
- **成功之后的刷新**：换令牌成功后立刻重读授权状态，徽标随之成为「已授权」；撤销也重读，因为对本来没有的授权执行撤销，答案同样是已撤销。
- **授权服务器侧的信息**：端点与客户端状态在第一次点「发现授权服务器」之后才显示，进入页面不会自动发现；发现会向授权服务器发出出站请求，执行中该按钮禁用，失败时保留上一次的发现结果并在区内显示错误、按钮转为重试。
- **发现后列出**：授权服务器（并标出它是手工填写、资源元数据还是 401 挑战里读来的）、授权端点、令牌端点、动态注册端点（没有则「无：客户端需预先登记」）、撤销端点（没有则「无：撤销只在本侧生效」）、可授予作用域、已登记的 client_id、密钥是否已保存、回跳地址。
- **两处必须读到的告警**：授权服务器没有声明本次要用的作用域时点名那些作用域；这一屏将要送回浏览器的回跳地址与已登记的值不一致时，提示授权服务器按字符比对回跳地址、需要把客户端重新保存为该值。
- **登记客户端的前置**：没有授权服务器时该按钮一直禁用，并写明「请先执行发现：客户端要登记到具体的授权服务器上。」动态注册这条路服务端并未实现，凭据必须事先由授权服务器签发再粘贴进来。
- **客户端凭据表单**：三项：签发下来的 client_id、client_secret（可留空）、回跳地址。client_id 必填且限 255 字；回跳地址限 500 字且必须是带域名的 http(s)；密钥留空表示保留已保存的值，纯空格被拒并写明「空格不是密钥——留空表示保留已保存的值」；勾上「删除已保存的密钥」会在同一拍把已存密钥与正在输入的值一起清掉，并把该客户端转为只依赖 PKCE 的公共客户端。任一字段有问题或正在保存时，保存按钮禁用，问题按字段逐条列在字段下方。

### 4.4 技能

- **两级关系**：技能永远属于某一个来源。左栏是来源列表，点进某一行才推入那个来源专属的技能表，技能表再点进详情；进入自动选中的第一行不会推屏，只有明确的点击才会。
- **来源列表的分页与条件**：每页 20 条，关键词按来源名匹配、500 毫秒节拍；这一屏的条件只有关键词一项，状态与源类型都不给筛选控件。右上角两枚图标：加号建仓库型来源，另一枚是压缩包入口。
- **来源卡显示**：名称、源类型徽标、只读徽标（该类型不可刷新时）、地址行（GIT 的地址与分支、NPM 的包名、ZIP 的原始文件名）、已启用技能数徽标、同步徽标、状态圆点。同步徽标由上次同步的状态与月日两截拼成，没有状态时写「从未同步」。
- **三种横幅的顺序**：列表上方依次可能出现刷新失败的红色横幅、删除被挡的警告横幅、以及一条可关闭的配置提示。
- **谁能操作来源**：整簇动作只在该来源不是平台内置、且由本人创建或本人是管理员时显示。内置那一行连同步与删除都不给。
- **来源菜单项**：同步与全部重装只对可刷新的类型（GIT、NPM）出现；启用/停用、编辑始终出现；删除在最后。
- **删除来源的条件**：该来源下仍有已启用技能时被挡，界面写「仍有 N 个已启用技能来自这个来源，请先停用它们。」这一计数缺失时按非零处理，最终判定权在服务端。
- **全部重装**：不发送任何技能名，含义是整个来源重装；发出之后重读列表。
- **新建来源需要什么**：名称必填且限 100 字；源类型在 GIT、NPM、ZIP 三者中选，类型决定要填哪两项以及是否必填。GIT 必须有仓库地址、分支可空且空着按 main 落库；NPM 必须有包名、Registry 可空；ZIP 不需要地址与包名。版本限 100 字，另有描述、状态与是否公开。公开开关在无权限时禁用并写明「您没有权限修改此设置」。
- **类型不可换**：源类型在编辑时不接受改动，编辑的写体里没有这一位；状态停用的含义是这一路随之停止被读取。
- **保存配置的两种答复**：新建会顺带安装，因此答复同时给出来源与安装结果，安装结果单独成屏；编辑只写配置，屏幕给一句可关闭的提示：改了地址、分支或包名不会自动重取，需要在列表里再走一次同步才会刷新已存储的技能。地址与包名的形状错误由服务端那句话来报。
- **上传压缩包**：右上角那枚向上的文件图标（读屏念作「上传 ZIP」）开一张独立屏，选好文件不会上传；必须先命名来源，再按「上传并安装」才发。缺名、缺文件、文件读不出来各有一句；成功后同样弹出安装结果，失败时留在原地显示错误。
- **内置来源的固定待遇**：卡片挂一枚「内置来源不能同步，也不能删除。」的只读徽标，同步、全部重装与删除三项对它都不存在。
- **压缩包来源的编辑限制**：编辑一张 ZIP 来源时字段说明写明这里不能替换已保存的压缩包，要刷新内容请重新上传一个 ZIP；这一路也没有地址与包名可改。
- **同步徽标的四种状态句**：上次同步完整、上次同步有失败、上次同步失败、上次同步没有内容；状态值认不出时整枚徽标不显示，只剩「从未同步」那一句。
- **同步面板的开场说明**：写明此刻还没有写入、下面列出的是来源当前持有的技能，要先勾选要存储的、再看安装结果、然后关闭；面板里的计数徽标会说「其中 N 个是新增」。
- **同步是两次调用**：第一次读来源但不写任何东西，把候选技能列出来；操作者删勾；第二次安装选中的那一部分。候选里区分「新增」与「覆盖」，另有全选与清空；提交顺序按预览给出的顺序。
- **安装按钮的文案**：按钮上写明这次要装几个（安装所选（N）），N 随勾选数量走；一个都没勾时不发请求，屏幕给「至少勾选一个技能。」。
- **勾选的门**：一旦出现安装结果，勾选即被锁定、不接受改动；一个都不勾不会走到服务端，因为那一路的空数组是有真实含义的回答，界面上必须至少留一个。
- **读失败不等于空来源**：打不开来源与来源里确实没有技能文件是两句话，前者的错误不会画成后者的空态。
- **同步后的刷新**：任何一次被应答的尝试都会让左栏来源列表重读，卡片上的已启用技能数与同步徽标随之更新。
- **安装结果的五档**：新增、已覆盖、停用待复核、失败、来源里已不存在。取色按优先级判一次：有失败且一个没写入是错误级；有失败是部分成功的警告级；有待复核是警告级；来源打不开是错误级并带原话；来源为空是警告级并带原因；一个都没写入是警告级；其余为成功级。空档不显示成「0 个」，「来源里已不存在」那一档即使整体是绿的也单独成段，它只报告、不删除任何行。
- **完整性校验不过的样子**：技能已写入但被停用，归在「停用待复核」档，标题句为「N 个技能已存储但被停用，待复核」，每行带服务端给的原因；同一个文件可能同时命中多条规则，原因以中点并列。一次干净的同步（无失败、无待复核、无消失、且有写入）自动关屏，否则页脚给「完成」与「确认」。
- **技能表的分页与条件**：每页 20 条，只列当前来源；关键词按技能名匹配；状态是右上角漏斗的三项（全部、启用、停用），当前项打勾；导航标题是那个来源的名字。换来源时关键词、筛选、行、覆盖状态、提示与页码全部复位，上一笔在途读同时作废。这张表上没有删除动作。
- **技能行显示**：标题（没有则「未命名技能」）、描述两行、绑定智能体与绑定团队徽标（数量为 0 时不显示）、共享徽标、创建者与同步时间一行。没有编号的行整行禁用。
- **停用的门控**：只有停用方向受绑定量约束，按被绑定的侧别给四种文案之一（只被智能体绑、只被团队绑、两侧都绑、两侧都没绑）。行上的两个计数不是全部依据：属于某个 CLI 包的技能在这里读作未绑定，写入时由服务端那句话来拒。启用方向不设这道门。
- **详情的读与写**：一次读、两个页签、没有任何写入。
- **正文页签的渲染范围**：文档按块渲染，支持的块是各级标题（井号式与下划线式）、段落、无序与有序列表及按缩进嵌套的子列表、任务勾选标记、两种围栏写法的代码块（正文原样保留、围栏上的语言名作标签）、引用、分隔线、管道表格（含左右中对齐与按表头列数截断）；行内支持加粗、斜体、代码、删除线、带标签链接、自动链接与反斜杠转义。HTML 一律当字面文本，因此没有可注入的东西；引用式链接与脚注原样显示；远程图片不抓取，用替代文字顶上；四空格缩进不当作代码块。空文档不报错，识别不出的内容至少留一个段落。
- **资源文件页签**：顶部是文件数徽标与「全部展开 / 全部收起」，下面按缩进呈现目录树、目录带子项数量；点开某个文件在同屏内联显示等宽正文，可横向滚动、文字可选中，不推新页面，因此展开状态不会丢。资源数据解析不出来与真的没有资源文件在这一路上无法区分，两种都表现为只有正文页签有内容。
- **空态**：没有正文时写「该技能没有存储 skill.md 正文。」没有资源文件时写「该技能没有资源文件。」

### 4.5 CLI

- **只读加一个开关**：这一路没有新建、编辑与删除的界面，包是通过把压缩包投放到服务端目录、由服务端启动时登记进来的。列表与详情能读，唯一能写的是启用状态。
- **列表的分页与条件**：每页 20 条，关键词按名称匹配、500 毫秒节拍，条件只有状态一项。
- **空态的两句话**：平台上一个包都没登记时写「暂无已登记的 CLI 包」，有条件却筛空时写「没有符合条件的 CLI 包」。
- **卡片显示**：名称与启用徽标、描述、一整排徽标（版本、包内技能、包摘要、环境参数数）、健康检查命令一行、登记时间一行。这一整排徽标整体套在一个下钻按钮里，按其中任何一处都打开声明详情；环境参数数那一枚自己还是一个独立按钮，直接按它只打开参数声明表。
- **菜单三项**：启用/停用、查看声明、刷新。
- **详情的两处入口**：菜单里的「查看声明」与卡片上那排徽标的下钻按钮到的是同一张声明表；四组的标题依次是「包信息」「包与镜像指纹」「apt 依赖」「运行时环境」，第一组给出版本、描述、状态（以启用或停用徽标表达）、包内技能、登记时间，名称与状态徽标由卡片那一层给出、声明表里没有名称这一行。卡片上的包内技能与包摘要两枚徽标各带一段前缀，读作「技能 …」「摘要 …」。
- **菜单的刷新项**：与下拉刷新同一笔读，回到第一页、带上当前的关键词与状态条件。
- **参数声明的读法**：点环境参数数徽标进入声明表，逐条给出参数名、用途、必需与敏感标记以及默认值；这一层读到的敏感值本来就是掩码，界面上没有任何动作可以把这一位送回服务端。
- **开关的四步判定**：读不到关联智能体清单时开关不动作，本次作废并显示失败；没有任何智能体绑定时，这一改只是本行的私事，直接执行，不确认也不提刷新；在有人绑定时启用，属于把能力加回去，因此立刻执行、随后提供刷新；停用是往里减东西，因此先确认并点名谁会失去。
- **停用确认的内容**：标题「停用该 CLI？」，正文给出绑定数量与名单（最多 5 个名字、超出用省略号，名字缺失时退到「智能体 #编号」再到占位名），并说明停用后这些智能体的沙箱会失去这条命令、包内技能也随之不装载。
- **停用不会被绑定量拒绝**：与模型、技能、MCP 不同，这一路的开关在有人绑定时照样可以通过，代价是先看影响面。包内技能跟随同一个启用值。
- **详情读的是列表没有的三列**：镜像指纹、apt 依赖、运行时环境槽位只有详情页会读，列表页的答案里根本不携带这三列，所以这一屏按编号自己再读一次，而不是直接画列表已经拿到的那一行。
- **详情的取值口径**：包摘要与镜像指纹用同一套截断，超过 12 个字符才截并加省略号、本来就在 12 字符以内的整段显示，完整值写在标签下面；声明表里任何一位缺值都写「无」而不是留空；运行时环境按键排序；「环境参数声明」是每次绑定要填的槽位，「运行时环境槽位」是平台建容器时注入的键值，两者分列不相混。
- **详情的四种状态**：这一行没有包编号时不发请求，并写明该行没有包编号、无法查询声明；其余依次是载入中、就绪、失败。包已下线时报「读不出来」而不是打开一张空页。
- **刷新受影响会话的触发条件**：只有在存在绑定关系的前提下改过状态，才会自动弹出共享面板；无绑定的翻转不弹、也不提供刷新。
- **面板的口径**：标题「刷新关联会话」，说明句点出刚被改动的 CLI 名字，并写明勾选的会话立即装载新的包、未勾选的最迟约 30 分钟内自动生效。清单一次读入、默认全勾；一个都不勾就是跳过、不发任何请求；每条会话各自给结论，整批里有条目失败时汇总写成「N 个已刷新，M 个失败」并保留失败行的原因、所有行停止可改；清单为空与清单读失败是两句话，不会用空态冒充读失败；「稍后处理」直接关闭。
- **在会话里的用法**：智能体绑定某个包后，会话运行时把该包装进沙箱，命令行与包内技能一并可用；启用与停用同时决定这两者。会话自己带着一份配置快照运行，管理端的改动不会自动落到已在跑的会话上，因此上一条的面板才是让改动立刻生效的手段。

### 4.6 环境变量

- **入口位置**：这一类的管理屏挂在「我的」的管理分组里，不在上下文那一排分段里；它与上下文的六类绑定同源，因为工具、MCP、CLI 声明的环境参数最终要引用这里的变量。
- **列表的分页与条件**：每页 20 条，关键词按 Key 与描述匹配、500 毫秒节拍；这一页没有状态筛选，服务端只收关键词，本机做假筛选会藏掉服务端已经计入的行。
- **列表顶部固定两行**：一条常驻提示「改动对运行中的会话最迟 30 分钟后生效」，以及服务端给的总数（不是当前页的行数）。
- **行显示**：Key（等宽字体一行）、敏感徽标、启用或停用徽标、值列、描述、创建者与时间。
- **两个标记的判定**：启用与否按状态列不等于 0 来读，状态列缺失时按启用呈现；敏感按敏感位读，这一位缺失时按非敏感读；没有值时值列写「未填值」而不是空白。
- **值的保密呈现**：敏感行的值是服务端解密之后再掩码给出的：四字符及以内整段掩成六个星号，更长的只保留头尾片段；解不开的值同样答六个星号。这台设备永远读不到明文，长按复制复制到的也只是屏上所见。
- **菜单三项且无权限门**：启用/停用、编辑、删除都在；这一列不加创建者门控，因为读本身已经按账号与租户限了范围，能读到的就是操作者可改的。
- **停用与删除同样被绑定拒绝**：任何智能体还在引用它时，停用会被拒、删除也会被拒，服务端那句话最多点名五个；删除前不做预查，确认里只承诺服务端会决定什么，并写明删除后智能体再也读不到它、且不可恢复。
- **表单字段与上限**：Key、Value、描述、敏感开关，新建另带启用开关。Key 以字母或下划线开头、只含字母数字下划线、限 200 字，新建时必填，改名时同样校验；Value 新建时必填、限 8192 字；描述限 500 字。
- **启用开关的所在**：编辑的写体里没有状态位，所以编辑表单里不显示它，改状态只能用行上的那个开关。
- **敏感开关的说明句**：字段下方固定一句「敏感值只在服务端保存明文，列表里显示脱敏文本。」这一位被翻动时服务端会把存下的文本按另一种形式重编，因此表单只在它真的被搬动时才上送这一位。
- **写完之后的界面动作**：新建与编辑的应答是空体、不带编号，所以表单关闭后重读整张列表，屏幕上的行与总数来自这次重读；删除成功时那一行就地移除、开关成功时只认屏上已落的状态，两种都不整表重读。
- **撞名的处理**：同一个作用域里 Key 重复时由服务端拒绝，那句话点名撞上的 Key，界面原样显示；改名是撞名的唯一来路，因此改名与新建走同一套本地校验。
- **绑定处的变量选择器**：标题「环境变量」、可按变量搜索；候选为空时写「没有可选择的变量」，列表项的副标题是该变量的展示值，敏感变量另带锁形标记，选中时只带走编号。
- **掩码绝不会被当作提交值**：敏感行的值栏从空白开始，旁边写明「当前值为 sk-****abcd」这类掩码；留空表示保持当前值。提交前还有一道判定：输入的内容与这一行读到的原文一模一样时，也算没改动、不上送。这条判定不依赖服务端是否会看穿掩码。
- **引用与自填互斥**：绑定行要么引用一个变量、要么自填一段文本，切到一半时另一半立刻被清空；引用走的是变量的编号，界面上显示的任何文本都写不进请求；选择项的副标题虽然是掩码，选中时也绝不复制进值里。
- **默认值的显示差别**：MCP 与 CLI 的空绑定行会灰显包内默认值，因为那一位确实会随进程投递；内置工具的默认值不落到运行时，因此不显示，必需参数校验也不把它算作已填。
- **一次什么都没改的保存**：表单一个字段都没动也可以保存，服务端把空体读作「什么都不改」并回成功，界面则明确写出还没改动任何字段。
- **作用域的归属**：这一页里的变量是全局池，按账号与租户限定；进入新建绑定候选集的条件是「为当前用户名下、在本租户内、且启用」，而一个已存在的智能体绑定可以指向属于别人的变量（那一位按租户解），因此候选读只界定新选择的范围，不用来判定旧绑定是否合法。往下一层：智能体级的绑定把某个变量或某段自填文本按参数名挂到具体的工具、MCP 或 CLI 上，跟着该智能体的绑定走；MCP 级与 CLI 级的参数由各自的声明给出名称、必需与敏感标记及默认值；会话级的运行时环境由平台在建容器时注入。
- **生效时机**：新建与改动不回溯已在跑的会话，对运行中的会话最迟 30 分钟后生效；被删掉的变量之后再也读不到。

### 4.7 失效徽标

- **统一判据**：某处仍在引用一条资源，而那条资源已停用、已删除或已不是可被使用的形态，引用就被标为失效；标失效的行留在原位并说明原因，绝不静悄悄消失。
- **触发前的必要条件**：候选或明细那一次读必须已经落地，才有资格声称某条引用已经没了；读还没回来时谁都无从判断。
- **对会话的影响**：会话执行的是自己那份配置快照，因此失效的引用不会中断已在跑的会话，但它意味着这一条能力当下拿不到；改动要落到具体会话，得靠刷新受影响会话的面板，勾选的立即应用、未勾选的最迟约 30 分钟内自动生效。
- **模型引用**：智能体与团队向导里存着的模型编号在候选页落地后仍解不出，名称后接一句降级说明，含义是该模型已停用、已删除或不是对话模型，整行转为警示配色但这一项仍在列表里、可以选回；解不出模型时不会据此锁掉工具与 MCP 面板，因为界面并无依据。
- **主管模型**：团队行里的模型记录不见了而引用还在时，直接显示编号形式的主管模型标签；没有主管模型时不显示这一位。
- **团队成员与主管技能**：成员的智能体行不见了时该行仍留在成员列表里，并标为「已删除或已停用」；团队卡上把不可用成员数与不可用主管技能数合为一枚红色徽标「N 项引用失效」，只在数出来的失效项大于零时出现，点开绑定明细可看到逐条标记。
- **会话详情**：成员行与技能行可带「失效」红徽标。这一标记只有团队自己的明细读能提供；智能体自己的明细读里没有可读的可用性列，因此智能体会话不画这枚徽标；会话快照连失效都不表达，技能记录被删之后它干脆不在快照名单里，所以快照那一支什么都不声称。
- **工具与 CLI 声明**：工具由代码注册，不存在被删后留引用的情形；CLI 包被下线时详情页报「读不出来」而不是空页，会话侧的影响以停用确认与刷新面板来交代。
- **技能与来源**：来源与技能的失效不走徽标，而走拒绝：来源下仍有已启用技能时删除被挡、被绑定的技能停用被拒、属于某个 CLI 包的技能在写入时被服务端拒，一律以服务端原话呈现。
- **变量引用**：绑定行指向的变量编号在候选里解不出时，绑定保留、并显示「不显示该变量的值」，因为那条变量属于别人时按租户仍能解，删掉它等于动了操作者没碰过的绑定。
- **向导里的行内降级**：团队向导的成员、主管技能与主管模型三处都用同一手法——坏掉的引用整行留着、名称后接一段说明，绝不把清单缩到看起来完整；判定依据是「候选那一页已经落地、且这行的编号在里面解不出」。
- **会话详情的面板来路**：工具、CLI 包与成员三块内容只存在于执行者自己的明细读里，会话行本身不携带，因此这三块要等明细读回来才出现；团队会话的 MCP 面板按服务端的口径本就是空，智能体会话的 MCP 与技能两块则以明细读为准。
- **两套明细读的可用性差别**：智能体卡片的绑定明细与会话详情读的是同一份明细行，可用性与否的判定也一致——有可用性列的行才谈得上标失效，没有可用性列的行只报名字。
- **面板的三个来路**：同一张刷新面板被智能体保存、团队保存与 CLI 改状态三处复用，说明句按来源各自点名被改动的对象（智能体、团队、CLI 三种说法）；只有改动场景才提供这张面板，新建场景没有已存在的会话可刷新，因此不出现。

## 5. 管理域、定时任务与「我的」

### 5.1 管理分组与管理员可见性

- **分组结构**：这四行是「我的」页面靠下的一组，分组标题「管理」，下面依次排四行：变量、API Key、渠道、Token 监控。行上不显示任何数量。
- **每行长什么样**：图标加名称加一句副标题，右侧只有一个箭头。副标题分别是「智能体运行时读取的参数值」「调用 Harnax 接口的密钥」「接进 IM 的机器人与回调」「按模型、智能体与会话统计的 Token 消耗」。
- **导航层级**：点进去的屏与「我的」共用一条导航栈，表单与弹层盖在该屏之上；返回就是逐层退，一路退回「我的」会把这几层一起收掉。
- **管理员才有的那一行**：账号带管理员标记时四行都在；不带时列表直接少一行，只剩变量、渠道、Token 监控。API Key 入口对普通用户是不出现，而不是出现后点进去被拒。
- **身份从哪来**：只看登录回答里带的那个管理员标记。重新打开 app 时先从本机缓存恢复身份、再用当前账号资料核对一次；缓存读不出来时按无身份处理，此时同样看不到那一行。
- **成员进得去的两个域**：渠道与 Token 监控这两行没有任何访问规则，成员照样打开。打开后每行的更多菜单是空的——菜单项全部要求「管理员或本行创建者」，而存储下来的渠道创建者一律是 system，所以成员看到的是列表与筛选，看不到任何写操作。
- **四个域共用的分页规则**：一页 20 条，执行日志一页 10 条。
- **搜索合并**：关键词在 500 毫秒内的连续输入合并成一次查询，中间态不发请求。
- **刷新与追加**：下拉刷新丢弃在途的旧请求重来；触底追加时若已有一次追加在途则排队，等它回来后再发一次。

### 5.2 API Key 管理

- **行第一层**：名称加一枚「启用」或「停用」徽标。
- **行上的到期信息**：已过期时在徽标后追加红字「已过期」；没过期但带着能读出的到期日时追加黄底片「09-12 到期」；这两种情况都不成立时，这一行不出现任何到期标记。
- **行第二层**：一把钥匙图标加 Key 的前缀，形如 hnx_sk_live_ab...9f3c（前 12 位加省略号加后 4 位）；前缀为空时这一行写「没有可显示的 Key」。
- **行第三层**：权限范围逐个排成片，规范顺序是 chat 在前 manager 在后。
- **行第四层**：小字归属，格式是创建者 · 创建日，日期只剩月-日、年份丢掉。
- **限流不上行**：每行不显示限流数值，限流只在表单里出现。
- **这一页能拉到什么 Key**：只列临时 Key，永久 Key 不在其中，行数据里也没有区分两类的列；服务端只保留密钥摘要与这段前缀，完整密钥从不出现在列表里。
- **一行的处置权**：管理员可以动任意一行，其他人只能动自己创建的行，行上没有创建者时谁都不能动。行是否公开在这条规则里不起作用。
- **菜单的第一项**：「启用/停用」对所有行都显示，但上面那条规则不满足时是灰的；本地状态已经等在那里时它也保持可点，好让在途的那次写入能被看清。
- **菜单的其余项**：「重新生成」「编辑」「删除」三项只给满足规则的行，删除用破坏性样式。处置在途时菜单图标换成沙漏，重复点击不发出第二个请求。
- **到期值为空**：按长期有效处理，行上不放任何标记。
- **到期值读不出来**：时间戳既不是「年-月-日 时:分:秒」也不是带 T 的写法时，行上同样什么都不放——既不算「已过期」也不给出到期片，界面不假装读过它。
- **到期时间的读法**：不带时区，按服务端墙上时钟读，再按手机日历渲染。
- **编辑里开关的初位置**：按「这一行的到期值能不能读出来」决定，读得出来则打开并回填该时刻，读不出来则关闭。
- **把到期关掉之后**：这一行带着一个能读出的到期值时，提交发一个空串把它清空，这是回到长期有效的唯一路径；那一行本来就是空的时候提交省略该字段，等于不动它。
- **新建表单标题与字段**：标题「创建 API Key」。依次是名称（占位「给这个 Key 起个名字」）、权限范围两条开关行「对话（chat）」「管理（manager）」及其上方提示「chat 只能发起对话；manager 还能改配置。」、限流、租户、「设置过期时间」开关。
- **限流字段**：提示「每分钟允许的请求数，留空表示不限流。」，占位「例如：60」，新建时默认已经填着 60。
- **租户字段**：只有管理员看得见，提示「只有管理员能指定，留空则归属当前租户。」；非管理员填了也没用——新建时服务端按当前租户落，更新时由服务端拒掉。
- **过期开关打开后**：出现一个到分钟的日期时间选择器，标题「到期时间」，开关下方提示「到期即不可用；不设置则长期有效。」。
- **新建的拦截条件**：名称为空报「请填写名称。」，超过 128 字符报「名称不超过 128 字符。」，权限一项没选报「请至少选择一项权限。」，限流不是整数报「限流要填一个整数。」，限流越出 1 到 10000 报「限流要在 1 到 10000 之间。」，租户不是正整数报「租户 ID 要是一个正整数。」。
- **留空的字段**：整条不发给服务端，好让服务端默认值生效。
- **权限两项的性质**：它们只是名称，不是权限边界，界面不得因为某个值是 chat 或 manager 而改变任何行为。
- **编辑表单的差异**：名称变成只读一行，旁边写着「名称创建之后不能再改。」；多出一枚启用停用开关，这枚开关只在编辑时出现；限流与租户初值取自行数据；没改动的字段不放进提交体。
- **一次性面板何时出现**：只有创建成功和重新生成成功会开它；编辑保存成功不开，因为那条路不回答密钥。
- **面板的排布**：标题就是这把 Key 的名称；顶部警告「完整 Key 只显示这一次，离开后就再也看不到。」；一块标着「完整 Key」的等宽正文，可整段选中，也可一键复制到系统剪贴板，按钮复制后变成「已复制」；下面说明列表里会显示成什么前缀，并写「现在把它复制到自己的客户端里；关掉这个面板只能靠重新生成换一把新的。」；唯一出口是标题栏「确定」。
- **往下拖被拒**：划走面板等于把没读过的密钥扔掉，这个手势在界面上不被允许。
- **值的寿命**：不落任何存储、不写缓存、不改行数据，关掉即销毁，也从不回到列表屏；一份密钥有四五十个字符，没人会手抄进配置文件。
- **重新生成的确认**：标题「确认重新生成？」，说明「重新生成会让当前 Key 立即失效，所有使用它的客户端都要换成新 Key。」，按钮写着「重新生成「某名称」」。
- **重新生成的路径**：POST /api/admin/api-keys/{id}/regenerate；返回后先弹同一张一次性面板，再重读列表，因为前缀变了、行必须重取；上一次重新生成没回来时不发出第二次。
- **重新生成不做类型保护**：这条路由上没有受保护类型的检查，换掉一把泄露的长期 Key 靠的正是它。
- **删除**：无前置校验；确认框「删除这个 API Key？」，说明「此操作不可恢复，正在使用它的客户端会立刻失效。」。
- **停用被服务端拒**：本地先翻过去、随后翻回来，行上方留一条红色横幅，文案用服务端原话，例如 Permanent API Key cannot be disabled。界面里没有一份「哪几类 Key 不能停」的白名单，判定完全交给服务端。
- **筛选与空态**：右上角漏斗的三项选服务端的启用位，当前项打勾，加号排在它左边；无筛选时空列表写「还没有 API Key。」，有筛选时写「没有符合条件的 Key。」。

### 5.3 渠道：列表、筛选与沙箱灯

- **行第一层**：名称加一枚「启用/停用」徽标。这一枚看的是列表开关那一列，和表单里的自动监听开关是两个不同的值；服务端没给这个值时按运行中算。
- **行第二层**：类型片、模式片、沙箱胶囊；个人微信类型的行额外给一枚「已扫码」或「未扫码」。
- **未扫码的判定**：读配置块里的登录令牌，值里含星号（也就是掩码形态）就算没绑。
- **类型的显示**：认得出的类型用中文名（企业微信、个人微信、飞书、钉钉、HTTP 回调），码认不出来时把码原样印成片，没有类型码就不出片。
- **行第三、四层**：「智能体 %@」一行，小字创建者与创建日一行。
- **筛选**：搜索框「搜索渠道」由服务端做模糊匹配；右上角的漏斗里放两枚选择器——状态筛选（全部/启用/停用）和类型筛选（五个类型加全部），加号在漏斗左边。两枚都选「全部」时对应的参数干脆不发出去，而不是发一个哨兵值。
- **空态**：无筛选时「还没有渠道」，有筛选时「没有符合条件的渠道」。
- **沙箱灯是一次二阶读取**：GET /api/router/agent/workspace/status 按行上的会话编号查，每页取回后再发一次，翻页结果累积保留，旧页的答案靠世代号作废。
- **灯的四种结果**：行上没有会话编号就不出胶囊；查到了但这个会话没被提到，出中性色「沙箱状态未知」；运行标记为真出「沙箱运行中」；为假出「沙箱空闲」。
- **灯的失败口径**：查询本身失败绝不渲染成「已停止」；这一页一个会话编号都没有时连请求都不发；运行标记回了个非布尔值时降级成「没提到」，而不是整张映射失败。

### 5.4 渠道：表单、开关与扫码

- **类型的可见与可选是两件事**：五个类型都摆在片行里，没有服务端适配器的那一个（HTTP 回调）灰到几乎按不动，也点不上。
- **不支持类型的表现**：一旦表单落在该类型上，顶部出现警告「该类型还没有注册服务端适配器，起这样的渠道只会在运行时报 no adaptor registered，因此这一行只能查看，不能保存。」，同时保存键不可用，提交动作在编码请求体前就拒绝。
- **已存下的这类行**：照样列出、照样读得出，只是无法通过表单保存。
- **模式行何时出现**：选定类型后才出现；某类型只支持一种模式时模式行整行隐藏。可跑的组合是：飞书配长连接或回调、钉钉配 Stream、企业微信配长连接、个人微信配轮询、HTTP 回调配回调。
- **凭证矩阵**：企业微信要「机器人 Bot ID」「机器人 Secret」；钉钉要「Client ID」「Client Secret」；飞书要「App ID」「App Secret」，回调模式再加「Encoding AES Key」「Verification Token」；HTTP 回调要「Webhook 地址」；个人微信不填任何凭证。
- **凭证的必填口径**：新建时上述各组必填，飞书回调那两项只在回调模式下必填；编辑时只有飞书回调那两项继续必填，其余留空表示不动它。
- **没选类型时**：提示「先选一个渠道类型，凭证字段会跟着变。」。
- **选中个人微信时**：提示「个人微信不在这里填凭证：先保存，再回列表扫码。」。
- **名称**：占位「渠道名称」，超过 100 字符时保存键不可用。
- **绑定智能体**：从 GET /api/admin/agents/page 取，只装第一页的 100 条；行上存的智能体不在这 100 条里时按名称补进选择器，连名称都没有就写成 # 加编号；这份选择器失败时字段下方留一行原因加「重试」——没有智能体时表单只剩取消，必须给出第二条路。
- **描述**：占位「一句话说明这个渠道做什么」，原样提交；清空时发空串，好让备注真的被抹掉。
- **编辑时多出的两块只读**：会话编号（值带 chn- 前缀，提示它由创建动作生成、此后不会改动）与回调地址（只在回调模式下由服务端按渠道派生给出）。
- **开关一：开机自启**：提示「服务重启后自动开始监听」；它只在服务重启那一刻起作用，对正在运行的服务没有任何动作。
- **开关二：深度思考**：新建时是三档菜单（跟随模型/开启/关闭），不选就等于把决定交给绑定的模型；编辑时是普通开关并提示「必填思考的模型会拒绝显式关闭」，绑的模型强制思考时显式关会被服务端拒。
- **开关三与四**：联网搜索、计划模式，是发给模型的可选能力位。
- **列表那枚开关的边界**：启用停用只决定控制台是否把渠道列出来，不会断开已经在跑的监听。
- **掩码回传规则**：配置块是一段字符串形态的 JSON，服务端的密钥字段永远以掩码形式回传；含星号的值一律原样送回，绝不改写——把掩码写回去就是用掩码覆盖真值。对应字段的提示是「按服务端的掩码显示；保持原样就不改动。」。
- **合并规则**：界面管理的键覆盖同名旧值，留空的键从结果里删除，没被管理的键与非字符串的 JSON 值一律原样保留；新建时一个键都没写就不发这个字段，编辑时一个键都没写就发一份空对象。
- **容量上限**：合并结果超过 20000 字符时整份配置不提交，失败原因是服务端原话。
- **回调密钥**：本身不在返回字段里，界面只有派生出的回调地址；扫码写入的那个令牌在这一侧只读，表单不管理它。
- **扫码的入口**：只在个人微信行的菜单里，从列表打开，关掉后列表重读这一行。
- **扫码的第一步**：面板一出现就自动发起 POST /api/admin/channels/{id}/wechat/login，服务端直接回一张内嵌在应答里的图片；220 见方的码直接铺出来、不做平滑，下方一句指令文案。
- **轮询**：每 2000 毫秒查一次 GET /api/admin/channels/{id}/wechat/login/status。
- **等待态**：「用微信扫这个码，在手机上确认后即完成绑定。」
- **已扫态**：成功徽标「已扫码」配「已在手机上确认，正在等待登录完成。」，轮询继续。
- **已登录态**：换成勾形与「渠道已绑定」，800 毫秒后关掉面板并刷新行。
- **过期与未登录态**：提示「二维码已过期，请重新获取。」并停在过期态，等人工点「重新获取二维码」，不会自动再取一张。
- **出错态**：优先显示服务端那句原因，没有原因时用「扫码登录失败。」。
- **认不出的状态值**：继续轮询，不擅自判定成败；单次轮询请求失败也不结束循环。
- **码取不回来**：登录返回的内容解析不成图片时，整块换成失败态并写明「服务端返回的二维码无法解析。」。
- **面板的退出**：底部说明「二维码五分钟内有效；关掉这一页会取消登录。」；往下拖被拒绝，因为划走会跳过欠服务端的取消动作；除了扫成功之外的出口只有关闭键，未出结果就关闭时发一次取消请求并忽略这次取消自己的失败。
- **删除渠道**：确认框「删除这个渠道？」，说明「删除前会先释放它的运行环境，释放被拒就不删。」——服务端先释放运行环境，释放被拒时行留着，原因用服务端原话。

### 5.5 Token 用量监控

- **三枚筛选器**：页面顶部三行，每行左边是名称、右边是一个下拉：时间区间（近 7 天、近 30 天、近 90 天，默认近 7 天）、时间粒度（按小时、按天、按周、按月，服务端默认按天）、统计维度（按 Token、按费用）。
- **窗口的写法**：区间是一个抽样时刻减去天数，两个边界都写成「年-月-日 时:分:秒」的墙上时钟，五个请求共用同一个窗口；两个边界都不发时服务端自己按「现在减七天」算。
- **换筛选的代价**：换区间重读全部五块，换粒度只重读四条趋势，换统计维度一个请求都不发（两列数字本来就在手）。
- **五个数据块**：一次聚合读取 GET /api/admin/token-stats/aggregation 喂七张总览卡和三个环形图；GET /api/admin/token-stats/time-series 与它的 model、agent、session 三条同族路由各喂自己那张折线图。聚合不接粒度参数，时间序列才接。
- **七个数**：总费用、总输入 Token、总输出 Token、总消耗 Token、活跃智能体、活跃会话、使用模型数。这个窗口里没有调用次数、失败次数、环比这类字段，七个数也只能由聚合这一次读取给出。
- **租户不在参数里**：每一条路由都按调用者自己的凭据解析范围，能改变这些数字的动作发生在「我的」的租户切换上。
- **环的截断口径**：按模型与按智能体的环不截断；按会话的环只画消耗最高的 10 个，服务端已按降序返回，界面注明「只画消耗最高的 10 个会话」。
- **趋势的线条数**：总体趋势在 Token 维度下画三条线（输入 Token、输出 Token、总消耗），费用维度下只画一条。
- **图例副行**：模型带供应商，智能体与会话带各自编号。
- **名称缺失**：名称列可能为空（服务端用的是左连接，删掉的模型照样消耗），取名顺序是服务端名称、编号、最后是「未命名」，没有名称的行不会并成一条匿名线。
- **缺分桶文字的行**：直接丢掉，不按位置补零。
- **时间对齐口径**：分桶起点由服务端决定，周这一档落回该周的星期一，月这一档落回月初；窗口内每一个分桶都会拿到一个点，没有消耗的桶报 0，因此折线连续铺满，而不是只在发生过的时刻有值。
- **图例开关**：每张图有自己的隐藏集合，图例行始终列出全部条目并标「已显示」或「已隐藏」；被隐藏的系列不进绘制也不参与纵轴范围；关掉某条图例时同时清掉这张图的下钻。
- **环上的点选**：按可见扇区的累计值算角度命中，值为零的行不占角度、点不到；点中后行下方展开四个数（输入、输出、总消耗、费用），这四个数与当前统计维度无关。
- **折线上的点选**：点某个横轴分桶，图下给出这一刻每条可见线的读数；再点同一个分桶取消选择。
- **状态的重置**：某张图的读取被重新发起时，它的隐藏集合、下钻与选中分桶全部清空，因为这些身份记的是上一次回答里行的位置；「图表 / 数值列表」这一项选择跨重载保留。
- **数值替代视图**：每张趋势图右上角可在「图表」与「数值列表」之间切换；列表把每个分桶摊成一行名称加数值单元，分桶顺序沿用服务端可排序的原文，某条线在这个分桶没有点就不出这一格。
- **Token 数渲染**：达到一百万（含整一百万）写成 xxx.xxM、达到一千（含整一千）写成 xxx.xxK，其余原样，零写作 0。
- **费用渲染**：¥ 加恰好两位小数，零也渲染成 ¥0.00；这一列本身是整数位小数，所以 .00 是常态。
- **占比渲染**：一位小数，总和为零时 0.0%。分隔符永远是句点，不加千分位。
- **轴标签**：从服务端原文切——月切成「年-月」，小时切成「月-日 时:分」，天和周切成「月-日」；形状对不上就整串照抄，不做时区换算。
- **配色**：按行的位置在 8 个色槽里循环，同一行在刷新后颜色不跳。
- **空判定**：挂在聚合读取上，总消耗为零时整页显示空态；聚合失败但图已到手时页面照常铺开，只有卡片区域写着它们自己的失败原因。这一处分不清「窗口真的没消耗」和「读不出来」。
- **重试粒度**：按块独立，一张图重读时其他块的数字留着，在途请求不被作废，每块各有自己的世代号。

### 5.6 定时任务：列表与权限

- **行第一层**：名称，公开任务多一枚「公开」片。
- **行第二层**：目标智能体名称，没有就写「无目标智能体」。
- **行第三层**：调度表达式用等宽块原样摆出。
- **行第四层**：上一次执行结果徽标，取值成功、失败、超时、运行中、停止中、已停止；缺这个键时写「从未运行」，值越出 0 到 5 时写危险色「状态未知」。
- **行第五层**：「上次执行 09-12 03:20」样式的时刻，丢掉年份、保留到分钟；刚手动触发过而列表还没回来的行贴着「已提交执行」。
- **行第六层**：描述、创建者 · 创建日、调度开关与下次执行时间。
- **搜索与筛选**：搜索提示「按名称搜索」；右上角漏斗里是一枚状态选择器，加号在它左边，选择器发的是任务状态位，选「全部」时不带参数；底部一行「%d 个任务」。
- **顺序**：固定按更新时间倒序，界面上没有排序开关。
- **下次执行是本地算的**：这条链路上没有任何字段带这个值，由表达式加上调度节点固定的东八区算出来，再按手机时区渲染；手机在别的时区时，0 0 9 * * ? 照样读作北京 9 点。
- **下次执行的三句文案**：开关显示为关时写「已停用，无下次执行」；算不出来时写「无法算出下次执行时间」；否则「下次执行 %@」。它跟随开关当前显示的状态，而不是刚取回的行值。
- **算不出来**：往后 5 年内找不到触发点就按「算不出来」处理，宁可不说也不给一个错的分钟。
- **这一域的门禁不一样**：启用停用、编辑、删除都要求行上的创建者等于当前登录名，管理员身份在这里不作通行证。
- **唯一的例外**：立即执行不受创建者限制，公开任务任何看得见的人都能起跑。
- **这一域的轮询**：只在有行处于运行中或停止中时以 3 秒间隔转，且只在前台转，离开屏幕就停；静默的那一拍不清横幅、不置失败，它自己的失败直接忽略。

### 5.7 定时任务：表单与表达式

- **字段清单**：名称、目标智能体、执行内容、调度表达式、超时时间、允许并发执行、所有人可见、描述。
- **名称**：占位「这个任务是做什么的」，必填，超过 128 字符报「名称不能超过 128 个字符。」。
- **目标智能体**：来自 GET /api/admin/agent-tasks/agents，只列运行中的智能体，提示「未在运行的智能体不可选。」，必填；行上存的智能体不在这份名单里时按名称补进选择器，连名称都没有就写成 # 加编号；取不到时字段自带一行原因和重试。
- **执行内容**：3 到 8 行的多行输入，占位「每次执行时发给智能体的内容」，必填，不设长度上限。
- **调度表达式**：提示「6 或 7 段：秒 分 时 日 月 周 [年]。日与周必须有一项是 ?。」，占位「0 0 9 * * ?」，下方跟着「预计下次执行 %@」的预览。
- **超时时间**：占位「300」，提示「单位秒，范围 30 到 3600。留空则沿用服务端默认 300。」，越界报「超时时间需要在 30 到 3600 秒之间。」。
- **允许并发执行**：提示「关闭时，上一次还没跑完就不接受新的触发。」。
- **所有人可见**：提示「公开任务别人能看到也能执行，但只有创建者能修改。」。
- **描述**：提示「最多 512 个字符。」，占位「可选，展示在名称下方」，超限报「描述不能超过 512 个字符。」。
- **校验的命中方式**：按顺序取第一条——名称为空、名称过长、智能体未选、内容为空、表达式为空、段数不是 6 或 7（「调度表达式需要 6 或 7 段。」）、日和周同时指定（「日与周只能指定其一，另一段用 ?。」）、超时越界、描述超限。不通过时保存键灰掉，硬按则把第一条原因打印出来。
- **预设片**：五枚，每 5 分钟、每小时、每天 9:00、每周一 9:00、每天 0:00，对应 0 */5 * * * ?、0 0 * * * ?、0 0 9 * * ?、0 0 9 ? * MON、0 0 0 * * ?。它们是填入工具而不是模式：片只在字符串完全相同时亮着，手动改动就灭。
- **表达式的解析口径**：只有 ? 表示该列不指定，* 是把该列每一个值都点名列出；周日到周六编号 1 到 7，SUN 到 SAT 的名称可用，数字 0 折到周日；降序区间回绕该列；步长、逗号、区间的上下界都受列范围检查，打错的表达式是解析失败，而不是被裁剪成一段能跑的范围。
- **编辑的代价**：表单上方一条警告「保存会停用这个任务的调度，改完请重新打开开关。」——任何一次被接受的保存都会把任务挂起。
- **一个字段都没改**：保存照样发得出去，回来写「没有任何改动，但保存仍会停用调度。」。
- **提交体的省法**：没改动的字段不放进体里；目标智能体没变就绝不发送它，发了会重刷行上的智能体名称快照；描述清空时发空串。
- **新建的收尾**：任务由服务端自己挂起，且那条路不会回答「调度库没收敛」这种码；编辑成功如果被拒于同一原因，面板照样关闭、原因进提示带。
- **保存后的两行**：先重读列表，再写「已保存。这个任务的调度已停用，重新打开开关后才会继续执行。」，后面可能再接一条同步警告。

### 5.8 定时任务：触发、删除与执行记录

- **开关被拒**：本地先翻、随后翻回，服务端原话贴进红条；「开始」这一支的拒绝理由客户端看不见，因为服务端只按表达式字段计数。
- **立即执行被接受**：行标成已触发、1.5 秒后重读列表，并直接打开这一行的日志面板。
- **立即执行被拒**：把服务端那句原话显示出来，其中包含「已经有一次执行在途且该任务禁止并发」。
- **删除**：确认框「删除这个任务？」，按钮写「删除「某名称」」，说明「删除后调度一并撤销，执行记录也不会继续增加，且无法恢复。」。
- **删除失败与删除半成功**：真失败时行保留；遇到「表里已删、调度库里还在」时行照删、原因放进提示带——界面不骗人说任务还在。
- **提示与错误的分带**：黄底「提示」带装「已经写成功但调度库没收敛」这类服务端消息与停止回执，红条装真失败。这一域的每条提示都是服务端英文原文，界面不翻译也不改写；创建、更新、删除返回的业务码并不相同，处置却完全一致。
- **日志的两个入口**：行菜单里的「查看执行日志」，以及一次被接受的立即执行。
- **日志的唯一路由**：GET /api/admin/agent-tasks/{id}/logs，因此不存在跨任务的一页记录。
- **面板抬头**：标题「执行日志」，副行「任务：%@」，计数「%d 条执行记录」。
- **日志的搜索**：提示「搜索提示词、回答或错误」，服务端在这三列上做模糊匹配，同样 500 毫秒合并输入。
- **日志的分页与顺序**：一页 10 条，固定按创建时间倒序，没有排序开关。
- **日志的筛选**：都在右上角的漏斗里——状态给全部加六种状态；另有「按开始时间筛选」打开一个暂存编辑器——两枚开关配两个日期选择器，按「确定」一次写入两个边界从而只发一次请求，提示「选择器只到分钟，结束时间会按整分发送。」，只有设过边界时才出现「清除时间区间」这一项。状态与区间当场生效，关键词不重走筛选路径。
- **日志的空态**：无筛选时「这个任务还没有执行记录。」，有筛选时「没有符合筛选条件的执行记录。」。
- **记录行**：状态徽标、开始时刻、耗时（一位小数的秒数，按整数算出来，换台用逗号做小数点的手机也是同一个字符串）、两行提示词、一行回答（没有就是一个破折号）、两行红色失败文本；运行中的行带「停止」片。
- **详情不花钱**：没有单条记录的路由，详情面板完全用已在手的数据拼：开始时间、结束时间、耗时、会话，失败时一条「失败原因」横幅，「执行内容」与「Agent 回答」是可长选的正文块（在手机上把提示词复制出来正是目的），标题栏用任务名。
- **详情的新鲜度**：面板在重载后重新指向轮询到的那份拷贝，于是耗时和回答自己会更新，面板也能一直开着不等第二条请求。
- **能停谁**：状态是运行中且行创建者是自己。读取按任务的可见范围放开、写入按创建者收紧，所以存在看得见却停不下来的行；已经是「停止中」的行不给第二次停止。
- **停止的确认**：「停止这次执行？」，按钮「停止」，说明「这会打断智能体当前正在进行的执行，无法撤销。」。
- **停止之后**：先写「停止请求已送达，这次执行的最终状态以下一次刷新为准。」，1 秒后静默重读；若这次执行恰好在按下瞬间结束，服务端的英文原话（例如 Task is not running or already completed）进红条。
- **日志面板的轮询**：只要开着就从不关掉，有行在途时 3 秒、否则 5 秒，同样只在前台跑；失败的每一拍直接忽略。
- **关掉面板**：停轮询并重读任务列表——记录在面板开着的时候跑完，正是任务卡上会过期的那枚徽标。
- **不上屏的量**：每条记录上的 Token 消耗量在这张页面上不显示。

### 5.9 我的

- **身份卡的内容**：头像是显示名首字母的圆，旁边是显示名，再下面一枚「管理员」或「成员」徽标，最后一行「当前租户：某个名字（id 12）」。
- **显示名的取法**：服务端给了非空昵称就用昵称，否则用登录名。
- **租户行的兜底**：名字缺失时写「未知租户」；编号缺失时那个位置放一个破折号——从本机缓存恢复的身份常常只有编号。
- **身份卡只是展示**：卡上没有箭头，也不响应点击；换租户用的是下面「账号」分组里那一行。
- **租户行的形状**：左边「切换租户」，右边是一个下拉，当前租户名就是下拉闭合时显示的那个值。这一行不分账号有几个租户都在屏上——只有一个租户时也读得出自己处在哪一个。
- **下拉什么时候开得动**：账号名下至少有两个租户才打得开；只有一个时它是灰的。名单里只列有编号的行，编号是唯一发出去的东西，没有编号的行根本不进选项。
- **停用租户的告知**：这类行的选项文字写成「名字 · 已停用」，因为服务端照样给它发令牌，这一项照样可选，只有文字能说清它的状态。
- **选中项的标记**：下拉自己给当前生效的那一项打勾，这就是「当前」的全部表达。
- **点中即执行**：选中一项立刻发起切换，执行期间这一行不可再开。
- **名单的口径**：可读租户名单只包含状态为启用的那些，按加入时间倒序。
- **切换成功的后果**：账号副本重读、根界面在新租户上重建每一个 tab；卡上的新租户名字能显示出来，是因为这一步顺手把它写了进去。
- **切换被拒的后果**：原因留在屏上——令牌没换，也就没有任何东西需要回滚。
- **切换的机制**：是一次新令牌，不是换一个请求头；此后每一条请求都自带新范围。
- **三条横幅各自独立**：身份信息、租户名单、切换被拒各有一句自己的红色横幅，「这份名单没读到」不等于「这个账号只有一个租户」，读不到名单时写「租户列表读取失败」。
- **本账号的永久 Key 不在这屏上**：没有卡片、没有掩码值、也没有重新生成的入口，这把 Key 的任何一个形态都不经这一屏输出。
- **这把 Key 在后端的两处**：登录时服务端按用户补造一把；管理员从「管理」分组的 API Key 那一行进列表，看的是本租户的条目，这一行的出现与否只看账号有没有管理员标记。
- **主题与语言各是一行**：都在「偏好设置」分组里，左边是名称、右边是一个下拉，选定即生效。主题三档：跟随系统、浅色、深色；语言三档：跟随系统、English、简体中文，后两档永远按自己的语言书写。
- **服务器地址**：这一项是应用内的下一页，副行是管理端与路由两条基础地址，来自一次成功读取，读不到就没有这行。
- **启动时解锁**：这一行只在设备具备生物识别能力时出现，副标题「下次启动 app 时，先要求生物识别或设备密码，才打开已保存的登录。」，开关写在行右侧。
- **退出登录**：底部破坏性一行「退出登录」，确认框「退出当前设备的登录状态？」，按钮为「退出登录」与「取消」。
- **退出做了什么**：本地确实有登录状态时向服务端发出这一次登出请求；随后无论那个请求回不回、回什么，本机凭据与缓存身份都被抹掉，根界面切回登录页。

### 5.10 本域的失败口径

- **与全局一致的一条**：401 是一种会话事件而不是文案——它结束登录、由根界面换掉整块屏，界面上不会出现「已退出」的提示。
- **与全局一致的第二条**：拿到答复之前失败的几种情况各有一句固定中文——「当前网络不可用，请检查网络连接。」「无法连接到服务器，请确认服务已启动。」「请求未能发出，请稍后重试。」「请求已中断，请重新加载。」「请求超时，请稍后重试。」。
- **与全局一致的第三条**：服务端给了业务码和原话时原话优先、逐字显示，没有原话时才用「服务器拒绝了本次请求。」；包装解不开时有自己的固定句子「服务器未返回数据。」与「无法解析服务器返回内容。」。
- **与全局一致的第四条**：列表已有行时失败表现为行上方一条红横幅并保留内容，一行都没有时才整屏切失败态。
- **与全局一致的第五条**：详情读取回来的对象缺了主键时，一律按「服务器未返回数据」处理，而不是当作一条空行去编辑。
- **本域特有：写开关的失败形状**：API Key 与渠道的启用停用被拒时，本地状态先翻再翻回，被拒文本永远来自服务端而不是本地判断，界面里也没有「哪几类不能停」的白名单。
- **本域特有：一次性密钥面板**：里面没有失败可显示，值不重试也不补发，取不到就是没有值。
- **本域特有：两处独立降级**：渠道沙箱灯绝不把查询失败渲染成「已停止」；智能体选择器失败后只留「重试」，因为它不给默认值。
- **本域特有：扫码面板**：失败落在相位上而不是横幅上，过期态停在屏上等人工重新取码，不会自动补一张。
- **本域特有：Token 监控**：失败按块隔离，聚合失败只带走卡片与三个环，四条趋势各归各的读；这一页还承认自己分不清空窗口与读不出。
- **本域特有：定时任务**：提示与错误分两条带，黄带装半成功与回执、红条装真失败；每条提示都是服务端英文原文，且不同业务码走同一套处置。
- **本域特有：租户切换**：被拒时这一行留在屏上并给出原因，选择落回仍在生效的那个租户；这一屏不发布任何密钥值。
