# Harnax 能力域（Capability-Domain）问题登记

> 按域登记当前代码的问题，**每个问题只归一个域**；每条附推荐做法供审查，最终「处置决定」填在 §9。
>
> 跨域类问题按最相关归属拆入各域：租户拦截器与环境变量归 agent 域（`env_variable` 与租户隔离的归属方）；服务全部域的应用外壳类（i18n 全量表、类型定义副本、脚手架残留、测试基线）也归 agent 域，并在该节标明。
>
> 口径：只读静态审计；迁移链按 V1→V46 累加后的**最新**形状判定（V40~V46 是各修复轮新增：V40 工具表去租户、V41 `agent_cli_binding` 唯一键、V42 清理软删 CLI 尸行、V43 `agent` 名称同租户唯一键、V44 模型与服务商的租户归属回填、V45 `env_variable` 键的同租户唯一键、V46 把该唯一键的粒度改到创建人），不以中间版本 DDL 为准；每条均回读过原文件。标「需运行期确认」的项见 §8。
>
> 未覆盖：scheduler/quartz、channel 内部实现、mp/小程序、auth 模块、`harnax-cli` 二进制源码。

级别：**【高】**会致错或稳定产生脏数据；**【中】**边界不守、维护负担；**【低】**仅整洁性。

总体形态：模型层（表、唯一键、外键）比服务层薄一档，"服务层忘了校验"是绝大多数脏数据的入口；删除路径普遍只做「清绑定 + 软删」两件事，而**被引用校验、对象回收、缓存失效**三件事大多缺位。
